GameShow V4: game logic transfer to Unreal Engine

Everything the Unity graphic app does between a studio frame arriving and a done leaving. Written so the same behaviour can be rebuilt in Unreal without reading the C#.

Source: unity/GameShow_v4, scene SampleScene.unity Numbers: scene values win over code defaults Date: 2026-09-02

0Overview and scope

The graphic app is a renderer. The studio server owns the game flow. The studio sends one stage at a time over a WebSocket. The app renders that stage. Four stages are gated: the studio waits for the app to report them done before the round moves on.

The app has five moving parts. Each one becomes one Unreal class.

ShowCamera + CameraSwingScripts/ShowCamera.cs, CameraSwing.csMoves the camera between shots, drifts the wide shot.AShowCamera (ACameraActor subclass)

Not in scope: the studio server itself, the Blender asset pipeline, the debug panel UI. The debug panel's round sequencer is described in 2.3 because it documents how the studio orders stages.

Reading guide

Each section ends with an "Unreal mapping" note. Values marked scene are the serialized values in SampleScene.unity or in the slot config assets. They differ from the C# field defaults in a few places, and the scene value is the one on screen.

1WebSocket connection

1.1 Protocol

Endpoint
ws://localhost:9435/joker-show/ws (scene). Make it a config value.
Direction
Studio sends state frames. App sends done responses. Nothing else travels.
Encoding
UTF-8 JSON text frames. One JSON object per WebSocket message.

Inbound frame (studio to app)

{
  "uri": "MAIN_SPINNING",          // required. GAME_PHASE, see section 2.1
  "correlationId": "4f1c-…",        // required. Echoed back in the done
  "payload": {                       // optional. Absent on most stages
    "result": "BONUS DICE",          // optional. Outcome the round must land on
    "bonusSpin": 1                   // optional. Spin number inside a bonus round, from 1
  }
}

A frame with no uri or no correlationId is a parse error. The app logs it and drops it. payload.bonusSpin is parsed and logged but nothing reads it.

Outbound done (app to studio)

{ "uri": "MAIN_SPINNING", "correlationId": "4f1c-…" }

Both fields are copied from the frame that opened the stage. A done is only sent for gated stages. The studio ignores a done for a stage it has already left, so a duplicate is harmless.

1.2 Socket lifecycle

  1. Dial loop. On start, connect. When the socket closes or fails, wait 3 s and connect again. Loop until the app quits.
  2. Resend on reconnect. Right after a connection opens, send the last done again if one exists. A done can be lost when the socket drops mid-send.
  3. Read. Read frames until the socket closes. Reassemble fragmented messages before parsing.
  4. Marshal to the game thread. Every parsed frame is delivered to subscribers on the main thread. Subscribers move scene objects.
  5. Dedupe. Keep the last delivered frame. If the next frame has the same uri and the same correlationId, drop it and log "repeat". Compare both fields, not just the uri: the studio can legitimately send the same uri twice in a row for two different rounds.
  6. Send lock. One send at a time. Two dones must never interleave on the wire.
  7. Send while closed. If a done is requested while the socket is closed, store it as the last done and log a warning. The reconnect resend delivers it.
  8. Offline flag. A debug switch that never dials and keeps every done inside the app. The debug driver injects frames through the same dedupe and dispatch path. Keep this path in Unreal so the FSM can be tested without a studio.
  9. Shutdown. Abort the socket first so a pending read gives up, then dispose.

Events the connection exposes

EventThreadPayloadWho listens
StageReceivedgame threadthe parsed frameShowDirector, debug panel
DoneSentgame threadthe done response, online or offlinedebug round sequencer

1.3 Unreal mapping

  • Module WebSockets. FWebSocketsModule::Get().CreateWebSocket(Url, TEXT("")). Bind OnConnected, OnConnectionError, OnClosed, OnMessage. OnMessage already delivers whole text messages.
  • IWebSocket callbacks arrive on the game thread in the default implementation. Still guard with AsyncTask(ENamedThreads::GameThread, …) if the module is ever swapped.
  • Parse with FJsonObjectConverter::JsonObjectStringToUStruct into a USTRUCT that mirrors the frame. Mark Result and BonusSpin optional by giving them defaults and checking HasField on the payload object.
  • Reconnect with FTimerManager::SetTimer at 3 s. Keep the timer on a subsystem so it survives level travel.
  • Put the connection in a UGameInstanceSubsystem. Expose two multicast delegates for the events above.

2Stage FSM

2.1 Stage grammar

A uri is GAME_PHASE. Split at the last underscore. The left part is the game. The right part is the phase. Game names carry underscores of their own.

Games (round)

Uri prefixEnumRig
MAINMainhero wheel
BONUS_LUCKBonusLuckslot machine, luck config
BONUS_DICEBonusDicedice cabinet
BONUS_DELUXEBonusDeluxeslot machine, deluxe config
BONUS_SHOWBonusShownone. The wheel stands in.

Phases

Uri suffixEnumGated
STARTStartno, studio timer
WAITINGWaitingno, studio timer
SPINNINGSpinningyes
RESULTResultyes
SWITCHSwitchyes
CANCELINGCancelingyes

Any name outside these lists parses as Unknown. A stage with an Unknown game or an Unknown phase is rejected: the app logs an error, renders nothing, sends no done, and keeps the stage already on screen. Parsing is exact and case sensitive.

Two helper predicates are used everywhere. IsGated is true for Spinning, Result, Switch and Canceling. IsSlotGame is true for BonusLuck and BonusDeluxe.

Why the slot config is applied on every stage

The two slot rounds share one cabinet. Only the config tells them apart. The studio can open a round at any phase, and a frame can interrupt a render. So the config is set on START, WAITING, SPINNING and SWITCH alike. Applying a config the machine already has is a no-op.

2.3 A full round

The debug driver plays rounds the way the studio does. This is the canonical order. START and WAITING are held by a timer (2 s each in the debug driver). Every gated stage waits for the done.

2.4 Interrupts and cancel

  • A frame that arrives mid-render replaces the running render. Stop the coroutine or timer chain, then start the new one. Nothing from the old render is finished, and no done is sent for the old stage.
  • CANCELING normally arrives this way. Every rig has a "stop where you are" call for it. See the table in 2.2.
  • A RESULT in a slot round with no result to show logs a warning and holds the close-up on whatever the reels rest on.
  • Missing rigs degrade rather than fail. No dice board: the dice round spins the wheel. No slot machine: both slot rounds spin the wheel. No camera: the camera holds still. No wheel: spins report done at once. Keep this so a partial Unreal scene still runs a round.

Unreal mapping

  • Model the render routine as a small state object on AShowDirector with a Tick. Coroutines map to either latent timers (FTimerHandle) or an explicit per-phase sub-state that polls IsSpinning / IsRolling / State == Idle every tick. Polling is the closer match to the C# and interrupts cleanly: on a new frame, clear all timers and reset the sub-state.
  • Store CurrentStage, StageStartedAt and the frame's correlationId. The done needs the correlation id of the frame that opened the stage, not the latest frame.

3Camera transitions

3.1 Shot model

A shot is not an authored pose. A shot is aimed at a rig and built outwards from the aim point. If the rig moves, the shot follows.

FieldMeaning
aimOffset (x, y, z m)Where the camera looks, offset from the rig's aim transform, in the rig's level frame: x across, y up, z out of the rig's face.
distance (m)From the aim point to the camera.
yawDegreesAround the aim point. 0 stands straight in front of the rig.
heightOffset (m)Camera above the aim point. 0 keeps the camera level with the aim.
fieldOfView (vertical, degrees)0 keeps the scene-authored FOV (40).
moveDuration (s)How long the move into the shot takes.

Each rig supplies two transforms. The aim transform gives the position. The basis transform gives the facing. The wheel aims at its spinning disc but takes its facing from the still rig root, because a spinning disc has no facing.

Pose formula

level    = yaw-only rotation of basis.forward projected onto the ground plane
           (identity if basis is null or points straight up/down)
aim      = aimTransform.position + level * shot.aimOffset
back     = level * (RotateAboutUp(shot.yawDegrees) * Forward)   // Forward = rig's own facing
position = aim + back * shot.distance + Up * shot.heightOffset
rotation = LookAt(from position, to aim, up = world Up)
fov      = shot.fieldOfView > 0 ? shot.fieldOfView : authoredFov

Note the sign: the camera sits on the rig's forward side and looks back at the rig. "Forward" of every rig is the side the audience sees.

Move

t  = SmoothStep(0, 1, clamp(elapsed / duration))     // 3t² − 2t³
pos = Lerp(fromPos, toPos, t)
rot = Slerp(fromRot, toRot, t)
fov = Lerp(fromFov, toFov, t)
// on finish: snap to exact target, mark not moving, re-enable the jib swing only for the wide return
  • A move into the shot already on screen, with no move running, is a no-op. Otherwise a new move replaces a running move and starts from the current pose.
  • Before every move, disable the jib swing without letting it snap the camera back: read the current pose, disable the swing, write the pose back.
  • IsMoving is true while a move runs. The director gates on this (3.4).

3.3 Jib swing (wide shot only)

The swing drifts the camera around a pivot the way a studio jib drifts on air. It is enabled only when the wide return finishes, and disabled before any other move.

Pivot
No pivot transform is set. The pivot is basePosition + baseRotation * Forward * 6 m.
Base pose
Captured when enabled. Restored when disabled. The wide return lands exactly on the authored pose first, so the base pose is always the authored pose.
Amplitudes
yaw ±2.2° period 12 s · pitch ±0.9° period 8.3 s · roll ±0.4° period 15 s. Intensity 1.
Ease-in
SmoothStep over the first 2 s from enable, scaling all three amplitudes.
Phase offsets
yaw 0, pitch +0.31, roll +0.67 cycles.
Aim
aimAtPivot on: the camera looks at the pivot, so the swing reads as parallax.
Wave(period, phase) = ( sin(2π(t/period + phase)) + 0.28 · sin(2π(t/(0.41·period) + 1.7·phase)) ) / 1.28

yaw   = 2.2 · scale · Wave(12,  0)
pitch = 0.9 · scale · Wave(8.3, 0.31)
roll  = 0.4 · scale · Wave(15,  0.67)
right = baseRotation * Right
arc   = AngleAxis(yaw, Up) * AngleAxis(pitch, right)
fromPivot = arc * (basePosition − pivot)
position  = pivot + fromPivot
rotation  = LookAt(−fromPivot, Up) * AngleAxis(roll, Forward)     // applied in LateUpdate / after all other movement

3.4 Camera gating

Three places wait for the camera. Each uses the same helper: wait while IsMoving, give up after 8 s (cameraMoveTimeout), then wait out whatever remains of a minimum hold.

WhereMinimum holdPurpose
SWITCH1.5 sThe switch is not reported done until the camera has landed on the new game.
BonusDice SPINNING, before release0.9 sThe drop happens on screen.
Slot SPINNING, before reels start0.7 sThe reel start happens on screen.

Keep the timeout above the longest move (1.6 s). It is a safety net, not a design value.

Unreal mapping

  • Subclass ACameraActor or drive a UCameraComponent on a pawn. Do not use SetViewTargetWithBlend: it cannot blend FOV to a computed pose and cannot be interrupted mid-blend with the same semantics. Tick the interpolation yourself.
  • FMath::SmoothStep(0.f, 1.f, t), FMath::Lerp, FQuat::Slerp, FRotationMatrix::MakeFromX(aim − position).Rotator() for LookAt with world up.
  • Run the swing in a component that ticks in TG_PostUpdateWork so it runs after the move. Only one of the two writes the transform in any frame.
  • Coordinates: see Appendix A for the Unity to Unreal axis swap. Yaw sign is preserved. Metres become centimetres.

4.2 Resolving the studio result to a segment

Run these steps in order on payload.result. Stop at the first that produces a segment.

  1. Empty result. Pick a random segment. Log a warning.
  2. Label match. Compare the result to every label, case insensitive. Several segments share a label, so pick one of the matches at random. This is what keeps the wheel from landing on the same spot every time.
  3. Numeric index. If the result parses as an integer 0..9, map it through the table below to a label and repeat step 2 with that label.
  4. Fallback. Random segment, warning logged.

4.3 Spin

Duration
7.0 s from release to stop.
Extra turns
4 whole turns on top of the travel to the target.
Direction
Clockwise as seen from the front. direction = +1.
Easing
1 − (1 − t)⁴, sampled into a 12-key smoothed curve. Fast off the mark, long tail.
Settle
Amplitude 1.6°, duration 0.9 s, 1.75 oscillations, decay (1 − t)².
Idle spin
8°/s in the spin direction while no spin runs and the idle flag is on. The director turns it on for START, WAITING and SWITCH, and off for SPINNING and CANCELING.
SpinTo(target):
  start     = angle                              // continuous angle, keeps counting up across turns
  landing   = AngleForSegment(target)
  remainder = ((landing − start) · direction) mod 360, in [0, 360)
  sweep     = (remainder + turns · 360) · direction
  end       = start + sweep
  for elapsed in 0..duration:  angle = start + sweep · easing(elapsed / duration)
  angle = end
  Settle: for elapsed in 0..0.9:
      t = elapsed / 0.9
      angle = end − sin(t · 1.75 · 2π) · 1.6 · (1 − t)² · direction
  angle = end;  IsSpinning = false;  raise SpinCompleted(target)

IsSpinning is true from the call until the settle ends, 7.9 s in total. The director polls it and then sends the done. StopSpin aborts the routine and leaves the disc where it is. A new SpinTo while spinning replaces the running spin.

The disc's rotation is written as AngleAxis(angle, localUp) every frame. On start-up, read the authored angle back from the disc so nothing snaps on load.

4.4 BonusShow on the wheel

BONUS_SHOW has no rig. Its SPINNING spins the wheel with the studio's result. The debug driver keeps that result off the bonus labels so a bonus round cannot open another one. The real studio is expected to do the same.

Unreal mapping

  • Rotate the disc component with SetRelativeRotation(FQuat(LocalUpAxis, FMath::DegreesToRadians(angle))). Keep the angle as a float that grows without wrapping.
  • Bake the easing into a UCurveFloat or evaluate 1 − (1−t)^4 directly. Both are equivalent within a frame.
  • FMath::RandRange for the random picks. Randomness here only chooses among segments that share the requested label.

5.4 Landing the studio result

payload.result for a slot round is a combination id, not a wheel label. The machine turns the id into reel positions:

TryBuildResultFor(id):
  for a in 0..left.count−1:
    for b in 0..center.count−1:
      for c in 0..right.count−1:
        match = paytable.Evaluate([left[a], center[b], right[c]])
        if match.IsWin and match.CombinationId == id (case insensitive):
          return (a, b, c)          // first hit wins
  return none

5.6 Reel motion

A reel owns a float position in strip cells. Whole numbers are exact rest points. Position P puts strip item Wrap(round(P) + winLineCell) on the win line. The controller ticks all three reels in order every frame, so nothing drifts.

Reel phaseBehaviour
IdleStill.
WaitingToStartCount down the stagger delay, then SpinningUp.
SpinningUpspeed = cruise × spinUpCurve(timer / spinUpSeconds). Advance. At the end snap speed to cruise, go Cruising, and begin a stop if one was already requested.
CruisingAdvance at cruise speed. Position is kept wrapped into [0, count).
Stoppingposition = LerpUnclamped(stopFrom, stopTo, stopCurve(timer / reelStopSeconds)). At the end land exactly on stopTo, then Bouncing (or Idle if bounce is 0).
Bouncingposition = stopTo + bounceCurve(timer / bounceSeconds) × bounceCells. Then Idle at exactly stopTo.
BeginStop (called when the reel is Cruising and a stop was requested):
  slope    = max(0.2, (stopCurve(0.02) − stopCurve(0)) / 0.02)      // ≈ 2 with the shipped curve
  natural  = cruise · reelStopSeconds / slope                       // 6.65 cells luck, 9.775 deluxe
  minimum  = position + natural + fullTurnsBeforeStop · count       // + 7 or + 14
  wanted   = Wrap(targetItem − winLineCell)                         // rest position that shows the item
  stopTo   = ceil(minimum) raised to the next integer ≡ wanted (mod count)
  stopFrom = position

Why this shape: the stop curve's opening slope is matched to the cruise speed, so the stop begins with no jolt. The target is an integer, so nothing accumulates over a show. The bounce is under half a cell, so the item on the win line never changes after landing.

The view scrolls a ribbon of cells by position × cellHeight and swaps the item drawn in each cell as it wraps. Highlight and punch are per-reel multipliers the view applies to the win-line cell.

5.7 Show integration

  1. SPINNING arrives. Apply the round's config. Frame slot-spin.
  2. Wait for the camera, minimum 0.7 s.
  3. Resolve payload.result with TryBuildResultFor. Hit: SpinWithResult. Miss or empty: Spin() and a warning.
  4. Poll until State is Idle or Disabled. Send the done.
  5. RESULT: HighlightLastResult, frame slot-result, hold 2 s, done.

  • USlotMachineConfig : UPrimaryDataAsset with a TArray<FSlotReelStrip>, the timing floats, and UCurveFloat* for the three curves. USlotPaytable : UDataAsset with TArray<FSlotWinCombination>.

6BonusDice game

Both bays of the acrylic cabinet are played at once. Every die is released together at the top. Three pip dice fall down the wide bay on the left and their top faces are summed. Two colour dice fall down the narrow bay on the right and each shows red, green or blue. The roll is the sum plus the pair of colours. The faces are whatever the physics leaves on top.

Result is not forced

The studio sends payload.result for BONUS_DICE_SPINNING. The dice ignore it. The board logs a warning when the physics total differs from the request. Nothing in the app forces the studio's number. This is the largest open item for the Unreal build; see section 9.

6.3 Settling and nudges

After every physics step, run StepRoll(step):

StepRoll(step):
  rollElapsed += step
  settled = true
  for each die i:
    height  = die height above the plinth, in board metres
    onFloor = height ≤ RestHeight
    if not onFloor or not IsStill(die): settled = false
    if onFloor: continue
    if height < lowest[i] − 0.02:  lowest[i] = height; stalled[i] = 0        // still making progress
    else:                           stalled[i] += step
    if stalled[i] ≥ 0.5 and nudges < 8:
        Nudge(die, nudges); lowest[i] = height; stalled[i] = 0; nudges += 1
  allStillFor = settled ? allStillFor + step : 0
  return allStillFor ≥ 0.45 and rollElapsed ≥ 0.5

IsStill(die)  = |v| < 0.05 m/s and |ω| < 25°/s
RestHeight    = floor height + 0.065 m (board metres). Covers three 30 mm dice stacked (61 mm)
                but stays under a die balanced on the lowest peg crown (90 mm).

Nudge(die, n):
  strength = 1 + 0.5 · n
  impulse  = (±right · 0.5 + up · 0.35) · strength · mass        // side picked at random; lift first
  torque   = randomUnitAxis · 0.0006 · strength · mass
  wake the body
  • Stalling, not stillness, is the nudge test. A die on a peg crown trembles above the still thresholds and would never be nudged otherwise.
  • A roll ends only when every die is on the floor and still for 0.45 s, and at least 0.5 s has passed. Only the 14 s timeout can end a roll with a die still in the field. That die's face is reported with a warning that it is not a fair roll.
  • Nudges are capped at 8 per roll. Each is harder than the one before.
  • StopRoll aborts, restores the timestep, and leaves the dice where they lie. Park stops and hides them.

  1. SPINNING arrives. Frame dice-spin.
  2. Wait for the camera, minimum 0.9 s.

Unreal mapping

  • Chaos rigid bodies on UStaticMeshComponents with SetSimulatePhysics(true). Build the cavity from UBoxComponent and UCapsuleComponent children with the metric numbers above, converted to centimetres. Capsules in Chaos are along local Z; rotate them to run front-to-back.
  • Contact offset: Chaos has no per-shape contact offset. Set the collision margin low in the project physics settings and enable CCD on the dice. Validate with a soak: the Unity project settled on 30 mm dice after 500 rolls per size, and Chaos will move that optimum.
  • Timestep: enable physics substepping with a 10 ms max substep, or set FPhysicsSettings fixed delta. Do it globally; the Unity build toggles it per roll only because the dice are the only physics in the scene.
  • Release pose: SetWorldLocationAndRotation(loc, rot, false, nullptr, ETeleportType::TeleportPhysics), then SetPhysicsLinearVelocity, SetPhysicsAngularVelocityInDegrees, WakeRigidBody.
  • Nudge: AddImpulse(impulse, NAME_None, /*bVelChange*/ false) and AddAngularImpulseInRadians. Scale by mass as the C# does, or pass bVelChange = true and drop the mass factor.
  • Run StepRoll from an FPhysScene post-physics callback or a TG_PostPhysics tick with the substep delta.
  • Sleep thresholds: Chaos sleeps bodies more eagerly than PhysX. Wake every die on release and after each nudge.

9Known gaps and decisions for the Unreal build

  1. Dice result is not honoured. Physics decides the faces. Options: (a) keep physics and accept the mismatch, as Unity does; (b) run the drop as a physics simulation but read the faces from payload.result and rotate each die to match as it comes to rest; (c) pre-simulate offline and replay a recorded drop whose total matches. Decide before building the dice actor; (b) and (c) change its interface.
  2. Colour dice are not part of the studio result. The payload carries one string. If colours must be forced too, the payload format has to grow.
  3. BonusShow has no visual. The wheel stands in. The studio must send a payout label, not a bonus label, for BONUS_SHOW_SPINNING.
  4. bonusSpin is unused. It is parsed and logged only.
  5. Fixed slot seed. Both configs seed the RNG with 20250812. Unforced spins repeat. See 5.1.
  6. Scene overrides differ from code defaults. Slot wide and spin shots, and colour release lanes. This document uses the scene values.
  7. Scene layout is metric and Y-up. Convert positions per Appendix A. The camera's authored wide pose is a scene fact, not a formula, and must be re-authored in Unreal against the Unreal set.
  8. Deflector model vs colliders. The Blender model's upper wall chevrons sit 28 mm across and 46 mm in height from where the colliders are built. The colliders are correct; the model is the side that is wrong. Build the Unreal colliders from the numbers here, not from the mesh.
