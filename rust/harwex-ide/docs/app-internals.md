# App internals

Read this file when you add a panel, a custom tab, a Git UI action or a language to the app. The contracts that every app change needs are in `app/CLAUDE.md`. This file lists the extension points behind them.

## State and jobs

- `AppState` (`app/src/state.rs`) holds what the window shares: `ctx`, `jobs`, `notifications`, `platform`, `editor_theme`, `memory`, `clicks`, `input_log`, `timings`, `test`, `deterministic`, `watch_files`, `terminal_command`, `default_layout`, `saved` (per-root layout and files) and `confirm_close_ws`.
- Everything of one project lives in a `Workspace` (`app/src/workspace.rs`): `project`, `tabs`, `tree`, `breadcrumbs`, `git: GitInfo`, `git_ui`, `langs`, `nav`, `diagnostics`, `find_window`, `find`, `search`, `index`, `layout`, `terminals`, `watcher`, `commands`, `confirm_close`, `tree_ops`. `state.ws` is the workspace in context; `others` holds the rest.
- `state.ws` is the active workspace while a frame draws. While a job callback runs, it is the workspace that started the job: `drain_inbox` calls `with_ws(id, f)`, which swaps that workspace into `state.ws` and back. No locks; the UI thread owns all of them.
- Workspace API: `open_workspace(root) -> WorkspaceId` (activates an open workspace with the same root; a blank active workspace takes the project; a non-canonical spelling of an open root closes the new workspace again once the worker canonicalized it), `activate(id)`, `close_workspace(id)` (asks with "Save and Close / Close Without Saving / Cancel" when files are dirty), `close_workspace_now(id)`, `workspaces() -> Vec<WorkspaceInfo>` (id, name, root, is_active; open order), `workspace(id)`, `all_ws()`, `with_ws(id, f)`, `Workspace::owned_pids()` (shells, language servers, linters; never waits).
- Closing the last workspace leaves a blank one: the welcome screen. An empty window is always one workspace without a project.
- `tick_workspaces` runs each frame for every workspace: custom-tab commands, debounced LSP sync, diagnostics, gutter marks, a pending "Save and Close". Background workspaces are never drawn; their modals and popups wait until they are active again. A background terminal asks for at most one repaint (`ide-term` repaints only on the clean-to-dirty edge, and only drawing clears it).
- egui ids: every absolute id a workspace draws goes through `workspace::wid(source)`; the editor area and the breadcrumbs sit under `ui.push_id(workspace::salt())`. The salt follows the canonical root, so persisted egui memory (panel sizes, scroll) comes back per project. Window-level ids (title bar, toasts, the close-project modal) stay plain `Id::new`.
- Storage (`app/src/persist.rs`): `open_projects` (roots in open order), `active_project`, `project_state` (per root: layout, active file, open editor files; closed projects stay, max 50), `recent_projects` (the selector's Recent list, newest first), plus `last_folder` and `tool_windows` for the active project, which older versions read. Startup reopens the saved roots, then opens `AppOptions::project` (a terminal start) and activates it.
- Terminal tabs (`app/src/terminal.rs`, `app/src/terminal_store.rs`): one SQLite file (`AppOptions::terminal_db`; `main.rs` takes `terminal_store::default_db_path`, the temp dir in background mode) with the tables `version`, `terminal_projects` (root, active tab) and `terminal_tabs` (root, position, name, last title, cwd). The `terminal-store` thread owns the connection; the UI thread only sends requests (in order) and a `spawn_quiet` job waits for the reply. `install_project` calls `terminal::restore`; until its answer `Terminals::loading` keeps the window from starting a shell. A restored tab has no `Terminal` until it is first shown (`Terminals::is_started`). A tab change saves after 300 ms (`save_pending` counts in `has_pending_debounce`); eframe's periodic `save`, `close_workspace_now` (`save_closed`) and `on_exit` (`flush_on_exit`, blocks up to 2 s before the shells die) save too, because only a save reads the shells' current directories. A11y: the rename box is `Tab name`; the tab menu has `Rename Tab…` and `Close Tab`.
- Inline rename boxes: egui drops the focus on Escape at the start of the frame unless the focused widget's focus filter keeps Escape, and a `TextEdit` resets that filter every frame it draws. Set `Memory::set_focus_lock_filter(id, EventFilter { escape: true, .. })` after `show`, or Escape reads as a click away. Consume Enter at the start of the frame but end the rename after the box drew: one frame can carry the last letters and Enter.
- Project selector (`app/src/projects_popup.rs`): `on_widget` (title bar press toggles), `take_keys` (start of `shortcuts`), `show` (after the panels; also moves the active root to the front of `projects.recent`). `ProjectsUi::note_opened`, `remove_recent`, `recent_shown(open_roots)`. A11y: `Open...`, `Open project <name>`, `Close project <name>`, `Recent project <name>`, `Remove recent project <name>`; the crosses are hover-only nodes inside the row, which decides by pointer x.
- Favourite branches stay in the active workspace's `git_ui.window.favorites`; `activate` moves the map along.
- `AppState` methods: `refresh_git()`, `open_location(path, Option<Position>, record_history)`, `save_tab(id, then_close)`, `save_all()`, `close_tab(id, force)`.
- `GitInfo` holds `repo: Option<Repo>`, the branch, `detached`, `status` (absolute path to `ChangeKind`), `changes: Vec<FileChange>`, `dirty_dirs` and `refresh` (the full and path-limited status runs, `git/refresh.rs`).
- `state.jobs` (`app/src/jobs.rs`): `spawn(label, work, done)`, `spawn_quiet(work, done)`, `post(f)`, `busy(label)`. The label shows next to the status bar spinner. Every handle carries a workspace tag: `state.jobs` the workspace in context, a clone the tag it was made with, `jobs.window()` none (window-level work such as the memory sampler and the folder picker). A callback of a closed workspace is dropped.
- `state.notifications`: `info`, `warn` and `error(title, body)` show a toast and log it. `log_only(level, title, body)` only logs it. For a git CLI result, use `CommandOutcome.stderr` as the body.
- `AppState::is_idle()` is true when no job, queued language command, git refresh, index build or debounce is pending in any workspace. The test driver's `settle()` waits for it. A new debounce or worker must report itself there, or the tests race it.

## Tabs

- An editor tab is an `EditorTab`: `doc`, `view` (`EditorState`), `marks`, `annotations: Vec<String>` (an empty list hides the blame column), `invalidate_marks()`, `path` (canonical), `read_only` (set for library paths), `lang: Option<LangId>` and the crate-private `lsp_version` (the doc version the server has seen). Get one with `state.ws.tabs.editor_mut(id)`.
- A custom tab implements `tabs::CustomTab`: `key`, `title`, `ui(&mut self, ui, &mut TabEnv)`, and optionally `tooltip`, `is_dirty`, `file_path`, `shared_editor`, `has_pending_work`, `file_icon`, `on_close`, `as_any_mut`. `state.ws.tabs.open_custom(Box::new(tab))` opens it. A key that is already open activates the existing tab.
- A job delivers results to a custom tab through `state.ws.tabs.custom_mut::<T>(key)`.
- Inside `ui`, `TabEnv` gives `jobs`, `notifications`, `project`, `git`, `tab_id`, `editor_theme` and `commands`. Push `AppCommand::OpenLocation`, `CloseTab`, `OpenCustomTab` or `RefreshGit`. The commands run after the frame.
- A custom tab that edits a file's document in place returns the file from `shared_editor()`. While it draws, `editor_area` lends that file's editor tab as `TabEnv::editor` (`Tabs::get_with_editor`), so both edit one `Document`. `has_pending_work()` (a debounced save) counts in `is_idle()`.
- The diff tab's working-tree side (`git/diff.rs`, `diff/edit.rs`) edits the lent tab's document, or a hidden `Document` loaded on a worker while no tab holds the file. The hidden one saves `SAVE_DEBOUNCE` after the last edit (`diff::tick` from `tick_workspaces`), on focus loss, on close and on Cmd+S (`diff::save_active`). `add_editor_tab` takes a dirty hidden document over (`diff::adopt_hidden`). Each doc version change starts one relayout on a worker (`Relayout`, `Document::text_snapshot`); the model generation drops a relayout that a reload overtook.
- Existing custom tabs: the diff tab (`git/diff.rs`, keys `diff:wt:<rel>` and `diff:<oid>:<rel>`), the merge tab (`git/conflicts/merge.rs`, key `merge:<path>`) and the image tab (`viewer/image.rs`, key `image:<path>`, `file_icon()` true so the strip shows the file's icon).
- The strip (`Tabs::show_bar`) wraps tabs onto rows in strip order (`tabs::flow`); a tab wider than the strip gets an ellipsis. Tab ids are `wid(("editor-tab", id))`. A tab activates and closes on the press: a close re-flows the rows, and a release-based click would land on the tab that moved under the pointer.
- `TAB_LIMIT` (50): `tabs::enforce_limit` runs after `add_editor_tab` and once per frame in `editor_area` (custom tabs open elsewhere). `Tabs::over_limit` closes LRU editor tabs that are clean and inactive, through `close_tab`, so they reach the Cmd+Shift+T history; custom tabs count but never close. `tabs::restore_set` caps a restored session at 50 files before they are read.

## Project tree selection and moves

- `ProjectTree::selected` is the lead row (the keyboard caret). The private `multi` list is the whole selection and counts only while it holds the lead, so code that sets `selected` directly (opening a file, tests) gets a single selection. Read the selection with `selection()`, `selection_len()` and `is_selected()`; change it with `select_one`, `select_many`, `toggle_selected` and `deselect_under`. `reveal` selects one row.
- Row presses act on the press frame (`pressed && is_pointer_button_down_on()`), not on the click: Cmd toggles, Shift selects the range from `anchor`, and a plain press on a row of a multi-selection only sets `press_pending`. The release (or `!down` on the next frame) turns a pending press into `select_one` unless a drag started. A drag of a selected row carries `tree::top_level(selection)`.
- Shift+arrows and Cmd+A are consumed before the plain arrows, because `consume_key(NONE, ArrowUp)` also takes Shift+Up.
- `tree_menu::run` gets every target. `TreeCommand::single_only` commands do nothing for several targets, and the menu disables them.
- A move (Cut + Paste, a drop) opens `Dialog::Move`: `ask_many` asks the servers per item, one after the other, and `fileops::merge_move_edits` joins the answers. Each answer assumes only its own item moves. A moved file that imports another moved item gets two edits at the same range; the edit of the imported item's move is re-based to the importer's new folder (`fileops::rebase_specifier`). The Computing phase is not drawn for `MOVE_DIALOG_DELAY`, so a move without imports does not flash a dialog. `relocate_all` applies the moves in order; after a failed move no import edit is applied.

## Git UI

- `app/src/git/mod.rs` holds the hooks the shell calls: `open_branches_popup` (Ctrl+Shift+Backtick), `push_clicked` (Cmd+Shift+K), `commit_tool_window`, `log_tool_window`, `log_header` (the Git window's header tabs), `load_storage` / `save_storage` (favourite branches), `on_editor_action`, `on_gutter_click`, `on_annotation_click`, `show_windows` (every frame after the panels: popups, dialogs) and `on_git_refreshed`.
- The modules: `changes.rs` (commit tool window), `diff.rs`, `editor_git.rs` (gutter popup, blame), `log.rs` + `log/` (filter bar, commit table), `commit_changes.rs` (changes pane), `window.rs` (Git window tabs), `branches.rs`, `remote.rs` (push, update, stash dialogs), `conflicts.rs` and `conflicts/merge.rs`.
- Entry points other modules call: `diff::open_worktree_diff`, `diff::open_commit_diff`, `diff::open_commits_diff` (several log commits), `diff::open_rev_local_diff` (a revision vs the file on disk), `log::show_file_history` (the Git window turns it into a History tab with `log::take_file_history`), `remote::open_push_dialog` (current branch) and `remote::open_push_dialog_for` (any local branch, from the branch tree). Fetch and Update: `remote::fetch(state, remote)` (quiet on success through `run_op_quiet`; the Log toolbar's `Fetch All Remotes`, the popup's Fetch, the tree's Remote group and remote folders) and `remote::update_branch(state, name)` (the current branch runs Update Project with the remembered merge/rebase; any other branch goes through `Repo::update_branch`, a fast-forward without checkout; a diverged branch fails with a message). The toolbar's `Update Project` opens the dialog.
- `remote::run_op(state, title, ok_body, check_conflicts, work, then)` runs a git write on a worker. It shows a toast, calls `refresh_git()`, checks for conflicts when asked, and then calls `then(state, ok)`.
- The log reloads after a git refresh only when a ref moved. It compares a fingerprint of HEAD and all branch tips; a move bumps `LogUi::refs_epoch`, and each `LogView` reloads the next time it is drawn.
- Log tabs: the Git window owns one `log::LogView` per Log or History tab and passes it to `log::log_body` each frame. `LogView` holds the filters, commits, graph, selection and the changes pane (`commit_changes::ChangesPane`). `state.ws.git_ui.log` (`LogUi`) holds what the tabs share: branch names, HEAD, the git user (`me`), the modal dialogs, the debounce map and the inbox.
- A job cannot reach a lent `LogView` through `AppState`. Log jobs post a `ViewMsg` into `LogUi::inbox` under the view id, and `log_body` applies the messages before it draws. The `--test-git-*` log hooks post to the view drawn last (`LogUi::active`).
- The text filter debounce is registered per view in `LogUi::debouncing` (part of `is_idle()`); an entry of a closed tab expires after 2 s.
- Git window (`window.rs`): `GitWindowUi.tabs[0]` is the main Log tab and never closes. Other tabs: more Log tabs (`+`), Console, History (from `log::take_file_history`), Compare with branch, Diff with a branch. The tab draws taken out of the list (`mem::replace`), so it can take `&mut AppState`; jobs reach a tab by its id (`tab_kind_mut`). Header tabs are press-based; `⌄` shows only when the tabs overflow. A11y: `Git tab <title>`, `Close <title>`, `New Log tab`, `Show all tabs`, `Switch to <title>`.
- Branch tree (`branch_tree.rs`): `build_rows` is pure (folders by `/` prefix, favourites first, then folders, then branches; a search keeps matches and their folders and unfolds everything). `show` returns `TreeAction`s; the window applies them after the tab is back in the list. Branch operations reuse `branches::run_action` and `branches::open_delete_dialog`. Refs (`branches()` + `tags()`) load once per window in `GitWindowUi.refs` and reload after `on_git_refreshed`. Favourites are full ref names per workdir in `GitWindowUi.favorites`, saved under the storage key `git_favorite_branches`; `install_project` keeps them across the `GitUi` reset. A11y: `HEAD (Current Branch)`, `Tree group <Local|Remote|Tags>`, `Tree folder <path>`, `Tree branch <name>`, `Tree remote branch <name>`, `Tree tag <name>`, badges `<name>: N to push` / `N to pull`, the search box `Branch or tag`. The `Branch <name>` label belongs to the title bar.
- Wide rows in the branch tree and the Log's changes tree (task 049): the `ScrollArea` scrolls both ways, every row is as wide as the widest row (measured per frame), and the row's click widget, highlight and a11y rect are `branch_tree::visible_part`: the row's band across the area's outer rect. So a press anywhere across the view hits the row at any horizontal offset, and a test that clicks a label's rect clicks something visible. A row of `available_width()` inside a two-way area leaves the right part of the view dead once it scrolls. `TreeState::scroll_x` and `ChangesPane::scroll_x` expose the offset for tests.
- Console (`console.rs`): `console::attach` sets the `Repo` command sink in `AppState::install_project`, before any clone; a `git console` thread posts each `CommandEvent` to the UI (dropped when the project generation changed). A finish event replaces its start event by id. A writing command reopens a closed Console tab without activating it. Durations are hidden in deterministic mode. A11y: `Command git <args>`.
- Log tests reach the main tab through `state.ws.git_ui.window.log_tab(0).view`. A11y labels: rows `Commit <subject>`, filter chips `Branch filter` / `User filter` / `Paths filter`, crosses `Reset branch filter` (and user, paths), toggles `Regex`, `Match Case`, `No Merges`, the refresh button `Refresh log`, the bar itself `Log filter bar`; the right pane `Log changes pane`, its tree `Changes tree`; changes rows `Changes root <path>`, `Changes folder <name>`, `Changed file <path>`. `LogView::row_style` tells how a row is drawn (bold author, dimmed merge, hollow HEAD).
- Log body layout: the changes pane is a right `SidePanel` over the full body height; the filter bar and the table share the `CentralPanel`, so the bar follows the splitter and clips filters that do not fit. The central panel keeps a 6 pt right margin: without it the table's scroll bar takes presses in the splitter's grab area, and the splitter can be grabbed only right of the edge.

## Languages

- `app/src/lang/` is the language registry. `LangId { TypeScript, Rust }` has a `LanguageSpec` each: extensions, root markers, server description, request concurrency.
- The `LanguageServer` trait: `open`, `change`, `close`, `locations` (Declaration, Source, Type), `references`, `hover`, `rename_edits` and `file_references` (file renames and safe delete, with candidate files), `files_renamed` and `files_deleted`, `status`, `stop_idle`, `running`, `take_notice`, `configure`, `shutdown`.
- `Bridge` runs one queue thread per language. TypeScript keeps strict request order. A Rust request runs on its own thread once the queue reaches it, so a request that waits for indexing does not hold up the next one.
- Read-only library paths (`lang::is_library_path`): `node_modules`, `$CARGO_HOME/registry`, `$CARGO_HOME/git`, `$RUST_SRC_PATH` and any `lib/rustlib/src/rust/` path, and server-generated documents (`lang::virtual_kind`).
- Virtual documents: a document a server generated opens read-only as an ordinary editor tab on a file outside the project. `lang::virtual_kind(path)` names its kind: `csharp::metadata_kind` recognises Roslyn's decompiled files under its `TMPDIR` (`decompiled`, `source`, `metadata`), and `ide_lsp::virtual_document` the files that `ide-lsp` wrote for non-file URIs (`ClientConfig::virtual_text` turns a URI into the request for its text; Roslyn's `roslyn-source-generated://` is `generated`, JDT's `jdt://` can follow). `EditorTab::virtual_kind` is set once in `EditorTab::new`; the tab title is `[<kind>] <name>`, the breadcrumbs start at `[<kind>]`, and `nav::display_path` shows the same. A request from inside goes to the language's server used last.
- C# (`lang/csharp.rs`): Roslyn runs as `dotnet <Microsoft.CodeAnalysis.LanguageServer.dll> --stdio` with its own `TMPDIR` per root (`$TMPDIR/harwex-ide-roslyn/<hash>`, removed on idle stop and shutdown, kept over a restart). The solution or projects open through `ClientConfig::startup_notifications` (`solution/open` / `project/open`); `workspace/projectInitializationComplete` ends the load, and requests, diagnostics and renames wait for it. The diagnostics plan is `Plan::server` (`SourceId::CSharp`); hint-severity items are dropped unless tagged unnecessary.
- rust-analyzer (`lang/rust.rs`): the lookup order is `rust.server` from `ide.toml`, `HARWEX_RUST_ANALYZER`, `PATH`, `~/.cargo/bin`, `rustup which rust-analyzer`. A candidate counts only if `--version` answers with `rust-analyzer`. The root is the topmost `Cargo.toml` with a `workspace` table, else the nearest `Cargo.toml`. The init options set `cargo.targetDir: true`, so rust-analyzer builds into its own `target/rust-analyzer` and never takes the lock of the user's `cargo build`. Diagnostics are off.
- Restart Language Servers (`lang/restart.rs`, `Languages::restart`): at the click the UI bumps the nav and hover generations, calls `FileProblems::recheck` on every tab and collects each open file's editor text. Each `Bridge` then stops its server at once on a `<lang> restart` thread (`LanguageServer::restart`; rust-analyzer also forgets its exe lookup), so a request stuck on a hung server fails without its timeout. A `Cmd::Restart` in queue order joins that thread, stops any server that queued requests started meanwhile, and opens the files again. Linters stop through `LintCmd::Restart`. One toast follows when every queue of every covered project is done. Tests swap in a fake server with `Languages::set_server` (`tests/app/restart.rs`).
- Stop / Start Language Servers (`lang::restart::language_servers` with `Action`): `Languages::off` is one `AtomicBool` shared by the language queues and the lint queue. While it is set, the queues drop Open/Change/Close, run requests against `OffServer` (empty answers, nothing starts) and treat lint requests as stale; `nav::request` and the hover return early, so no error toast appears. Stop is a restart with no files and the switch on; Start is a restart with the switch off. Stop resets each tab's problems. The switch is per project root: `SavedWorkspace::langs_off`, storage key `languages_off`, set by `install_project` before any file opens.
- rust-analyzer loading: `experimental/serverStatus` and `$/progress` feed a per-server status. An empty answer while the server is not quiescent waits for the next status change. "content modified" and "server cancelled" retry after 100 ms. Both stop at the 20 s request timeout.

## Diagnostics

- `app/src/diagnostics/`: `strategy.rs` (markers on disk, the pure `plan`), `oxlint.rs` (the oxlint `LintSource`), `eslint.rs` + `eslint_server.js` (the ESLint `LintSource` and the node script it runs with `node -e`), `problems.rs` (the counts widget, the hover text, the Problems tool window), `mod.rs` (`Problem`, `FileProblems` per editor tab, `LintQueue`, scheduling, F2).
- `EditorTab::problems` holds the plan, the last result per `SourceId` with the doc version it belongs to, and `marks` for `EditorView::problems`. `refresh(&doc)` shifts results through `Document::changes_since` once per version.
- `diagnostics::schedule` runs every frame: detection on a worker (cached per directory in `state.ws.diagnostics`), then a request 300 ms after the last edit, or at once after a save (`force`). `FileProblems::pending` is part of `is_idle()`.
- TS requests: `LanguageServer::diagnostics` on the TypeScript bridge, after `nav::flush_lsp`. Lint requests: `state.ws.langs.lint` (one thread, `LintCmd`). A request carries a generation; the queue skips one that is no longer the newest, and `deliver` drops a stale answer.
- A new linter: implement `LintSource`, add a `SourceId` and a `LintTarget` variant, extend `strategy::plan`. The UI needs no change. `LintQueue::counts(source)` gives the lint calls made and the stale requests skipped (tests check debounce with it).
- ESLint: `strategy::detect` finds the nearest config, the install and the TS project (`Markers::eslint_*`); `EslintPlan` carries the config dir and the root. The request is `textDocument/diagnostic` with an extra `harwex: {configDir, legacy}`. A cold (config dir, project) pair holds `jobs.busy("ESLint: loading <project>")` for the lint.

## Find in Files popup

- `app/src/find/`: `mod.rs` (state `FindInFiles`, the search, replace), `popup.rs` (the Cmd+Shift+F / Cmd+Shift+R popup), `history.rs` (history and storage).
- One search for every caller: `find::search_with(targets, source, query, mask, skip, cancel, limit, on_file)`. `source` is a `find::TextSource` (`source.rs`): the search asks it only for the bytes of a path and knows nothing about editors. `Disk` reads the file with one open and one `fstat`; it skips folders, files over 4 MB, binary extensions (`BINARY_EXTENSIONS`, no open) and files with a NUL in the first `PROBE` bytes (only that block is read). The UI callers (popup, Replace All, Open in Find Window, the Find window's ⟳) pass `find::unsaved_buffers(state)`: an `Overlay` of rope clones of the dirty documents, turned into text on the worker, so unsaved edits are searched and nothing is saved. `find::targets(state, scope)` turns a `SearchScope` into a `Targets` on the UI thread: the file index (`Targets::Index`, an `Arc` of `ws.index.files`) for Project and a recursive Directory inside the project while the index is built and not rebuilding, else a walk (Directory with `max_depth` 1 when not recursive) or a file list (Open Files: the editor tabs; Changed Files: `git.status` without deletions). `find::Mask::parse` reads `*.ts, !*.test.ts` (globs on the file name; a pattern with `/` matches the path end). The Find window's ⟳ uses the same three.
- Threads: a search uses `find::search_threads()` (half the cores, 1..=8), each at low priority (`lower_priority`: QoS utility on macOS, nice 10 on Linux). An index search hands out chunks of 512 paths in path order; small chunks put all threads into one folder and APFS lookups there queue up (slower than the walk on mono). Timing run on a real tree: `find/bench.rs` (ignored test, `HARWEX_FIND_BENCH_ROOT`, 4 threads; run it under `nice -n 19`).
- The popup's search is `find::start`: it cancels the last run (`AtomicBool`), bumps `generation`, and stops at `POPUP_CAP + 1` hits, so one more than 100 tells `100+`. Each file's hits are `jobs.post`ed as they are found (`add_streamed`, sorted insert); the final answer replaces them in path order. An index search of a small tree is one chunk, so its first 100 are the first 100 paths; a walk finds a different first 100 in each run. The header's `popup::status_text` says `Searching… N matches in M files` with a spinner (none in deterministic mode) while `searching`, then `N matches in M files`, `No matches`, or `… · limit reached` when capped.
- Every field or toggle change sets `debounce_at` (egui time + `DEBOUNCE_SECS`); `show_dialog` starts the search when it is due. `FindInFiles::has_pending_debounce` (part of `is_idle()`) covers the debounce and the popup preview's load or save.
- Open in Find Window (Cmd+Enter) searches on a worker up to `find::FIND_WINDOW_CAP` (5000) + 1 hits and calls `find_window::open_text_results`; the Find window's ⟳ does the same. `open_text_results` cuts the list to the cap (`find::cap_hits`) and sets `FindTab::truncated`; the tab then shows "5000+ results, showing the first 5000 found". The cap keeps the rows (each holds its line text) and the frame cost bounded; the parallel walk decides which 5000 come first.
- Replace All has no cap. It first opens `FindInFiles::replace_confirm` (`popup::confirm_dialog`) and runs `find::count_with` on a worker: it keeps only (path, count) per file, no hits. The dialog shows "Counting…" while it runs, then "Replace N occurrences in M files?". Esc, `Cancel Replace All` or the backdrop sets the cancel flag (the walk stops) and writes nothing. Enter or `Confirm Replace All` runs `replace_counted` with the counted query: closed files are searched again and written one file per thread at a time (`replace_all_in_file`, bytes between matches copied as they are); open documents are searched in a rope snapshot on the worker and written through `replace_in_doc`. A file with fewer matches than counted adds the difference to the `warn_changed` toast; a file with more gets them all replaced. While the dialog is open the popup takes no keys and a press outside does not close it.
- Replace (one hit) edits an open document through `transact` (one undo step, then saves) or a closed file on a worker, and shifts the later hits of the file (columns on the match's last line, lines below it). A hit may span lines: `FindHit::matched` is the whole text, `column..end_column` only its first line (rows, preview), `FindHit::end()` the real end. Replace (one hit) and the open-document part of Replace All check `matched` at its place first; a hit that no longer matches is skipped and `warn_changed` toasts the count. Open documents compare and write with LF (the rope has no `\r`).
- Keys: `find::take_keys` runs first in `app::shortcuts` and takes Escape, the arrows, Enter (not while `⏎` is on) and Cmd+Enter. Escape closes an open dropdown first. A press outside the popup and its dropdown closes it, except the press that opened it (`just_opened`). Closing flushes the preview edit and gives the editor the focus back.
- The query field takes the focus back whenever nothing has it (a press on a row or a toggle drops it). Only the open selects the old query.
- History: `AppState::find_history` (per canonical root: queries, masks, directories, newest first, 20 each), storage key `find_history`, written on close, on open of a result, Open in Find Window and Replace All.
- A11y: rows `Result <rel>:<line>`; toggles `Multiline`, `Match Case`, `Words`, `Regex`, `Clear search`, `Recursive`; tabs `In Project`, `Directory`, `Scope`; fields `File mask pattern`, `Directory path`, `Replace with`; `File mask:` checkbox; dropdown buttons `Search History`, `File Mask History`, `Directory History`, `Choose scope`; dropdown rows `Recent search <q>`, `Recent mask <m>`, `Recent directory <d>`, `Scope Open Files`, `Scope Changed Files`; `Choose Directory` (`…`, the platform's folder picker).

## Find window

- `app/src/find_window.rs` (+ `find_window/rows.rs`, pure): the bottom `ToolWindow::Find`. `state.ws.find_window` holds `tabs: Vec<FindTab>` and `active`. A `FindTab` has `kind` (`Usages(UsageOrigin)` or `Text { query, scope, mask }`), sorted `items: Vec<ResultItem>`, `selected: Option<NodeKey>`, `collapsed`, a `FilePreview` and a `generation`.
- Producers: `start_usages(state, origin, into) -> (tab, generation)` opens a tab in the searching state (or reuses tab `into` for ⟳), `finish_usages(state, tab, generation, result)` fills it; a closed or rerun tab drops the answer. `nav::usages` (symbol) and `tree_menu::find_file_usages` (file) use them. `open_text_results` is the Find in Files entry; its ⟳ searches through `find::targets` + `find::search_with`.
- `UsageKind::of(&Reference)`: definition, then an `import`/`use` line, then write, else read. tsserver reports no declarations (only for a search started at one) and counts declarations as writes.
- Rows are rebuilt only after a change (`FindTab::rows`). Keys: `Group(kind)`, `Dir(kind, display prefix)`, `File(kind, path)`, `Item(id)`; a collapsed single-child chain is keyed by its full prefix. A11y: `<Kind> group`, `Find folder <prefix>[ in <Kind>]`, `Find file <rel>[ in <Kind>]`, results `<rel>:<line>:<col>` (1-based), the tree `Find results`, tabs `Find tab <title>` / `Close <title>`, toolbar `Rerun`, `Previous Occurrence`, `Next Occurrence`, `Expand All`, `Collapse All`.
- The body lends the active tab out of the list while it draws (the preview needs `&mut AppState`); actions that reach tabs by id (open, rerun) run after it is back.
- Header tabs reuse the terminal drag pattern; the drop slot counts the tabs whose middle lies left of the pointer (with the dragged tab's middle a wide tab never passes a narrow first one).
- `preview.rs`: `FilePreview` edits the tab's `Document` when the file is open (its own `EditorState`), otherwise a hidden `Document` loaded on a worker (a channel per preview; the job cannot reach a lent preview). A changed document source gets a fresh `EditorState`, because highlight caches are keyed by doc version. A reveal resets the carets, so the match selection is applied one frame later. Saves run `SAVE_DEBOUNCE` after the last preview edit or on focus loss. Every owner calls `preview::tick` each frame (the Find window does it from `tick_workspaces`), `preview::flush` before dropping a preview, and counts `is_pending()` in `is_idle()`.

## Memory indicator

- `app/src/memory.rs`: a `memory sampler` thread walks the process tree from our pid every `[memory] interval_secs` and posts an `Arc<Sample>` to `state.memory.sample`. The status bar draws nothing until the first sample.
- Kinds: our own process is `Ide`. A direct child named `node`, `tsc`, `tsgo`, `*tsserver*` or `*rust-analyzer*` roots a `LanguageServer` subtree. Any other direct child roots an `Other` subtree. Descendants take the kind of their subtree root.
- Other projects: the status bar sends the `owned_pids()` of every workspace that is not active (`MemoryMonitor::others`, only on a change). Such a pid and its subtree are `OtherProjects` at any depth; the tooltip shows the group as one line. Tests add pids through `memory.extra_others`, because a fake tree has no real servers. The first sample is taken before any frame sends the sets, so it has no `OtherProjects`: set the pids, `step()` once, then `sample_now()` (both go down one channel, in order).
- Skipped subtrees: terminal shells (`Terminals::shell_pids`, sent to the thread when they change) and direct children named `git` or `git-*`. The walk never lists their children.
- `AppOptions::memory`: `Auto` (the OS source, off in deterministic mode), `Off`, `Real`, `Custom(Arc<dyn ProcessSource>)`. Tests pass a fake tree; its `now()` steps 15 s per sample, so CPU% is stable.
- `state.memory.sample_now()` asks for a sample at once. Tests wait for `sample.seq` to grow. The thread is not part of `is_idle()`.
- A press on the widget toggles `state.memory.menu_open` (`clicks::pressed`). The menu (`memory-menu` Area, window-level ids) holds `Restart Language Servers`, plus `(All Projects)` when two projects are loaded. The tooltip is not drawn while the menu is open.

## Theme and icons

- `app/src/theme.rs`: `theme::T` is one `static Theme`. It owns every color, `T.radius`, `T.space`, `T.font`, `T.badges`, `T.editor` (an `ide_editor::EditorTheme`) and `T.terminal` (an `ide_term::TerminalTheme`). The palette follows IDEA 2025 Islands Dark.
- `theme::install_fonts` bundles Inter Regular and SemiBold (UI) and JetBrains Mono Regular (editor, terminal, diff) from `app/assets/fonts/` with `include_bytes!`. egui's own fonts stay behind them as fallbacks. `theme::tests::fonts_cover_shortcut_symbols` asserts the shortcut glyphs (⇧ ⌘ ⌥ ⌃ ⏎ ⌫ ⎋, arrows, › … • ✓ ×) and the title spinner glyphs.
- A subset of Noto Sans Symbols 2 (OFL, `NotoSansSymbols2-Subset.ttf`) comes right after Inter in every family, before egui's fonts. It holds only the spinner glyphs that programs put into a terminal title: ◐ ◑ ◒ ◓, ◴ ◵ ◶ ◷, the dingbat stars U+2722–U+274B and Braille U+2800–U+28FF. Without it ◐ drew as a box and ◑ came from egui's icon font. To add glyphs, cut a new subset from the full font with `pyftsubset --unicodes=... --layout-features='' --no-hinting`.
- Claude Code (2.1.28x) titles its terminal `◐ <title>` and `◑ <title>` in turns every 960 ms while it works, and `✳ <title>` when idle. The glyphs have different advances, so `terminal::header_tabs` draws a leading status glyph (`terminal::status_glyph`) centered in a slot as wide as the widest glyph of the set. A spinner frame then moves no tab (`terminal::title_spinner_glyphs_draw_and_keep_the_tabs_still`).
- `app/src/icons.rs` draws line icons on a 16×16 grid from shapes that egui stores inline (segments, circles, rects, cubic Béziers). Icons need no textures, no SVG parsing and no allocation per frame. Keep new icons that way.
- Count badges (`app/src/badge.rs`, task 036): one pill look for the Terminal tabs, the Commit changed files (`ws.git.changes.len()`, a partly staged file once) and the open projects on the title-bar project widget. `badge::show` paints the pill at an icon's top-right corner and adds a hover-only a11y node over it (`Terminal, 3 tabs`, `Commit, 5 changed files`, `2 open projects`). The button labels stay unchanged, so tests that click `Commit tool window` keep working. A wide pill (`99+`) grows to the left so it stays inside the 40 pt strip. Counts are read from state each frame; a change to them re-records every snapshot that shows a terminal, a changed repository or two projects (the diff stays inside the strip and the project widget).
- A tool window header can hide its own window (closing the last terminal tab). `app::tool_window` then skips the body; before task 036 the Terminal body started a new shell in the hidden window.
- The title bar is merged with the window chrome (`with_fullsize_content_view`) and leaves 78 px for the macOS traffic lights.
- The title bar group (project widget, Settings, branch) is centered on the window width by `app::title_group_place` (pure): it measures the names first, then starts the row at the computed x. A window too narrow to center moves the group to `chrome` content x; if it still does not fit before `title_pad`, the longer name truncates with `…` first, then both. The projects popup, the settings menu and the branches popup read the widget rects, so they follow. The tint stays anchored to the left window edge.
- Trap: a popup that hangs from a centered title bar widget can sit near the right window edge. A submenu placed to its right then gets pushed back by egui's Area constraint and covers the hovered row, which drops the hover and the tooltip. The branches submenu has a definite width (its widest row text, at least 240) and opens on the left when the right side has no room. Rows that take `available_width()` inside an Area otherwise grow to the screen edge.
