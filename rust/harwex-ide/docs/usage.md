# harwex-ide: как пользоваться

## Установка

```bash
cd rust/harwex-ide
cargo install-ide
```

Команда собирает IDE в release. Бинарник ложится в `~/opt/harwex-ide/bin/harwex-ide`. Запущенная IDE при этом не ломается: файл заменяется атомарно.

На macOS команда создаёт `~/Applications/Harwex IDE.app`. Через него IDE запускается из Spotlight и Dock.

Команда добавляет `~/opt/harwex-ide/bin` в PATH. Для этого она дописывает блок `# >>> harwex-ide >>>` в rc-файл вашего shell: `~/.zshrc`, `~/.bash_profile` (macOS), `~/.bashrc` (Linux) или `~/.config/fish/conf.d/harwex-ide.fish`. Остальной файл не меняется. Повторный запуск блок не дублирует.

После установки откройте новый терминал или выполните `source ~/.zshrc`. Дальше IDE запускается так: `harwex-ide /path/to/project`.

Чтобы обновить IDE, снова выполните `cargo install-ide`.

Перед сборкой команда проверяет языковые инструменты и печатает таблицу:

- `rust-analyzer` нужен для перехода по коду Rust. Он считается найденным, только если `rust-analyzer --version` отвечает. Прокси rustup без компонента считается отсутствующим.
- `rust-src` нужен для перехода в стандартную библиотеку.
- `node` нужен для JS/TS.
- `git` нужен для всего git.

Если нет `rust-analyzer` или `rust-src`, команда спрашивает: `Install rust-analyzer via rustup? [y/N]`. Ответ `y` запускает `rustup component add rust-analyzer`. Ответ `n` или пустая строка пропускает установку. На любой другой ответ команда показывает, что прочитала, и спрашивает ещё раз. Второй непонятный ответ пропускает установку. Вопрос задаётся только в терминале. Без терминала команда пропускает установку и печатает команду для ручного запуска. Компонент ставится в активный toolchain rustup. Если установка не удалась, команда печатает ошибку rustup. Установка IDE при этом продолжается.

`node` и `git` команда сама не ставит. Она только подсказывает, как их поставить: `node` через nvm или `brew install node`, `git` через `xcode-select --install` или `brew install git`.

Если нет самого rustup, команда пишет, где его взять (https://rustup.rs), и продолжает.

Флаги идут после команды, например `cargo install-ide --dry-run`:

- `--prefix <dir>` — другая папка установки (по умолчанию `~/opt/harwex-ide`).
- `--no-path` — не трогать rc-файлы.
- `--no-app` — не создавать `.app`.
- `--yes` (или `-y`) — ставить недостающие компоненты rustup без вопроса.
- `--no-tools` — не проверять языковые инструменты.
- `--dry-run` — только показать проверки и действия. Команда ничего не ставит и не меняет.

Удаление: `cargo uninstall-ide`. Команда удаляет `bin`, `.app` и блок PATH. Компоненты rustup остаются на месте.

## Что нужно

- Rust (stable).
- `git` в системе. Сеть, коммиты, хуки и LFS идут через него.
- `node`. Для перехода по коду в проекте нужен `node_modules/typescript`. Если его нет, IDE возьмёт глобальный `typescript`.
- Если IDE не находит `node`, задайте путь вручную: `HARWEX_NODE=/path/to/node`.
- Если IDE не находит `git`, задайте путь так же: `HARWEX_GIT=/path/to/git`.
- Для перехода по коду Rust нужен `rust-analyzer`. Установка: `rustup component add rust-analyzer`.
- Для перехода в стандартную библиотеку нужен `rust-src`. Установка: `rustup component add rust-src`.

## Запуск без установки

```bash
cd rust/harwex-ide
cargo build --release
target/release/harwex-ide /path/to/project
```

Без аргумента из терминала IDE открывает текущую папку. Из Spotlight или Dock IDE открывает последний проект. Если последнего проекта нет, она показывает кнопку «Open Folder». Путь в аргументе важнее всего.

В одном окне открыто несколько проектов. Виден один, активный. Остальные работают в фоне: терминалы, языковые серверы и git продолжают работать. При запуске IDE снова открывает все проекты прошлого запуска и делает активным тот же проект. Каждый проект помнит свои окна инструментов и открытые файлы. Папка из аргумента или из терминала открывается рядом с ними и становится активной.

IDE запускается в одном экземпляре. Если IDE уже открыта, `harwex-ide <папка>` не открывает второе окно. Команда передаёт папку открытой IDE и сразу завершается с кодом 0. IDE открывает папку как новый проект или делает активным уже открытый проект с этой папкой. Окно IDE выходит на передний план. Без аргумента команда только выводит окно вперёд.

- Связь идёт через unix-сокет `$TMPDIR/harwex-ide-<uid>-default.sock`. Если путь длиннее 103 байт (очень длинный `$TMPDIR`), имя сокета короче: `hx-<uid>-<хеш>.sock`. Если IDE упала и сокет остался, следующий запуск удаляет его и становится главным.
- `--new-instance` запускает отдельную IDE, даже если одна уже открыта. Эта IDE сокет не слушает.
- `HARWEX_IDE_SOCKET=<имя>` задаёт своё имя сокета (`$TMPDIR/harwex-ide-<uid>-<имя>.sock`). Значение с `/` считается полным путём.
- Фоновый режим (`HARWEX_IDE_BACKGROUND=1`, флаги `--test-*`) без `HARWEX_IDE_SOCKET` сокет не использует. Такой запуск никогда не попадает в вашу открытую IDE.

### Список проектов

Если в окне открыто больше одного проекта, на значке проекта в заголовке стоит синий кружок с их числом.

Клик по имени проекта в заголовке открывает список, как в IDEA. Второй клик по имени, Esc или клик мимо списка закрывают его.

- **Open...** открывает системный выбор папки. Выбранная папка открывается как ещё один проект в этом окне и становится активной. Если папка уже открыта, IDE просто переключается на неё.
- **Open Projects** показывает проекты этого окна: значок, имя и путь (домашняя папка пишется как `~`). Активный проект выделен жирным и галочкой. Клик по проекту делает его активным. При наведении справа появляется крестик. Крестик закрывает проект. Если в проекте есть несохранённые файлы, IDE сначала спросит, что с ними делать.
- **Recent Projects** показывает недавние проекты, которые сейчас не открыты. Новые идут сверху, видно не больше 10. Клик открывает проект и делает его активным. Крестик при наведении убирает проект из списка. Список сохраняется между запусками. Если папки проекта больше нет на диске, строка серая. Клик по ней ничего не открывает и показывает уведомление "Folder not found". Крестик убирает такую строку.
- Стрелки вверх и вниз двигают выделение, Enter выбирает строку.

## Окно

Оформление повторяет IntelliJ IDEA 2025 «Islands Dark». Фон окна почти чёрный. Каждое окно инструмента и редактор лежат на нём отдельным скруглённым «островом».

- Заголовок окна совмещён с панелью IDE. Слева стоят кнопки macOS.
- Посередине заголовка стоит группа: значок проекта, кнопка настроек и ветка. Группа стоит по центру ширины окна. В узком окне группа сдвигается вправо и не заходит на кнопки macOS. Если места всё равно мало, длинное имя обрезается с `…`.
- Значок проекта — цветной квадрат с инициалами. Рядом имя проекта. Цвет значка слегка подкрашивает заголовок слева. Клик по имени открывает список проектов (см. ниже). Список выпадает под именем.
- После имени стоит кнопка настроек (шестерёнка). Она сразу открывает окно Settings, как Cmd+, (см. «Настройки» ниже). Другую папку открывает список проектов.
- Дальше стоит текущая ветка со значком. Ветка только показывает имя. Клик по ней ничего не делает.
- Список веток открывает Ctrl+Shift+\`. Список выпадает под веткой.
- Кнопок Update, Commit, Push и поиска в заголовке нет. Их заменяют клавиши: Cmd+K, Cmd+Shift+K, Shift Shift или Cmd+Shift+O. Update Project и Fetch стоят кнопками в строке фильтров лога (окно Git) и есть в списке веток (Ctrl+Shift+\`).
- Левая полоса иконок открывает окна. Верхняя группа: Project, Commit. Нижняя группа: Find (лупа), Git (лог), Problems, Terminal, Notifications. Открытое окно подсвечено. Подсказка у иконки показывает клавишу окна.
- Клавиши окон как в IDEA: Cmd+1 — Project, Cmd+0 — Commit, Cmd+9 — Git, Cmd+6 — Problems, Alt+F12 — Terminal. Клавиша открывает окно и переводит в него клавиатуру: в дерево Project, в список файлов Commit, в таблицу лога Git. Если окно уже открыто и клавиатура в нём, та же клавиша прячет окно и возвращает клавиатуру в редактор. У Problems нет списка с фокусом: окно просто становится активным, и Esc или Shift+Esc работают как после клика в него. У Find своей клавиши нет: Cmd+3 открывает терминал в папке. Shift+Cmd+цифра ничего не делает. Клавиши окон работают и из терминала.
- Cmd+Shift+F12 прячет все окна (Hide All Tool Windows). Повторное нажатие, пока все окна спрятаны, возвращает их. Если между нажатиями открыть какое-то окно, следующее нажатие прячет уже его. Клавиатура после скрытия уходит в редактор. Работает и из терминала.
- Точка на иконке Notifications значит, что есть непрочитанные уведомления.
- Числа на иконках, как в IDEA. На Terminal: сколько вкладок терминала открыто в этом проекте. На Commit: сколько файлов изменено (staged, unstaged и новые файлы; файл, изменённый частично, считается один раз). При нуле числа нет. Больше 99 показывается как `99+`.
- Правой полосы нет. Редактор доходит до правого края окна.
- У каждого окна есть заголовок. Кнопка «−» справа прячет окно.
- Shift+Esc прячет активное окно, как в IDEA. Активное окно — то, где фокус или где был последний клик. Если такого нет, прячется нижнее окно, потом левое. Клавиатура возвращается в редактор. Shift+Esc работает из любого фокуса: из редактора, дерева Project, списка Commit и поля сообщения, лога Git, результатов Find, окна Problems, терминала. Когда открытых окон нет, Shift+Esc ничего не делает.
- Esc в окне Project, Commit, Git, Find, Problems или Notifications возвращает клавиатуру в редактор, как в IDEA. Окно остаётся открытым. Окно считается активным, если в нём фокус. Окно без фокуса (например, Problems) активно после клика в него. Если Esc нужен чему-то внутри окна, первый Esc уходит туда: он закрывает контекстное меню, попап или диалог, отменяет переименование или перетаскивание. Следующий Esc возвращает клавиатуру в редактор. Без открытой вкладки редактора Esc ничего не делает.
- Клавиши поиска в файле работают и из окна. Они переводят фокус в редактор и делают там своё дело: Cmd+F (поиск), Cmd+R (замена), Cmd+G и Shift+Cmd+G (следующее и предыдущее совпадение), Ctrl+Cmd+G (выделить все совпадения). Из поля ввода внутри окна эти клавиши в редактор не уходят. Глобальные клавиши (Search Everywhere, Find in Files, переключение окон) работают как раньше.
- В центре: вкладки редактора и диффов. Активная вкладка светлее остальных.
- Пустой редактор показывает подсказки: Search Everywhere, Go to File, Recent Files, Navigation Bar.
- Файл можно перетащить в окно. IDE откроет его во вкладке.
- Статус-бар: язык файла, сервер языка, фоновые задачи. Позиции курсора и ветки в нём нет. Ветка видна в заголовке.
- Фоновые задачи видны в статус-баре справа от хлебных крошек. Для них отведено место постоянной ширины (204 pt, в окне уже 800 pt — 136 pt), поэтому крошки не сдвигаются, когда задача начинается или заканчивается. Когда задач нет, место пустое. Длинное имя задачи обрезается с `…`. Полное имя видно при наведении.
- Задача видна с временем работы, например `Annotating 12s`, и кнопкой `×`. `×` отменяет задачу. Git останавливается вместе со своими дочерними процессами (хуки, git-lfs), `index.lock` не остаётся. Запрос к языковому серверу отменяется через `$/cancelRequest`. После отмены всплывает одно уведомление `Cancelled: <задача>`.
- Если задач несколько, видна самая старая и `+N`. Наведение показывает все задачи. Клик по тексту открывает окно задач над статус-баром. В нём у каждой задачи имя, полоса прогресса и `×`. Если задача сообщает, сколько сделано, полоса показывает долю. Иначе по полосе бегает отрезок. У задачи, которую нельзя прервать (например, перезапуск языковых серверов), `×` нет. Окно обновляется само, пока открыто. Escape, клик мимо окна или конец последней задачи закрывают его.
- Через 30 секунд задача становится оранжевой: `… — still running, Cancel?`. Так видно, что git или сервер завис.
- Справа в статус-баре видна память IDE, например `1821 of 32768M`. В сумму входят IDE и языковые серверы всех открытых проектов. Терминалы и git в неё не входят. Полоса показывает долю от всей RAM. IDE обновляет число раз в 15 секунд. Подсказка при наведении показывает каждый процесс активного проекта: имя, pid, память и CPU. Процессы остальных открытых проектов идут одной строкой `Other projects` с общей суммой. Зомби-процессы (завершённые дети, которых родитель не дождался) не получают своих строк: под их родителем стоит одна строка `N defunct`. Сервер oxlint копит по одному зомби на каждую проверку с типами. Когда их больше 20, IDE тихо перезапускает его в паузе между проверками. Внизу подсказки идёт таймер до следующего замера.
- Клик по индикатору памяти открывает меню с пунктом `Restart Language Servers`. Он останавливает все языковые серверы и линтеры активного проекта: TypeScript, rust-analyzer, ESLint и oxlint. Серверы стартуют заново и сразу получают открытые файлы с текущим текстом, вместе с несохранёнными правками. Ответы на запросы, отправленные до рестарта, IDE отбрасывает. Когда открыто несколько проектов, в меню есть ещё `Restart Language Servers (All Projects)`. После рестарта всплывает уведомление `Language servers restarted`. Меню закрывается по Escape, по клику мимо него или по второму клику на индикатор. Подсказка при наведении работает, пока меню закрыто.
- Пункт `Stop Language Servers` в том же меню выключает языковые серверы и линтеры проекта и держит их выключенными. Открытие файла, правки и Cmd+B их не поднимают. Навигация, подсказки и проверка ошибок молча ничего не делают. В статус-баре видно `Language servers off`, а индикатор памяти дописывает `servers off`. Пункт меняется на `Start Language Servers`: он запускает серверы снова и отдаёт им открытые файлы. Выключенное состояние запоминается для проекта и сохраняется после перезапуска IDE. Когда открыто несколько проектов, есть варианты `(All Projects)`.

Шрифты встроены в IDE. Интерфейс использует Inter, код и терминал используют JetBrains Mono.

Слева в статус-баре видны хлебные крошки: корень проекта › папки › файл. Они показывают файл активной вкладки. Вкладка диффа тоже показывает свой файл.

Файл вне проекта начинается с корня библиотеки. У корня значок книг. Полный путь на диске не виден.

- Исходники Rust (rust-src) начинаются с крейта: `std`, `core` или `alloc`. Дальше идёт путь внутри `src` крейта.
- Крейт из `~/.cargo/registry` начинается с имени и версии, например `serde 1.0.228`.
- Пакет из `node_modules` начинается с имени пакета, например `typescript` или `@scope/name`.
- Другой файл начинается с `External`. Дальше идут не больше трёх последних частей пути.
- Список корня показывает папку библиотеки. Папки выше корня не видны.

- Клик по папке открывает список её содержимого. Папки идут первыми. Цвет имени показывает git-статус.
- Текущий элемент пути выделен.
- Наведение на папку в списке открывает вложенный список.
- Клик по файлу открывает его.
- Списки стоят на статус-баре и растут вверх. Вложенный список встаёт справа от родителя. В списке до 18 строк. Длинный список прокручивается.
- Alt+Home переводит клавиатуру в хлебные крошки. Выделен файл. Список не открыт. В терминале Alt+Home не работает.
- Стрелки влево и вправо выбирают сегмент. Выбранный сегмент прокручивается в видимую часть. Стрелка вниз или Enter открывает список сегмента. Стрелка вверх или Escape возвращает клавиатуру в редактор.
- В списке стрелки вверх и вниз двигают выделение. С последней строки выделение переходит на первую.
- Стрелка вправо на папке открывает вложенный список. Стрелка вправо на файле во вложенном списке ничего не делает. Стрелка влево во вложенном списке возвращает на уровень назад.
- В первом списке стрелки влево и вправо открывают список соседнего сегмента. В нём выделен элемент текущего пути.
- Стрелка вверх на первой строке первого списка закрывает список. Выделенным остаётся его сегмент.
- Enter на файле открывает файл. Enter на папке входит в неё. Escape закрывает всё и возвращает клавиатуру в редактор.
- Если в открытом списке печатать, список фильтруется, как speed search в IDEA. Набранный текст виден в поле над строками. Совпавшие буквы подсвечены. Строки без совпадения скрыты. Выделение переходит на первое совпадение. Буквы ищутся без учёта регистра и по порядку, не обязательно подряд. Если совпадений нет, поле красное и в списке написано `No matches`.
- С фильтром стрелки вверх и вниз ходят только по совпадениям и переходят с последнего на первое. Backspace стирает последнюю букву. Первый Escape очищает фильтр, второй закрывает список. У каждого вложенного списка свой фильтр. Набранный текст не попадает в редактор.
- Клавиши работают и после клика по сегменту. Стрелки не доходят до редактора.
- Клик по имени файла открывает меню файла. В нём пункт `Select in Project` (⌥F1) и те же пункты, что в меню файла в дереве проекта: копирование пути, поиск, переименование, удаление, `Open In`, git. Повторный клик или Escape закрывает меню.
- Правый клик по любому сегменту проекта открывает такое же меню для этого файла или папки.
- Двойной клик по папке выделяет её в окне `Project` и раскрывает её. Окно открывается, если было скрыто. Путь раскрывается, строка прокручивается в вид, клавиатура переходит в дерево.
- Соседние файлы показывает стрелка вниз или Enter на сегменте файла.
- Когда клавиатура в хлебных крошках, клавиши файлов из дерева работают на выбранном сегменте: ⇧⌘C и ⌥C копируют путь, ⇧F6 переименовывает, ⌥F7 ищет использования, ⌘X/⌘C/⌘V и Delete работают как в дереве, ⌥F1 выделяет сегмент в окне `Project`. Клавиши редактирования не доходят до редактора. Escape возвращает клавиатуру в редактор.
- У файлов вне проекта меню и клавиш файла нет. Клик по такому файлу показывает соседние файлы.
- Если путь не помещается, крошки прокручиваются вбок: колесом мыши, Shift+колесом или жестом на трекпаде. Сначала видно конец пути с файлом, начало уходит за левый край. Ваша прокрутка сохраняется, пока не сменится файл. Другой файл снова показывает конец пути. Список и меню открываются под сегментом там, где он сейчас виден.
- Полоса прокрутки крошек тонкая и лежит под текстом у нижнего края. При наведении она не растёт и не закрывает имена.
- Файлы из `.gitignore` в списках не видны.

IDE запоминает, какие окна открыты и какого они размера.

В дереве файлов цвет имени показывает git-статус: синий — изменён, зелёный — добавлен, красный — не под git. Файлы из `.gitignore` скрыты. Дерево обновляется само, когда файлы меняются на диске.

Дерево работает как в IDEA:

- Перед папкой стоит тонкая стрелка. Стрелка `›` значит, что папка свёрнута. Стрелка `⌄` значит, что папка раскрыта.
- Клик в любом месте строки выделяет её. Папка от клика не раскрывается.
- Двойной клик в любом месте строки раскрывает или сворачивает папку. Двойной клик по файлу открывает файл.
- Клик по стрелке сразу раскрывает или сворачивает папку. Стрелка ловит клик во всей своей ячейке, на всю высоту строки.
- Выделенная строка синяя, пока клавиатура в дереве. Пока кнопка мыши нажата, строка остаётся синей. Когда клавиатура уходит в редактор или терминал, строка становится серой. Строка под мышью слегка подсвечена.
- Стрелки вверх и вниз двигают выделение. Стрелка вправо раскрывает папку. На раскрытой папке она переходит к первому файлу внутри. Стрелка влево сворачивает папку. На свёрнутой папке или на файле она переходит к родительской папке.
- Enter открывает файл. Enter на папке раскрывает или сворачивает её. Escape возвращает клавиатуру в редактор.
- Свёрнутая папка сворачивает и все папки внутри себя. При следующем раскрытии видно только её содержимое, без вложенных раскрытых папок.
- Speed search, как в IDEA. Если печатать, пока клавиатура в дереве, начинается поиск по видимым строкам. Файлы внутри свёрнутых папок не ищутся. Набранный текст виден в поле на месте строки с именем проекта. Совпавшие буквы подсвечены. Выделение переходит на первое совпадение. Если выделенная строка ещё совпадает, она остаётся выделенной. Буквы ищутся без учёта регистра и по порядку, не обязательно подряд, как в попапах хлебных крошек. Если совпадений нет, поле красное.
- Во время поиска стрелки вверх и вниз ходят только по совпадениям, по кругу. Backspace стирает последнюю букву, а не удаляет файл. Escape убирает поиск, клавиатура остаётся в дереве. Enter открывает файл или раскрывает папку и закрывает поиск. Клик по строке и уход клавиатуры из дерева тоже закрывают поиск. Текст с Cmd, Ctrl или Alt в поиск не попадает: это сочетания клавиш.
- Кнопка с прицелом в заголовке окна Project называется Select Opened File. Она раскрывает дерево до файла активной вкладки. Потом она выделяет файл и прокручивает дерево к нему.
- Глубокие папки и длинные имена прокручиваются вбок: свайп двумя пальцами или Shift+колесо. Горизонтальная полоса появляется, только если строка шире окна. Строка ловит клики, правый клик и перетаскивание по всей видимой ширине, на любом сдвиге.
- Select Opened File и стрелки вверх и вниз сдвигают дерево вбок, если имя выбранной строки не видно. Как в IDEA, в окно попадает начало имени, а не его конец.
- Alt+F1 делает то же самое из редактора. В терминале Alt+F1 уходит в терминал.
- Можно выделить несколько строк, как в IDEA:
  - Cmd+клик добавляет строку к выделению или убирает её.
  - Shift+клик выделяет все строки от прошлой выбранной до этой.
  - Shift+стрелка вверх или вниз расширяет выделение на одну строку.
  - Cmd+A выделяет все видимые строки. Файлы внутри свёрнутых папок не выделяются.
  - Простой клик по одной из выделенных строк сначала оставляет всё выделение. Так можно сразу тащить все строки. Если отпустить кнопку без перетаскивания, останется выделена только эта строка.
- Перетаскивание, Cut, Copy, Paste, Delete и меню работают со всеми выделенными строками.
- Файл или папку можно перетащить мышью в другую папку. Рядом с курсором видно имя. При нескольких строках там написано «3 items». Папка, куда упадёт файл, обведена синей рамкой. Если отпустить над файлом, файл уйдёт в папку этого файла.
- Перенос работает как Cut и Paste: импорты обновляются, при совпадении имени IDE спросит, что делать. С зажатым Alt файл копируется, а не переносится.
- Папку нельзя бросить в неё саму или в её подпапку: рамки нет, курсор показывает запрет. Бросок в ту же папку, где файл уже лежит, ничего не меняет. Escape отменяет перетаскивание.
- Если держать файл над свёрнутой папкой около секунды, папка раскроется. У верхнего и нижнего края дерево прокручивается само.
- Перетаскивание мышью не прокручивает дерево. Колесо и тачпад прокручивают как обычно.

### Меню файла в дереве

Правый клик по файлу или папке выделяет строку и открывает меню. Правый клик по одной из нескольких выделенных строк оставляет выделение. Тогда меню работает со всеми выделенными строками. Клавиши ниже работают, пока клавиатура в дереве.

При нескольких выделенных строках пункты для одного файла выключены: New File, New Directory, Paste, Find Usages, Find in Files, Replace in Files, Rename, Open In, Git Show History и Mark Directory as Excluded. Cut, Copy, Copy Absolute Path, Copy Project Path, Delete, Git Rollback и Reload from Disk работают со всеми. Пути копируются по одному на строку.

| Пункт | Клавиши | Что делает |
|---|---|---|
| New File… / New Directory… | Cmd+. | Создаёт файл или папку в выбранной папке (или в папке файла). Имя `a/b/c.ts` создаёт и папки. Новый файл сразу открывается. |
| Cut | Cmd+X | Помечает файл для переноса. Имя становится серым. Escape снимает пометку. |
| Copy | Cmd+C | Помечает файл для копирования. Имя файла попадает в буфер обмена. |
| Paste | Cmd+V | Переносит или копирует помеченные файлы в выбранную папку. Если имя занято, IDE спросит: Overwrite, Keep Both или Cancel. При нескольких файлах окно появляется на каждый конфликт и есть ещё кнопка Skip. Два выбранных файла с одним именем из разных папок тоже конфликтуют друг с другом. Overwrite отправляет старый файл в Корзину. |
| Copy Absolute Path | Shift+Cmd+C | Копирует полный путь. |
| Copy Project Path | Alt+C | Копирует путь от корня проекта. |
| Find Usages | Alt+F7 | Показывает, кто импортирует файл. Список в новой вкладке окна Find. |
| Find in Files… / Replace in Files… | Shift+Cmd+F / Shift+Cmd+R | Ищет или заменяет текст в выбранной папке. |
| Rename… | Shift+F6 или Alt+2 | Переименовывает и обновляет импорты. |
| Delete… | ⌫ или Cmd+⌫ | Переносит в Корзину macOS. Если в Settings › System выключить «Move files to the Trash…», удаляет навсегда. Окно тогда спрашивает «Delete … permanently?». |
| Open In Finder / Open In Terminal | — / Cmd+3 | Показывает файл в Finder. Открывает новую вкладку терминала в папке. |
| Git Rollback… / Git Show History | | Откатывает изменения файла или папки после подтверждения. Показывает историю в окне Git. |
| Reload from Disk | | Перечитывает открытый файл с диска. Если в нём есть несохранённые правки, IDE спросит. |
| Mark Directory as Excluded / Cancel Exclusion | | Исключает папку из поиска. |

Перенос и переименование:

- Rename, Paste после Cut и перетаскивание обновляют импорты. Для JS/TS их считает сервер TypeScript. Для Rust `rust-analyzer` правит `mod` и пути к модулю. `rust-analyzer` делает это только при переименовании внутри той же папки. Перенос `.rs` в другую папку импорты не правит.
- Сначала IDE быстро ищет текстом файлы, которые могут импортировать файл. Сервер TypeScript загружает проекты этих файлов. Поэтому пакет монорепозитория, который никто не открывал, тоже получит правки.
- Rename показывает итог перед применением: «Rename to "x.ts" and update 7 imports in 4 files». Ниже список файлов и счётчики: сколько файлов просмотрено, сколько кандидатов, сколько проектов загружено. Back возвращает к имени, Cancel отменяет всё. Если импортов нет, файл переименуется сразу.
- Перенос (Paste после Cut или перетаскивание) показывает такое же окно перед применением: «Move "x.ts" to src/lib and update 3 imports in 2 files». Кнопка Move переносит и правит импорты. Cancel ничего не меняет на диске, пометка Cut остаётся. Если импортов нет, файлы переносятся сразу, без окна. Если сервер языка не ответил (например, TypeScript не установлен), файлы тоже переносятся, а уведомление «Imports not updated» говорит, что импорты не изменены.
- Перенос нескольких строк показывает одно общее окно: «Move 3 items to src/lib and update …». Если один перенесённый файл импортирует другой перенесённый файл, IDE пишет путь между их новыми местами.
- Пока сервер считает, в окне видна строка прогресса и кнопка Cancel. Cancel ничего не меняет на диске.
- Галочка «Also list text occurrences» показывает упоминания имени в комментариях, строках и других файлах. IDE их только показывает и не меняет.
- Открытые файлы меняются через редактор и сохраняются. Cmd+Z отменяет правку одним шагом. Закрытые файлы IDE правит на диске параллельно.

Удаление:

- Окно Delete спрашивает подтверждение один раз, даже для нескольких строк: «Move 2 items to the Trash: a.md, c.md?». Галочка «Search for usages (safe delete)» включена сразу. IDE показывает, кто ещё импортирует файл. Удалить всё равно можно.
- Если сервер языка не отвечает (язык выключен или файл не код), IDE ищет относительные импорты и `mod` текстом.
- Файл уходит в Корзину, а не стирается. Вкладки удалённых файлов закрываются.

Исключённые папки:

- Mark Directory as Excluded пишет папку в `.harwex/ide.toml`, в `[project] excluded`.
- Исключённая папка и её файлы в дереве тусклые оранжевые.
- Search Everywhere и Find in Files их не ищут.

## Настройки

Cmd+, или шестерёнка в заголовке открывают окно Settings. Слева список страниц, справа страница. OK применяет изменения, Cancel и Esc их отбрасывают. Окно открывается на странице, которую показывали последней.

У каждого блока справа от заголовка написано, где живут его значения:

- **Global · all projects** — настройки самой IDE. Они общие для всех проектов и хранятся в данных IDE. OK применяет их сразу.
- **Project · .harwex/ide.toml** — настройки проекта. OK записывает в `.harwex/ide.toml` только изменённые ключи. Остальной текст и комментарии файла остаются. Пустое поле пути убирает ключ, тогда IDE ищет программу сама. Кнопка `Open .harwex/ide.toml` внизу открывает файл в редакторе.

Страницы:

- **System › Files** (глобальные):
  - «Move files to the Trash instead of deleting permanently» (включено). Delete в дереве переносит в Корзину macOS. Выключено — удаляет навсегда.
  - «Save files if the IDE is idle for N seconds» (включено, 15 секунд). Если N секунд не было ни клавиш, ни мыши, IDE сохраняет все изменённые файлы. Форматирование при этом не запускается.
  - «Save files when switching to a different application or to the built-in terminal» (включено). Изменённые файлы сохраняются, когда окно IDE теряет фокус или когда клавиатура уходит в терминал.
  - «Back up files before saving» (включено). Перед каждым сохранением IDE кладёт прошлую версию файла в папку `backups` в данных IDE. Для каждого файла хранятся 5 последних версий. Файлы больше 1 МБ не копируются. Копии старше 7 дней удаляются при запуске.
  - Подсказка «Autosave cannot be disabled completely»: коммит всегда сначала сохраняет файлы, а закрытие изменённой вкладки спрашивает про сохранение.
- **System › Sync external changes** (глобальные):
  - «When switching to the IDE window or opening an editor tab» (включено). Когда окно IDE получает фокус, IDE перечитывает все открытые файлы. Когда открывается или выбирается вкладка, IDE перечитывает её файл. Вкладка без несохранённых правок получает текст с диска. Вкладка с правками их сохраняет.
  - «Periodically when the IDE is inactive (experimental)» (выключено). Пока окно IDE без фокуса, IDE перечитывает открытые файлы каждые 10 секунд.
- **Keymap** — список действий и их клавиш. Только для чтения. Поле сверху фильтрует по названию, группе или клавишам: `save`, `⌘K`.
- **Editor** — размер шрифта редактора (глобальный, 9–28 pt) и форматирование oxfmt проекта (см. «Форматирование: oxfmt»).
- **Languages** (проектные) — какие языковые серверы проект может запускать (`languages`), пути к rust-analyzer, clangd, серверу Roslyn и dotnet, строка «In use» с найденной программой и сколько серверов запущено. Ниже Auto / On / Off для ошибок TypeScript, oxlint, его type-aware правил и ESLint. Auto значит: включено, если у пакета есть конфиг и сам линтер.
- **Frameworks** (проектные) — Unreal Engine: движок по умолчанию (`[unreal] engine`), индекс файлов движка (`index_engine`) и движок для каждого найденного проекта `*.uproject` (`[unreal.projects."<папка>"] engine`). Проект появляется в списке, когда открыт один из его C/C++ файлов. Для Unity настроек нет.

## Файлы и поиск

| Действие | Клавиши |
|---|---|
| Найти файл | Shift Shift или Cmd+Shift+O |
| Недавние файлы | Cmd+E |
| Найти текст по проекту | Cmd+Shift+F |
| Заменить текст в файлах | Cmd+Shift+R |
| Сохранить | Cmd+S |
| Сохранить все | Cmd+Alt+S |
| Отформатировать файл (oxfmt) | Cmd+Alt+L |
| Настройки (Settings) | Cmd+, |
| Закрыть вкладку | Cmd+W или средняя кнопка мыши |
| Открыть закрытую вкладку | Cmd+Shift+T |
| Закрыть все вкладки, кроме этой | Alt+клик по крестику вкладки |

В списке Search Everywhere и Recent Files длинный путь обрезается многоточием `…`. Если не помещается даже имя файла, у имени вырезается середина: видны начало, `…` и конец с расширением. Путь обрезается раньше имени. Если строка обрезана, наведение на неё сразу раскрывает её, как в IDEA. Раскрытая строка лежит поверх списка в одну линию, с тем же фоном. Её правый край совпадает с правым краем строки, а сама она растёт влево, но не дальше левого края экрана. Если и так не помещается, путь и имя обрезаются по тем же правилам.

Список целей перехода (Cmd+B с несколькими целями) раскрывает строки по-старому: строка продолжается вправо поверх края окна, а если не помещается на экране, сдвигается влево.

Точка на вкладке значит, что в файле есть несохранённые изменения. Точка стоит на месте крестика закрытия.

Вкладки не уходят за край окна. Если они не помещаются в одну строку, полоса вкладок переносится на следующие строки, и редактор становится ниже. Порядок вкладок не меняется: клик по вкладке не переставляет строки. После закрытия вкладки остальные сдвигаются и занимают её место.

Вкладку можно перетащить мышью на другое место, как в IDEA. Перетаскивать можно и в другую строку полосы. Вкладка едет за курсором, остальные стоят на месте. Синяя черта показывает, куда встанет вкладка. Перетаскиваемая вкладка становится активной. Esc отменяет перетаскивание. Отпускание кнопки далеко от полосы вкладок тоже отменяет его. Короткий клик без движения только открывает вкладку. Новый порядок сохраняется после перезапуска IDE. Close Tabs to the Left/Right и Cmd+Shift+T берут новый порядок.

Правый клик по вкладке открывает меню, как в IDEA. Это работает и на вкладках диффа и merge. Пункты меню действуют на вкладку под курсором, а не на активную:
- Close (Cmd+W) закрывает эту вкладку.
- Close Others закрывает все вкладки, кроме этой. Эта вкладка становится активной.
- Close All закрывает все вкладки.
- Close Tabs to the Left и Close Tabs to the Right закрывают вкладки до этой и после неё. Порядок берётся из полосы вкладок, даже если она в несколько строк.
- Close Unmodified закрывает вкладки без несохранённых изменений и без изменений в git. Вкладки с изменениями остаются.

Пункт, который ничего не закроет, серый. Например, Close Others при одной вкладке. Вкладки закрываются по порядку слева направо. Вкладка с несохранёнными изменениями спрашивает, как при Cmd+W. Cancel останавливает закрытие остальных вкладок. Cmd+Shift+T возвращает закрытые вкладки по одной.

В проекте открыто не больше 50 вкладок, как Tab limit в IDEA. Пятьдесят первая вкладка закрывает вкладку, в которую дольше всего не заходили. Активная вкладка, вкладки с несохранёнными изменениями и вкладки диффа и merge так не закрываются. Если все вкладки изменены, IDE ничего не закрывает, и вкладок становится больше 50. Вкладку, закрытую по лимиту, возвращает Cmd+Shift+T. После перезапуска IDE открывает не больше 50 сохранённых вкладок, активная среди них всегда есть.

Cmd+Shift+T открывает последнюю закрытую вкладку, как в браузере. Файл встаёт на своё старое место в полосе вкладок, каретка стоит там же, где была. Прокрутка тоже прежняя: сверху та же строка, сбоку тот же сдвиг. С переносом строк сверху та же строка текста, даже если окно стало уже или шире. Следующее нажатие открывает вкладку, закрытую перед ней. IDE помнит 20 последних закрытых вкладок каждого проекта. Удалённый файл пропускается. Вкладки диффа и merge не возвращаются. Вкладки, закрытые вместе с проектом, тоже не возвращаются. Cmd+Shift+T работает и из терминала.

Cmd+E открывает Recent Files. Это список недавно открытых файлов. Выделен предыдущий файл, поэтому Enter возвращает к нему. Ввод текста фильтрует список.

Файлы из `node_modules` открываются только для чтения. На вкладке такого файла есть замок. Редактор не меняет такой файл.

### Find in Files и Replace in Files

Cmd+Shift+F открывает большое окно поиска, как в IDEA. Поиск идёт сразу при вводе, Enter не нужен.

- Вверху строка состояния. Пока поиск идёт, крутится спиннер и написано `Searching… 12 matches in 5 files`. Когда поиск закончен, спиннера нет: `3 matches in 2 files` или `No matches`. Окно показывает не больше 100 совпадений. Если их больше, строка пишет `100+ matches in 39+ files · limit reached`.
- Новый ввод сразу останавливает прошлый поиск. Поиск занимает не больше половины ядер и работает с низким приоритетом, поэтому IDE и другие программы не тормозят. На большом проекте (500 тысяч файлов) поиск без совпадений идёт около 15–20 секунд. Первые совпадения появляются сразу.
- Двоичные файлы (картинки, архивы, шрифты) и файлы больше 4 МБ не ищутся.
- Справа в поле поиска переключатели: `⏎` (многострочный запрос: Enter вставляет перевод строки), `Cc` (регистр), `W` (целые слова), `.*` (Regex). Крестик очищает запрос.
- Лупа со стрелкой открывает историю запросов. История своя у каждого проекта и сохраняется между запусками.
- File mask: галочка, поле и история. Пример маски: `*.ts, !*.test.ts`. Маска с `!` исключает файлы. Ввод в поле включает галочку.
- In Project ищет по всему проекту.
- Directory ищет в папке. Путь можно ввести, выбрать из истории (стрелка) или выбрать в системном окне (`…`). Кнопка справа включает и выключает поиск во вложенных папках (Recursive).
- Scope ищет только в открытых файлах (Open Files) или только в изменённых по git (Changed Files).
- В открытом файле с несохранёнными правками поиск читает текст из редактора, а не с диска. Поиск ничего не сохраняет. То же для Replace All и для окна Find (Cmd+Enter и ⟳).
- Справа в строке результата имя файла и номер строки. Серое имя значит, что файл исключён (`.harwex/ide.toml`) или лежит в библиотеке (`node_modules`).
- Стрелки вверх и вниз выбирают строку. Фокус остаётся в поле поиска. Enter или двойной клик открывает файл на этой строке и закрывает окно. Escape закрывает окно.
- Внизу превью выбранного файла. Превью можно править.
- Open in Find Window (Cmd+Enter) ищет без ограничения в 100 совпадений и показывает в окне Find до 5000 совпадений. Если совпадений больше, вкладка пишет «5000+ results, showing the first 5000 found». Галочка Open results in new tab открывает новую вкладку в окне Find.
- Из дерева проекта Cmd+Shift+F ищет в выбранной папке (Directory).

Cmd+Shift+R открывает то же окно с полем замены. У каждой строки видна замена: старый текст зачёркнут, новый стоит рядом. Replace меняет выбранное совпадение и выбирает следующее. Replace All сначала спрашивает: «Replace N occurrences in M files?». Числа берутся из полного поиска. У него нет ограничения: ни 100, ни 5000. Пока IDE считает, в окне написано «Counting…», и кнопка Replace выключена. Replace (или Enter) меняет все посчитанные совпадения и закрывает окно. Cancel (или Esc) ничего не меняет и возвращает к окну поиска. В Regex замена понимает группы: `$1`. Многострочное совпадение (`⏎` или `\n` в Regex) тоже заменяется целиком, группы работают через строки. В списке у такого совпадения видна только первая строка. Открытые файлы меняются через редактор, одно Cmd+Z откатывает всю замену в файле. Совпадение, текст которого изменился после поиска, IDE не трогает и пишет об этом предупреждение.

### Окно Find

Результаты Find Usages (Alt+F7) и Open in Find Window (Cmd+Enter в Find in Files) открываются в нижнем окне Find. Его кнопка — лупа в нижней группе левой полосы.

- Каждый поиск открывает новую вкладку. Старые вкладки остаются. Заголовок вкладки: что искали и где, например `greet in Project Files` или `"TRACKING" in Directory packages`. У вкладок Find Usages и Find in Files разные значки.
- Крестик закрывает вкладку. Вкладки можно перетаскивать мышью. После закрытия последней вкладки окно прячется.
- Дерево результатов. Find Usages сначала делит результаты по виду: Declarations, Imports, Writes, Reads. Дальше идут папки и файлы. Find in Files начинает сразу с папок. Цепочка папок с одной вложенной папкой показана одной строкой (`packages/calc/src`). У папок и файлов стоит счётчик: `2 results`.
- Строка результата: номер строки и сама строка. Найденное слово выделено жирным.
- Клик выбирает строку. Enter или двойной клик открывает файл на этом месте. Стрелки ходят по строкам, влево и вправо сворачивают и разворачивают папки.
- Delete (или Backspace) убирает строку из списка. На папке или файле убирает всё, что внутри. Файлы на диске не меняются.
- Кнопки слева сверху вниз: ⟳ ищет заново (Find Usages — то же место в коде, Find in Files — тот же запрос, область и маска); стрелки вверх и вниз выбирают предыдущий и следующий результат и разворачивают его папки; Expand All и Collapse All.
- Справа превью выбранного результата: имя файла, путь, код с подсветкой. Найденное слово выделено. Разделитель между деревом и превью можно двигать.
- Превью можно править, как в IDEA. Если файл открыт во вкладке, правка идёт в ту же вкладку, и Cmd+Z в превью её откатывает. Если файл не открыт, превью правит свою копию. IDE сохраняет файл через полсекунды после правки или когда превью теряет фокус.

## Переход по коду (JS/TS)

Работает в `.ts`, `.tsx`, `.js`, `.jsx`. Переход открывает и файлы внутри `node_modules`.

| Действие | Как |
|---|---|
| Go to Declaration | Cmd+B, Cmd+клик, правый клик → Go to Declaration |
| Go to Source Definition | правый клик → Go to Source Definition |
| Go to Type Definition | Cmd+Shift+B |
| Find Usages | Alt+F7 |
| Назад / вперёд | Cmd+[ / Cmd+] или Cmd+Alt+← / Cmd+Alt+→, боковые кнопки мыши 4 / 5 |
| Подсказка с типом | задержать мышь на имени 0.5 с |

- Боковые кнопки мыши «Назад» и «Вперёд» работают в любом месте окна, и в терминале тоже: терминал передаёт программе только три основные кнопки.
- **Declaration** открывает объявление. Для пакета из npm это обычно `.d.ts`.
- **Source Definition** открывает настоящий `.js` пакета, например `react/cjs/react.development.js`.
- Пакеты воркспейса `@hw/*` открываются сразу в исходниках `src/`.
- Если целей несколько, появится список. Выберите цель стрелками и Enter или мышью. Escape закрывает список.
- Первый переход в проекте занимает около секунды, потому что запускается tsserver. Следующие переходы занимают миллисекунды.
- TypeScript 7 работает через свой нативный сервер. Он быстрее tsserver. Статус-бар показывает, кто обслуживает файл: `TS 7.0.2 native`, `TS 5.9.3 tsserver` или `no TypeScript`.

## Переход по коду (Rust)

Работает в `.rs` так же, как в JS/TS: Cmd+B, Cmd+клик, Cmd+Shift+B, Alt+F7 и подсказка под мышью.

- Код обслуживает `rust-analyzer`. IDE ищет его в PATH, в `~/.cargo/bin` и через `rustup which rust-analyzer`.
- Если `rust-analyzer` не найден, справа внизу появится подсказка с командой установки.
- Один `rust-analyzer` обслуживает один Cargo workspace. Корень — самый верхний `Cargo.toml` с `[workspace]`. Если такого нет, корень — ближайший `Cargo.toml`.
- Переход открывает и исходники зависимостей из `~/.cargo/registry`. Он открывает и стандартную библиотеку (`rust-src`). Такие файлы открываются только для чтения.
- Go to Source Definition в Rust делает то же, что Go to Declaration.
- Первый запуск на большом проекте занимает секунды. Пока сервер грузит проект, статус-бар показывает `rust-analyzer: indexing…`. Запрос в это время ждёт загрузки и не отвечает «не найдено» сразу.
- Когда загрузка закончена, статус-бар показывает `rust-analyzer`.
- `rust-analyzer` складывает свою сборку в `target/rust-analyzer`. Поэтому он не блокирует ваш `cargo build`.
- Cmd+Alt+B — Go to Implementation: реализации трейта и его методов.
- Shift+F6 или правый клик → Rename Symbol… переименовывает символ во всём workspace. Сначала окно показывает, сколько мест и в каких файлах изменится. Кнопка Rename применяет правку. Открытые файлы сохраняются, правку в них можно отменить через Cmd+Z.

## Переход по коду (C/C++)

Работает в `.c`, `.h`, `.cpp`, `.cc`, `.cxx`, `.hpp` и других заголовках C++. Файл `.h` считается C++.

| Действие | Как |
|---|---|
| Go to Declaration | Cmd+B, Cmd+клик. На объявлении Cmd+B ведёт к определению и обратно, как в IDEA |
| Go to Implementation | Cmd+Alt+B: переопределения виртуального метода, наследники класса |
| Go to Type Definition | Cmd+Shift+B |
| Find Usages | Alt+F7 |
| Rename Symbol | Shift+F6, потом окно с предпросмотром |
| Подсказка с типом | задержать мышь на имени 0.5 с |

- Код обслуживает `clangd`. IDE не скачивает его. IDE ищет `clangd` так: `clangd` из `[cpp]` в `.harwex/ide.toml`, потом PATH, потом `xcrun --find clangd` (Xcode или Command Line Tools), потом Homebrew LLVM (`/opt/homebrew/opt/llvm/bin/clangd`).
- Если в `[cpp]` задан `clangd`, IDE берёт только его. Неверный путь даёт подсказку.
- Если `clangd` не найден, справа внизу появится подсказка: `xcode-select --install` или `brew install llvm`.
- Статус-бар показывает версию: `clangd 22.1.6`. Пока clangd строит индекс, там видно `clangd 22.1.6: indexing…`.
- Флаги компиляции clangd берёт из `compile_commands.json`. Корень проекта для clangd — ближайшая папка вверх, где есть `compile_commands.json`, `compile_flags.txt`, `build/compile_commands.json`, `cmake-build-*/compile_commands.json` (как в CLion) или `.clangd`. Для папки сборки IDE передаёт `--compile-commands-dir`.
- Получить `compile_commands.json`: для CMake — `cmake -B build -DCMAKE_EXPORT_COMPILE_COMMANDS=ON`, для make — `bear -- make`.
- Без базы clangd всё равно работает, но угадывает флаги. Тогда include и макросы могут найтись неверно. IDE один раз показывает подсказку `No compile_commands.json`.
- Несколько корней в одном проекте — несколько `clangd`. Каждый запускается, когда вы открываете первый файл его корня.
- Переход открывает и системные заголовки, и STL (`<vector>` из SDK). Такие файлы открываются только для чтения.
- Ошибки и предупреждения clangd видны в редакторе и в окне Problems.
- clangd хранит фоновый индекс в `.cache/clangd` рядом с `compile_commands.json`, то есть внутри проекта. Если git не игнорирует эту папку, IDE один раз подскажет добавить `.cache/` в `.gitignore`. `background_index = false` выключает индекс. Тогда Find Usages и переход к определению находят только то, что clangd видит в открытых файлах.

### Unreal Engine

- Проект Unreal — это папка с файлом `*.uproject`. Открытая папка может содержать несколько проектов, например `Sub/Game1` и `Sub/Game2`. Проект файла C/C++ — ближайшая папка над ним с `*.uproject`, но не выше открытой папки. IDE ищет проект только для открытого файла и запоминает ответ для его папки. Всё дерево IDE заранее не сканирует.
- У каждого проекта свой движок (свой `EngineAssociation`), своя цель, своя база `<проект>/.harwex/unreal/compile_commands.json` и свой clangd.
- Если в одной папке лежат два `.uproject`, IDE берёт файл из `uproject` в `[unreal]` (или в `[unreal.projects."<папка>"]`). Без этой строки IDE берёт файл с именем папки, иначе первый по имени. Один раз IDE показывает подсказку `Several .uproject files`: какой файл выбран, почему, и как выбрать другой.
- IDE заново определяет проекты после изменения `.harwex/ide.toml`, а также когда меняется `.uproject`, `Build.version` движка или список установленных движков (`Install.ini`, `LauncherInstalled.dat`).
- IDE находит движок так: `engine` из `[unreal.projects."<папка>"]` или `[unreal]` в `.harwex/ide.toml`, потом `EngineAssociation` из `.uproject` по списку установок Epic launcher (`LauncherInstalled.dat`), потом список сборок из исходников (`Install.ini`), потом движок вокруг проекта. Эти файлы IDE только читает.
- У Unreal нет `compile_commands.json`, пока его не напишет UnrealBuildTool. Пока базы нет, над редактором файла C/C++ проекта видна полоса с кнопкой `Generate compile_commands.json (UnrealBuildTool)`. Полоса относится к проекту активного файла и называет его: `Game2: no compile database for clangd yet (Unreal Engine 5.8.0).` `Not now` прячет полосу этого проекта до следующего открытия папки.
- Статус-бар для файла C/C++ проекта показывает имя проекта и версию движка: `clangd 22.1.6 · Game2 · UE 5.8`.
- Кнопка сначала показывает диалог: команду и все места, куда она пишет. Сама IDE никогда не запускает UnrealBuildTool. Команда: `<Engine>/Build/BatchFiles/Mac/Build.sh -mode=GenerateClangDatabase -project=<.uproject> -game -engine -OutputDir=<проект>/.harwex/unreal/ubt <Target> Mac Development` (на Linux `Linux/Build.sh` и `Linux`). Target — `<Имя>Editor` из `Source/*.Target.cs`, или `target` в `[unreal]`.
- UnrealBuildTool пишет полную базу в `.harwex/unreal/ubt` внутри проекта, не в папку движка. IDE оставляет в `.harwex/unreal/compile_commands.json` только файлы проекта и его плагинов. Эту базу читает clangd. Так фоновый индекс охватывает только проект, а файлы движка clangd индексирует, когда вы их открываете. `index_engine = true` оставляет в базе и движок. В `.harwex/unreal` IDE кладёт `.gitignore`, поэтому git эту папку не видит.
- UnrealBuildTool также пишет состояние сборки в `Intermediate/` проекта. Для движка, собранного из исходников, он пишет сгенерированные файлы ещё и в `Engine/Intermediate`. Диалог говорит об этом.
- Пока UnrealBuildTool работает, полоса показывает его последнюю строку вывода, а статус-бар — задачу со временем и `×`. `Stop` в полосе или `×` останавливает UnrealBuildTool вместе с дочерними процессами. После успеха перезапускается только clangd этого проекта, и он читает новую базу. Остальные проекты базу и clangd сохраняют.
- UnrealBuildTool блокирует движок. Поэтому для одного движка одновременно идёт только одна генерация. Вторую IDE не запускает и показывает сообщение `UnrealBuildTool is busy` с именем проекта, который сейчас генерирует. Проекты на разных движках можно генерировать одновременно.
- Для проекта Unreal clangd запускается с ограничениями для больших кодовых баз: не больше 4 потоков (`-j`), `--header-insertion=never`, `--limit-results=50`, фоновый индекс с низким приоритетом и PCH на диске. Такой же флаг в `[cpp] args` заменяет значение IDE.
- Заголовки движка (`Engine/Source`, `Engine/Plugins`) открываются только для чтения. Переход в них остаётся на clangd проекта.
- `UCLASS()`, `GENERATED_BODY()` и `UPROPERTY()` работают только после того, как Unreal Header Tool создал файлы `*.generated.h` в `Intermediate/`. Если такого файла нет, IDE один раз показывает подсказку `Build the project once so Unreal Header Tool generates the headers`.

## Переход по коду (C# и Unity)

Работает в `.cs`.

| Действие | Как |
|---|---|
| Go to Declaration | Cmd+B, Cmd+клик |
| Go to Implementation | Cmd+Alt+B: реализации интерфейса и переопределения метода |
| Go to Type Definition | Cmd+Shift+B |
| Find Usages | Alt+F7 |
| Rename Symbol | Shift+F6, потом окно с предпросмотром |
| Подсказка с типом | задержать мышь на имени 0.5 с |

- Код обслуживает языковой сервер Roslyn (`Microsoft.CodeAnalysis.LanguageServer`). Это тот же сервер, что работает в расширении C# для VS Code и в C# Dev Kit. Лицензия MIT.
- IDE не скачивает сервер. IDE ищет его так: `server` из `[csharp]` в `.harwex/ide.toml`, потом сервер из расширения C# для VS Code (`~/.vscode/extensions/ms-dotnettools.csharp-*`, также Cursor и Windsurf), потом dotnet-инструмент `roslyn-language-server`. Если в `[csharp]` задан `server`, IDE берёт только его.
- Серверу нужен .NET SDK (версия 10 или новее). IDE ищет `dotnet` так: `dotnet` из `[csharp]`, потом `DOTNET_ROOT`, потом PATH, потом `/usr/local/share/dotnet`, потом `~/.dotnet`.
- Если сервер или SDK не найдены, справа внизу появится подсказка. Установка: .NET SDK с https://dot.net, потом `dotnet tool install --global roslyn-language-server --prerelease`.
- Один сервер обслуживает одно решение. Корень — ближайшая папка вверх, где есть `.sln` или `.slnx`. Если решений в папке несколько, IDE берёт решение с именем папки, иначе первое по алфавиту. Если решения нет, корень — ближайшая папка с `.csproj`. Тогда сервер открывает все проекты этой папки.
- Пока сервер грузит решение, статус-бар показывает `Roslyn: loading solution…`. Пока сервер восстанавливает пакеты NuGet, там видно `Roslyn: restoring packages…`. Запрос в это время ждёт загрузки. Потом статус-бар показывает `Roslyn`.
- Переход в библиотеку (`List<T>`, `UnityEngine.dll`) открывает декомпилированный код. Вкладка называется `[decompiled] List.cs`. Такой файл открывается только для чтения. Из него тоже работают Cmd+B, Alt+F7 и подсказка.
- Декомпилированные файлы сервер пишет во временную папку (`$TMPDIR/harwex-ide-roslyn`), не в проект. Папка удаляется, когда сервер останавливается.
- Ошибки и предупреждения компилятора и анализаторов видны в редакторе и в окне Problems, например `csharp(CS0029)`. Скрытые подсказки сервера (`IDE0028` и похожие) IDE не показывает.

### Unity

- IDE узнаёт проект Unity по папкам `Assets/` и `ProjectSettings/`. Статус-бар тогда показывает `Roslyn (Unity)`.
- Файлы `.sln` и `.csproj` создаёт сам Unity. Если их нет, IDE покажет подсказку: в Unity откройте Edit › Preferences › External Tools, выберите Visual Studio или Visual Studio Code как External Script Editor и нажмите Regenerate project files.
- Переход в `MonoBehaviour` и другие типы Unity открывает декомпилированный `UnityEngine.dll`.
- Если проекты подключают анализаторы Unity (`Microsoft.Unity.Analyzers`), их предупреждения тоже видны.
- Файлы `.meta` IDE не трогает.

## Языковые серверы

- Сервер языка запускается, когда вы открываете первый файл этого языка. JS-проект не запускает `rust-analyzer`.
- Сервер останавливается сам после 10 минут простоя. Для остановки все его файлы должны быть закрыты.
- Упавший сервер перезапускается при следующем запросе. Открытые файлы, даже несохранённые, он получит заново.

### Настройки проекта: `.harwex/ide.toml`

Файл не обязателен. Без него действуют настройки по умолчанию. Файл лежит в корне проекта:

```toml
languages = ["ts", "rust"]      # каким языкам можно запускать сервер; без строки — всем
idle_timeout_secs = 600         # через сколько секунд простоя остановить сервер

[rust]
server = "/path/to/rust-analyzer"   # свой rust-analyzer; без строки IDE ищет сама
idle_timeout_secs = 300
check_on_save = false               # cargo check после сохранения; по умолчанию выключен
build_scripts = true                # запускать build.rs (нужно для OUT_DIR и cfg)
proc_macros = true                  # раскрывать процедурные макросы

[rust.init]                         # добавляется в initializationOptions rust-analyzer
cargo.features = "all"

[ts]
idle_timeout_secs = 600

[csharp]
server = "/path/to/Microsoft.CodeAnalysis.LanguageServer.dll"   # или его папка; без строки IDE ищет сама
dotnet = "/usr/local/share/dotnet/dotnet"                        # свой dotnet; без строки IDE ищет сама
idle_timeout_secs = 600

[cpp]
clangd = "/path/to/clangd"          # свой clangd; без строки IDE ищет сама
background_index = true             # фоновый индекс clangd; по умолчанию включён
args = ["--clang-tidy"]             # дополнительные аргументы clangd
idle_timeout_secs = 600

[unreal]                            # проекты с *.uproject
engine = "/path/to/UE_5.4"          # папка движка; без строки IDE ищет через Epic launcher
target = "MyGameEditor"             # цель UnrealBuildTool; по умолчанию <Имя>Editor
index_engine = false                # оставить движок в базе clangd (индекс станет огромным)
uproject = "Game.uproject"          # какой .uproject взять, если в папке их несколько

[unreal.projects."Sub/Game2"]       # один проект: его папка относительно открытой
engine = "/path/to/UE_5.8"          # любые ключи из [unreal]; остальные берутся из [unreal]
target = "Game2Editor"

[diagnostics]
ts = true                           # ошибки TypeScript от TS-сервера

[diagnostics.oxlint]                # без секции oxlint работает там, где он настроен
enabled = true
type_aware = true                   # правила с типами; по умолчанию включены, если есть oxlint-tsgolint
type_check = false                  # ошибки TypeScript от oxlint; сейчас не поддерживается

[diagnostics.eslint]                # без секции ESLint работает там, где есть его конфиг
enabled = true

[format.oxfmt]                      # то же, что Settings › Editor › oxfmt
on_save = false                     # форматировать oxfmt при Cmd+S и Save All; по умолчанию выключено
extensions = ["ts", "tsx", "js"]    # какие файлы; по умолчанию js, jsx, ts, tsx, mjs, cjs, mts, cts, json, jsonc, css, md
timeout_secs = 10                   # дольше — файл сохраняется без форматирования

[memory]
interval_secs = 15                  # как часто обновлять память в статус-баре; не меньше 1

[project]
excluded = ["dist", "build/out"]    # папки, которые не ищут Search Everywhere и Find in Files
```

- В `languages` есть `ts`, `rust`, `cpp` (C и C++) и `csharp` (C# и Unity).
- `languages = ["ts"]` выключает Rust. Тогда `.rs` открывается как обычный текст. Cmd+B в нём показывает подсказку.
- Если задан `server`, IDE берёт только его. Неверный путь даёт подсказку. Другой `rust-analyzer` IDE тогда не ищет.
- Ошибка в файле не ломает IDE. IDE покажет предупреждение и возьмёт настройки по умолчанию.
- IDE перечитывает файл, когда вы его сохраняете.

## Ошибки и предупреждения

IDE подчёркивает проблемы в открытых файлах `.ts`, `.tsx`, `.js` и `.jsx`. В файлах C и C++ проблемы приходят от `clangd` (раздел «Переход по коду (C/C++)»). В файлах C# проблемы приходят от сервера Roslyn (раздел «Переход по коду (C# и Unity)»).

- Красная волна — ошибка. Оранжевая волна — предупреждение. Серая волна — слабое предупреждение. Серые точки — неиспользуемый код.
- Ошибки TypeScript приходят от TS-сервера. Это тот же сервер, что работает для перехода по коду. Отдельный процесс проверки типов не запускается.
- Ошибки линтера приходят от oxlint. oxlint работает, если у пакета есть `.oxlintrc.json`, `oxlint.config.ts` или oxlint в `package.json`. Ближайший конфиг главный.
- IDE запускает один `oxlint --lsp` на весь репозиторий. Корень — самая верхняя папка с конфигом и установленным oxlint. Сервер останавливается после простоя, как языковые серверы.
- Если установлен `oxlint-tsgolint`, работают правила с типами (например `no-floating-promises`).
- Если oxlint с правилами с типами не ответил за 30 секунд, IDE убивает его вместе с tsgolint и проверяет файл без правил с типами. Всплывает одно уведомление `oxlint type-aware rules turned off`. Правила с типами остаются выключенными для этого корня, пока не изменится `.harwex/ide.toml` или проект не откроется заново. Обычно так зависает tsgolint, который не может стартовать, пока macOS (`syspolicyd`) проверяет новые программы.
- oxlint 1.77 падает на файле, где правило из `jsPlugins` нашло проблему (это ошибка самого oxlint). Тогда IDE ставит этот файл на карантин. Вместо проблем файла в Problems видна одна тихая строка `oxlint crashed on this file ...` с текстом паники. Уведомления нет. Остальные файлы проверяет новый сервер, он стартует при следующей проверке. Файл на карантине IDE не отправляет в oxlint, даже когда вы его правите. Карантин снимается, когда файл или конфиг oxlint меняется на диске (например, после сохранения), когда меняется `.harwex/ide.toml` или проект открывается заново.
- Если oxlint падает при старте 3 раза подряд или падает на 3 разных файлах подряд за 20 секунд, IDE останавливает его. Всплывает одно уведомление `Diagnostics failed`. oxlint остаётся выключенным, пока не изменится `.harwex/ide.toml` или проект не откроется заново.
- Языковой сервер oxlint 1.77 не умеет проверять типы. Поэтому ошибки TypeScript всегда приходят от TS-сервера.
- ESLint работает, если рядом с файлом или выше есть `eslint.config.*` и в `node_modules` установлен `eslint`. Ближайший конфиг главный. Старые `.eslintrc*` работают только с ESLint 8 и 9.
- IDE запускает один процесс ESLint на весь репозиторий. Конфиг каждого пакета загружается один раз и дальше живёт в этом процессе. Ошибки TypeScript по-прежнему приходят от TS-сервера.
- Первая проверка пакета медленнее: ESLint загружает конфиг, а правила с типами (`projectService` из typescript-eslint) строят программу TypeScript. В это время в статус-баре видно `ESLint: loading <пакет>`.
- Когда закрыт последний файл, ESLint выбрасывает загруженные проекты TypeScript. Процесс останавливается после простоя, как языковые серверы.

### ESLint или oxlint в большом монорепозитории

Замеры на сгенерированном монорепозитории из 200 пакетов (`docs/timings.md`):

| | Первая проверка | Повторная проверка файла | Память |
|---|---|---|---|
| ESLint без типов | 0.36 с | 5 мс | 270-320 МБ |
| ESLint с типами | 0.47 с | 11 мс | 350-450 МБ |
| oxlint без типов / с типами | 0.05 с | 1 / 11 мс | 24 МБ |

- Если в проекте настроены оба, IDE запускает оба. Это нормальная схема: oxlint ловит основное быстро, ESLint проверяет правила, которых нет в oxlint.
- Если правила совпадают, оставьте один oxlint: `[diagnostics.eslint] enabled = false`. Он в 7 раз быстрее на холодном старте и занимает в 10 раз меньше памяти.
- Правила с типами в ESLint держат свою программу TypeScript рядом с TS-сервером. На каждом открытом пакете память растёт. Если памяти мало, перенесите правила с типами в oxlint (`oxlint-tsgolint`) или выключите их в IDE. Процесс ESLint в IDE получает `HARWEX_IDE=1`, поэтому конфиг может написать `...(process.env.HARWEX_IDE ? [] : tseslint.configs.recommendedTypeChecked)` и включать `projectService` только без этой переменной.
- Правила по всему графу импортов (`import-x/no-cycle`) в IDE стоят дёшево: граф кешируется в процессе ESLint. На цикле через 200 файлов первая проверка дольше на 0.06 с, повторная на 1 мс.
- IDE проверяет файл через 0.3 с после последней правки и после сохранения. Несохранённый текст тоже проверяется.
- Пока идёт проверка, старые подчёркивания остаются. Они сдвигаются вместе с текстом.

| Действие | Как |
|---|---|
| Следующая проблема | F2 |
| Предыдущая проблема | Shift+F2 |
| Текст ошибки | навести мышь на подчёркивание |
| Список проблем файла | окно Problems (значок `!` внизу левой полосы) |

- F2 сначала ходит по ошибкам. Если ошибок нет, F2 ходит по предупреждениям.
- Справа вверху редактора видно число ошибок и предупреждений. Клик по нему ведёт к следующей проблеме. Зелёная галочка значит, что проблем нет.
- Подсказка под мышью показывает текст, источник и код: `ts(2322)`, `oxlint(no-debugger)` или `eslint(no-debugger)`. Ниже идёт обычная подсказка с типом.
- Метки на полосе прокрутки показывают, где в файле проблемы.
- Окно Problems на вкладке Current File группирует проблемы по важности. Клик по строке ведёт к проблеме.
- В `.harwex/ide.toml` можно выключить источник: `[diagnostics] ts = false`, `[diagnostics.oxlint] enabled = false` или `[diagnostics.eslint] enabled = false`.

## Редактор

| Действие | Клавиши |
|---|---|
| Отменить / повторить | Cmd+Z / Cmd+Shift+Z |
| Дублировать строку | Cmd+D |
| Удалить строку | Cmd+Backspace |
| Закомментировать | Cmd+/ |
| Сдвинуть отступ | Tab / Shift+Tab |
| По словам | Alt+← / Alt+→ |
| Начало / конец строки | Cmd+← / Cmd+→ |
| Начало / конец файла | Cmd+↑ / Cmd+↓ |

- Cmd+C и Cmd+X без выделения копируют и вырезают всю строку.
- Двойной клик выделяет слово. Третий клик выделяет строку. Следующие клики той же серии оставляют строку выделенной.
- После третьего клика каретка стоит там, куда пришёлся клик. Каждый следующий клик серии переносит каретку в новое место. Строка остаётся выделенной.
- Cmd+C и Cmd+X копируют такую строку вместе с переводом строки. Ввод текста, вставка, Backspace и Delete заменяют всю строку.
- Стрелки, Home и End снимают выделение. Каретка движется от того места, где она нарисована.
- Shift со стрелкой выделяет от каретки. Движение вправо или вниз держит начало строки. Движение влево или вверх держит конец строки.
- Cmd+B и Alt+F7 работают от нарисованной каретки.
- Клики идут в одну серию, если они в одном месте и пауза между ними не дольше системного интервала двойного клика.
- Протяжка после двойного клика выделяет по словам. Протяжка после третьего клика выделяет по строкам.
- Подсветка есть для TS, TSX, JS, JSX, JSON, Rust, CSS, Markdown, C, C++, C#, Java, Kotlin и GLSL.
- C: `.c`. C++: `.h`, `.cc`, `.cpp`, `.cxx`, `.c++`, `.hh`, `.hpp`, `.hxx`, `.h++`, `.inl`, `.ipp`, `.tpp`. Файл `.h` считается C++. C#: `.cs`, `.csx` (скрипты Unity тоже). Java: `.java`. Kotlin: `.kt`, `.kts`. GLSL: `.glsl`, `.vert`, `.frag`, `.geom`, `.comp`, `.tesc`, `.tese`. Файлы Objective-C (`.m`, `.mm`) открываются как обычный текст.
- Для C, C++, C#, Java, Kotlin и GLSL есть только подсветка. Перехода по коду, поиска использований и проверки ошибок для них нет. Cmd+/ ставит `//`.
- Имя из заглавных букв перед скобками подсвечено как макрос: `UCLASS(...)`, `UPROPERTY(...)`, `GENERATED_BODY()`, `CHECK(x)`. В заголовке Unreal класс с `UCLASS(...)` и `MYGAME_API` разбирается неточно: внутри такого класса часть имён (например, `TArray<FString>`) остаётся без цвета. Код после класса подсвечен как обычно.
- В JSON ключи фиолетовые, строковые значения зелёные, числа голубые, `true`, `false` и `null` в цвете ключевых слов, как в IDEA. Так же выглядят `.jsonc` и `tsconfig.json` с комментариями.
- `Код в обратных кавычках` в Markdown и в обычном тексте (`.txt` и другие файлы без подсветки) показан зелёным на светлой подложке. Работают и двойные обратные кавычки: ``a ` b``. Одинокая обратная кавычка и обратная кавычка после `\` остаются обычным текстом. Код ищется в пределах одной строки: если кавычки на разных строках, подложки нет. Внутри блока ```` ``` ```` кавычки не размечаются.
- Длинные строки прокручиваются вбок: свайп двумя пальцами влево и вправо или Shift+колесо мыши. Номера строк стоят на месте.
- Внизу текста есть горизонтальная полоса прокрутки, если какая-то строка файла шире окна. Её ползунок можно тянуть. Клик по полосе переносит ползунок туда.
- Каретка, которая уходит за край окна, тянет текст за собой: End на длинной строке показывает её конец, Home возвращает к началу.
- После пункта контекстного меню клавиатура остаётся в редакторе. Cmd+Z сразу отменяет действие пункта.
- Каретка в идентификаторе подсвечивает другие вхождения этого идентификатора в файле мягким фоном. Выделение ровно одного идентификатора делает то же самое. Справа на полосе прокрутки появляется серая метка у каждой строки с вхождением.
- Вхождение ищется целым словом и с учётом регистра. Само выделенное слово и слово под кареткой не подсвечены. Если идентификатор встречается в файле один раз, подсветки нет.
- Ключевые слова, числа, комментарии, строки и выделение не из одного идентификатора ничего не подсвечивают. При нескольких каретках подсветки тоже нет.
- Подсвечено не больше 2000 вхождений. В большом файле поиск идёт в фоне, подсветка появляется чуть позже.
- Метки ошибок и предупреждений на полосе прокрутки рисуются поверх меток вхождений.
- Значок раскладки macOS и окна ввода (японский, китайский) появляются у каретки. Мёртвые клавиши (Option+E, потом E даёт «é») и набор иероглифов работают. Пока набор не закончен, текст набора виден у каретки с подчёркиванием.

Пока нет: автозакрытия скобок и фолдинга. Эмодзи и CJK сдвигают колонки. В терминале набор через IME не работает.

### Форматирование: oxfmt

IDE форматирует файлы через oxfmt (форматтер oxc) из самого проекта. IDE ищет `node_modules/oxfmt` от папки файла вверх. Глобальный oxfmt IDE не берёт и ничего не скачивает.

- Cmd+Alt+L (Reformat File, как Reformat Code в IDEA) форматирует открытый файл. Файл не сохраняется. Клавиша работает и при выключенном форматировании при сохранении.
- Форматирование при сохранении включается в Settings (Cmd+, или шестерёнка) › Editor › Formatting: oxfmt › «Run oxfmt on save». По умолчанию оно выключено. Там же список типов файлов через запятую и найденный oxfmt с версией или «not found». OK пишет `[format.oxfmt]` в `.harwex/ide.toml` проекта, у каждого проекта своя настройка.
- Форматируют только явные сохранения: Cmd+S, Save All (Cmd+Alt+S) и «Save» в вопросе при закрытии вкладки или проекта. Сохранения, которые IDE делает сама (переименование, Replace in Files, сохранение перед коммитом), файл не форматируют. Файл без изменений Cmd+S не форматирует, для него есть Cmd+Alt+L.
- oxfmt получает текст из редактора, а не с диска, и берёт ближайший `.oxfmtrc.json` или `.oxfmtrc.jsonc` над файлом. Форматирование идёт в фоне, в статус-баре видна задача `oxfmt <файл>` с кнопкой отмены.
- Результат ложится одной правкой: одно Cmd+Z возвращает текст до форматирования. Меняются только изменённые строки. Каретка и прокрутка остаются на своём тексте.
- Если oxfmt не справился (синтаксическая ошибка, oxfmt не установлен, дольше 10 секунд), файл сохраняется как есть. В статус-баре одна строка с причиной, например `oxfmt could not parse the file. Saved unformatted.`. Окон и всплывающих уведомлений нет, текст ошибки oxfmt лежит в окне Notifications. Про отсутствие oxfmt при сохранении IDE говорит один раз за сессию проекта.
- Если вы печатали, пока oxfmt работал, результат не применяется: текст уже другой.

### Подсказки в package.json

В `package.json` IDE подсказывает пакеты и версии из реестра npm, как IDEA. Подсказки работают в разделах `dependencies`, `devDependencies`, `peerDependencies` и `optionalDependencies`.

- Набираете имя пакета в ключе (`"rea`) — через 150 мс IDE ищет пакеты в реестре. Сначала стоит точное имя, потом имена, которые начинаются с набранного (короткие выше), потом остальные. Справа видна последняя версия.
- Набираете версию в значении (`"lodash": "^4`) — список показывает версии этого пакета. Сверху стоят dist-теги (`latest`, `next`): у каждого три варианта, `^4.17.21`, `~4.17.21` и `4.17.21`, тег написан справа. Ниже идут все версии, новые первыми. Если вы уже набрали `^` или `~`, все варианты идут с ним.
- Пре-релизы (`5.0.0-rc.1`) видны только у dist-тега или когда в набранном тексте есть `-`.
- Ctrl+Space открывает подсказки сам, без набора текста.
- Стрелки вверх и вниз, PageUp и PageDown выбирают строку. Enter или Tab подставляют её, клик мышью тоже. Esc закрывает список. Пока список загружается, Enter работает как обычно.
- Подстановка заменяет всю строку в кавычках. Если закрывающей кавычки нет, IDE её добавит. Каретка встаёт после кавычки.
- Версии `workspace:`, `file:`, `npm:`, git-ссылки и пути подсказок не получают.
- Реестр берётся из `.npmrc`: ближайший файл от папки `package.json` вверх до корня проекта, затем `~/.npmrc`. Поддерживаются `registry=`, `@scope:registry=` и `//хост/путь/:_authToken=` (в том числе `${ПЕРЕМЕННАЯ}`). Без настройки IDE ходит на `registry.npmjs.org`.
- Запросы идут в фоне через системный `curl`, не дольше 8 секунд. Если реестр не ответил, в списке видна причина, например `npm registry: not found`.
- Ответы хранятся в памяти, а версии пакетов ещё и на диске: `.harwex/cache/npm/` в проекте. Рядом лежит `.gitignore`, поэтому git этих файлов не видит. Свежий кеш (до часа) IDE берёт без запроса. Если реестр недоступен, IDE берёт и старый кеш.

### Перенос строк (Soft-Wrap)

- Markdown, `.txt` и текстовые файлы без расширения (LICENSE, заметки) открываются с переносом. Длинная строка разбивается на экранные строки по ширине редактора. Код не переносится.
- Перенос идёт по пробелам. Слово длиннее экранной строки рвётся посередине.
- Продолжение строки сдвинуто на её отступ, если отступ не больше половины ширины.
- Номер строки стоит только на первой экранной строке. Полоски git тянутся на все экранные строки.
- Стрелки вверх и вниз двигают каретку по экранным строкам. Home и End сначала идут к началу и концу экранной строки, второе нажатие — к началу и концу всей строки. Cmd+← и Cmd+→ работают так же.
- End на перенесённой экранной строке ставит каретку в её конец, после последнего символа. Каретка рисуется в конце этой строки, а не в начале следующей. Набранный текст встаёт после последнего символа строки.
- Клик справа от конца экранной строки ставит каретку туда же. Стрелки вверх и вниз из конца строки попадают в конец соседних строк.
- Если прийти на границу двух экранных строк стрелкой вправо, каретка рисуется в начале нижней строки.
- Пункт «Soft-Wrap» в контекстном меню редактора включает и выключает перенос для этой вкладки. Пункт есть только у Markdown и текстовых файлов.
- При изменении ширины окна строки переносятся заново. Верхняя строка на экране остаётся на месте.
- Горизонтальной прокрутки при переносе нет.
- В большом файле перенос сначала считается для видимых строк. Остальные досчитываются за несколько кадров, полоса прокрутки при этом немного уточняется.

### Предпросмотр Markdown

- В правом верхнем углу вкладки `.md` есть три кнопки: Editor (только текст), Split (текст и предпросмотр рядом) и Preview (только предпросмотр). Режим свой у каждой вкладки. Новая вкладка открывается в режиме Editor.
- Предпросмотр показывает заголовки, абзацы, жирный, курсив, зачёркнутый текст, `код в строке`, списки (с номерами и галочками задач), цитаты, блоки кода, таблицы, горизонтальные линии, ссылки и картинки.
- Ссылка `https://…` открывается в браузере. Ссылка на файл (`docs/a.md`) открывает файл в IDE. Ссылка `#заголовок` прокручивает предпросмотр к заголовку.
- Картинки с относительным путём берутся рядом с файлом `.md`, путь с `/` в начале — от корня проекта. Картинки из интернета не грузятся: вместо них виден их alt-текст в квадратных скобках.
- В режиме Split обе половины прокручиваются вместе, примерно по блокам: прокрутка текста двигает предпросмотр, прокрутка предпросмотра двигает текст. Границу между половинами можно тянуть мышью.
- Предпросмотр обновляется при каждой правке. Файл больше 256 КБ разбирается в фоне.
- Выделять и копировать текст в предпросмотре нельзя.

### Картинки

- `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.bmp`, `.ico` и `.svg` открываются как картинка, а не как текст. Картинка открывается целиком в окне, маленькая — в натуральную величину.
- Cmd+= и Cmd+- меняют масштаб, Cmd+колесо и жест щипка масштабируют вокруг курсора. Кнопки «+» и «−», «1:1» (натуральная величина) и «Fit» (вписать в окно) стоят над картинкой.
- Увеличенную картинку можно двигать мышью или колесом.
- Прозрачные места показаны шахматной клеткой.
- Справа над картинкой: размер в пикселях, формат, размер файла и масштаб, например «64×48 PNG (1.8 KB) 100%».
- У `.svg` есть кнопка Text: она открывает файл как текст. Пока текстовая вкладка открыта, файл открывается в ней. SVG рисуется без текста (шрифты не грузятся).
- Если файл изменился на диске, картинка перечитывается.
- Очень большая картинка уменьшается до 4096 точек по длинной стороне. Анимированный GIF показывает первый кадр.
- Вкладки картинок не восстанавливаются после перезапуска и не возвращаются по Cmd+Shift+T.

### Несколько кареток

| Действие | Клавиши |
|---|---|
| Добавить или убрать каретку | Alt+клик |
| Выделить колонку | Alt+Shift+перетаскивание или перетаскивание средней кнопкой |
| Выделить следующее вхождение | Ctrl+G |
| Убрать последнее вхождение | Ctrl+Shift+G |
| Выделить все вхождения | Ctrl+Cmd+G |
| Каретка выше / ниже | Alt дважды, держать, затем ↑ / ↓ |
| Оставить одну каретку | Esc |

- Первое Ctrl+G выделяет слово под кареткой. Следующие нажатия добавляют его следующие вхождения. Поиск идёт до конца файла, потом с начала.
- Слово ищется целиком и с учётом регистра. Выделенный текст ищется с учётом регистра.
- Ctrl+Cmd+G при открытой панели поиска выделяет все совпадения запроса. Исключённые через Exclude не выделяются. Панель закрывается, клавиатура переходит в редактор.
- Ctrl+Cmd+G без панели выделяет все вхождения слова под кареткой или выделенного текста.
- Ввод, Backspace, Delete, Enter, Tab, Cmd+D, Cmd+/ и стрелки работают у каждой каретки.
- Одно Cmd+Z отменяет правку сразу у всех кареток. Каретки возвращаются на свои места.
- Cmd+C копирует выделения всех кареток. Между ними встаёт перенос строки.
- Cmd+V вставляет по одной строке в каждую каретку, если строк в буфере столько же, сколько кареток. Иначе каждая каретка получает весь текст.
- Строки с каретками подсвечены. Метки на полосе прокрутки показывают, где стоят каретки.
- Esc сначала убирает лишние каретки. Остаётся главная, последняя добавленная.

### Поиск и замена в файле

| Действие | Клавиши |
|---|---|
| Найти в файле | Cmd+F |
| Заменить в файле | Cmd+R |
| Следующее / предыдущее совпадение | Enter / Shift+Enter или ↓ / ↑ в поле, Cmd+G / Shift+Cmd+G везде |
| Закрыть панель | Esc |

- Панель поиска открывается над текстом файла.
- Выделение в одну строку становится запросом.
- Выделение в несколько строк включает режим In Selection. Тогда поиск идёт только внутри этого выделения.
- Совпадения подсвечиваются сразу при вводе. Счётчик показывает номер текущего совпадения и их число.
- Метки на полосе прокрутки показывают, где есть совпадения.
- Кнопки в поле: `⏎` разрешает перенос строки в запросе, `Cc` учитывает регистр, `W` ищет целые слова, `.*` включает регулярные выражения.
- Воронка ограничивает поиск: только комментарии, только строки или всё, кроме них.
- Меню `⋮` содержит Select All Occurrences и In Selection. Select All Occurrences ставит каретку на каждое совпадение.
- Cmd+G работает и при закрытой панели. Он ищет последний запрос.
- Стрелки ↓ и ↑ работают в поле поиска и в поле замены. После последнего совпадения ↓ переходит к первому. Фокус остаётся в поле, каретка редактора встаёт только на выбранное совпадение.
- В многострочном режиме (`⏎`) стрелки двигают каретку внутри запроса. Enter там вставляет перевод строки. К совпадениям ведут Cmd+G, Shift+Cmd+G и кнопки со стрелками. В многострочной замене (`⏎` в поле замены) стрелки тоже двигают каретку внутри замены.
- Esc закрывает панель. Клавиатура возвращается в редактор.

Строка замены открывается через Cmd+R или стрелку `>` слева.

- Replace заменяет текущее совпадение и переходит к следующему.
- Replace All заменяет все совпадения сразу. Одно Cmd+Z в редакторе отменяет всю замену.
- Exclude пропускает текущее совпадение. Replace и Replace All его не трогают. Счётчик его не считает.
- `AA` сохраняет регистр: `foo` → `bar` превращает `Foo` в `Bar`, а `FOO` в `BAR`.
- В режиме `.*` замена понимает группы `$1`, `$2` и `${name}`, а также `\n`, `\t` и `\\`.
- Лупа слева от поля замены открывает прошлые замены этой сессии.
- В файлах только для чтения поиск работает, а замены нет.
- Больше 100000 совпадений счётчик не считает. Он показывает `100000+`. Replace All всё равно заменяет все.

## Git

### Изменения и коммит

1. Откройте окно Commit. Cmd+K открывает его и ставит курсор в поле сообщения.
2. Отметьте галочками файлы для коммита. Галочка на папке отмечает всё внутри неё.
3. Напишите сообщение.
4. Нажмите Commit или Commit and Push. Cmd+Enter в поле сообщения тоже делает коммит.

- Список разбит на группы, как staging area в IDEA: Staged (изменения в индексе), Unstaged (изменения, которых нет в индексе) и Unversioned Files (файлы вне git).
- Файл, застейдженный частично, виден в обеих группах: Staged и Unstaged.
- Файлы в Staged отмечены сразу. Файлы в Unstaged и Unversioned Files не отмечены.
- У папки и группы рядом с именем стоит число файлов. Галочка папки с частью отмеченных файлов показывает черту.
- Перетащите файлы или папки из Unstaged или Unversioned Files на Staged, и они застейджатся (`git add`). Перетащите из Staged на Unstaged, и они уйдут из индекса. Можно тащить сразу несколько выделенных файлов. Группа под курсором подсвечивается, рядом с курсором видно число файлов. Сброс на ту же группу ничего не делает.
- Только что застейдженные файлы становятся отмеченными.
- Коммит включает только отмеченные файлы. Другие застейдженные изменения остаются застейдженными.
- Частично застейдженный файл: отмеченная строка в Staged коммитит только застейдженную часть. Отмеченная строка в Unstaged коммитит весь файл с диска. Подсказка над строкой говорит, что именно попадёт в коммит.
- Перед коммитом IDE сохраняет все изменённые вкладки.
- Галочка Amend дописывает изменения в последний коммит и подставляет его сообщение.
- Разделитель над полем сообщения двигается мышью. Поле не становится ниже трёх строк. В низком окне сначала сжимается список файлов. Если места не хватает и тогда, окно Commit прокручивается целиком.
- Хуки коммита выполняются. Если хук упал, коммита нет, а текст ошибки появится в уведомлении.
- Над списком стоят кнопки-иконки: Refresh, Rollback, Show Diff, Expand All, Collapse All.
- После Stage, Unstage, Commit, Rollback и Delete IDE перечитывает статус только этих файлов. Поэтому окно Commit обновляется почти сразу и в большом репозитории. Сохранённые и изменённые на диске файлы тоже перечитываются по одному.
- Весь статус IDE перечитывает при открытии проекта, по кнопке Refresh и после Unstash. В большом репозитории это долго: на mono (500 тысяч файлов) около 12 с, почти всё время git ищет неотслеживаемые файлы.
- После checkout, pull, merge, rebase, stash, reset и fetch IDE перечитывает только нужные файлы. Это файлы, которые отличаются между старым и новым HEAD, файлы в индексе и файлы, которые уже видны в окне Commit. То же происходит, когда индекс или HEAD меняются снаружи, например после `git add`, `git commit` или `git checkout` в терминале. На mono это занимает около 1 с вместо 12 с. Файлы, которые вы правите на диске, IDE видит через слежение за файлами. Если таких файлов больше 400, IDE перечитывает весь статус. Новое перечитывание останавливает прежнее, если оно ещё идёт.
- Двойной клик по файлу открывает дифф. Enter открывает дифф выделенного файла.
- Если активна вкладка диффа рабочей копии, один клик по другому файлу показывает его дифф в той же вкладке. Новая вкладка не открывается. Стрелки ↑ и ↓ ходят по файлам и тоже переключают дифф. Клик по галочке только отмечает файл. Клик по папке дифф не меняет. Если активна обычная вкладка редактора, один клик только выделяет файл.
- Правый клик по файлу: Show Diff, Jump to Source, Rollback…, Stage, Unstage, Delete…. Rollback и Delete сначала спрашивают.

### Дифф

- Дифф показывает две версии рядом, и они прокручиваются вместе.
- Изменённые слова подсвечены.
- F7 переходит к следующему изменению, Shift+F7 — к предыдущему.
- Jump to Source открывает файл в редакторе, как в IDEA. Это F4, кнопка с карандашом рядом с Prev и Next и пункт в меню правого клика. Cmd+↓ здесь не работает: в диффе он ставит каретку в конец файла.
- Строка для перехода берётся так. После F7 или Shift+F7 это начало текущего изменения. Иначе это строка с кареткой. Если каретки нет, это строка на трети высоты диффа.
- Строка с правой стороны диффа рабочей копии открывается как есть, вместе с колонкой каретки. Строка с левой стороны или из коммита сначала проходит через дифф, а потом через разницу между коммитом и файлом сейчас. Если строку удалили, переход встаёт на следующую строку. Несохранённые правки во вкладке файла тоже учитываются.
- Если файла на диске больше нет, Jump to Source выключен, а подсказка у кнопки пишет «File no longer exists».
- Двойной клик в диффе выделяет слово и никуда не переходит.
- Правую сторону диффа рабочей копии можно редактировать, как в IDEA. Это дифф HEAD против рабочей копии (из окна Commit, из полоски на полях) и Compare with Local. Левая сторона и дифф двух коммитов только для чтения: у их заголовка стоит замок.
- Правая сторона — это тот же документ, что во вкладке редактора этого файла. У них общий текст и общая история отмены. Правка в диффе сразу видна во вкладке, и вкладка получает точку несохранённых изменений. Cmd+Z в диффе отменяет и правку из вкладки, и наоборот.
- В правой стороне работают ввод, Enter с отступом, Tab и Shift+Tab, Backspace и Delete (с Alt — по словам, Cmd+Backspace удаляет строку), Cmd+Z и Shift+Cmd+Z, Cmd+D, Cmd+/, Cmd+X и Cmd+V. В меню правого клика есть Cut и Paste.
- Cmd+S сохраняет файл. Если вкладки этого файла нет, дифф сохраняет файл сам через полсекунды после последней правки, при уходе фокуса и при закрытии диффа. Если потом открыть вкладку файла, несохранённые правки переходят в неё.
- Изменения пересчитываются на ходу: блоки, полоски между сторонами и счётчик различий следуют за текстом. Если файл поменялся на диске, правая сторона показывает новый текст, как вкладка редактора.
- Текст можно выделять и копировать на обеих сторонах.
- Выделение всегда на одной стороне. Клик ставит каретку, перетаскивание выделяет текст. Двойной клик выделяет слово, тройной — строку. Shift+клик расширяет выделение от каретки.
- Если при выделении увести мышь за верхний или нижний край, дифф прокручивается, и обе стороны едут вместе.
- Стрелки двигают каретку, Shift+стрелки выделяют. Работают Home, End, PageUp, PageDown, Alt+стрелки (по словам) и Cmd+стрелки (к краю строки или файла). Пока каретки нет, стрелки прокручивают дифф.
- Cmd+A выделяет всю сторону с кареткой. Cmd+C копирует выделенный текст без номеров строк, с переводами строк как в файле.
- Правый клик открывает меню с пунктами Jump to Source, Copy и Select All (на правой стороне ещё Cut и Paste). Правый клик внутри выделения его сохраняет, правый клик снаружи ставит туда каретку.
- Дифф картинки (`.png`, `.jpg`, `.gif`, `.webp`, `.bmp`, `.ico`) показывает обе версии рядом, с размером в пикселях и размером файла под каждой. Масштаб и сдвиг общие для обеих сторон. Новый или удалённый файл показан одной стороной с пометкой (added) или (deleted). SVG сравнивается как текст.

### Полоски на полях редактора

- Слева от строк видны полоски изменений относительно HEAD: добавлено, изменено, удалено.
- Клик по полоске показывает старый текст и кнопки Rollback, Show Diff и Copy.
- Cmd+Z отменяет Rollback.
- Правый клик → Git → Rollback Lines откатывает выделенные строки.
- Правый клик → Git → Annotate with Git Blame показывает дату и автора каждой строки. Клик по аннотации показывает коммит.
- Правый клик → Git → Show History показывает историю файла в окне Git.

### Окно Git: вкладки

В заголовке окна Git стоят вкладки:

- **Log: HEAD** — главная вкладка с историей. После двоеточия видно, по какой ветке отфильтрован лог. Главную вкладку закрыть нельзя.
- **+** открывает ещё одну вкладку Log с чистыми фильтрами. У каждой вкладки Log свои фильтры и своё дерево веток. Дополнительные вкладки закрываются крестиком.
- **Console** показывает git-команды, которые запустила IDE (checkout, commit, fetch, push и другие), с их выводом. Ошибки показаны красным. Галочка Show read commands показывает и команды чтения (diff, blame). Console можно закрыть. Следующая git-команда вернёт вкладку, но не переключит на неё.
- **History: файл** открывается из Git → Show History. Повторный Show History того же файла переключает на уже открытую вкладку.
- **Compare with ветка** и **Diff with ветка** открываются из меню ветки (см. ниже).
- **⌄** появляется, когда вкладки не помещаются по ширине. Он показывает список всех вкладок. Клик по строке переключает вкладку.

### Окно Git: дерево веток

Слева от лога во вкладке Log стоит дерево веток. Его ширину можно менять, перетаскивая границу.

- Поле **Branch or tag** фильтрует дерево по мере ввода. Остаются подходящие ветки и папки, в которых они лежат.
- **HEAD (Current Branch)**: клик фильтрует лог по текущей ветке.
- **Local** — локальные ветки. **Remote** — удалённые ветки, сгруппированные по remote (`origin`). **Tags** — теги. Remote и Tags сначала свёрнуты.
- Часть имени до `/` становится папкой: `agent/ostrov-assets-01` лежит в папке `agent`. Вложенные префиксы дают вложенные папки.
- У текущей ветки жёлтая иконка ярлыка. Стрелка вверх-вправо с числом — коммиты, которые ещё не отправлены. Стрелка вниз-влево с числом — коммиты, которые можно забрать.
- Клик по ветке или тегу фильтрует лог этой вкладки по ней. Клик по стрелке слева сворачивает или разворачивает папку. Двойной клик по папке тоже сворачивает её.
- Клавиши: стрелки вверх и вниз двигают выделение, влево сворачивает папку или переходит к родителю, вправо разворачивает, Enter фильтрует лог.
- Избранные ветки отмечены звездой и стоят первыми в своей папке. Избранное хранится в настройках IDE отдельно для каждого репозитория, а не в самом репозитории.
- Длинные имена прокручиваются вбок: свайп двумя пальцами или Shift+колесо. Строка ловит клики и правый клик по всей видимой ширине, на любом сдвиге.

Правый клик по ветке открывает меню:

- Checkout
- New Branch from '…'…
- Compare with Current — вкладка с коммитами, которые есть только в текущей ветке, и коммитами, которые есть только в выбранной. Клик по коммиту показывает его файлы справа. Клик по файлу открывает дифф.
- Show Diff with Working Tree — вкладка со списком файлов, которые отличаются от рабочей копии. Клик по файлу открывает дифф: файл в ветке против файла на диске.
- Merge '…' into Current, Rebase Current onto '…'
- Rebase Current onto '…' (Update Refs) — то же, что Rebase, но через `git rebase --update-refs`. Ветки, которые указывают на перебазируемые коммиты, переезжают вместе с текущей. Пример: ветка `upper` растёт из `lower`, а `lower` растёт из `main`. Rebase `upper` на `main` с Update Refs переносит и `lower`. Конфликты решаются так же, как при обычном rebase. Git передвигает остальные ветки, только когда rebase закончен (Continue). Нужен git 2.38 или новее.
- Update (для локальной ветки с upstream). Для текущей ветки это Update Project с последним выбранным способом (merge или rebase), без окна. Другую ветку IDE обновляет без Checkout: скачивает её upstream и передвигает ветку вперёд (fast-forward). HEAD, индекс и файлы на диске не меняются. Если ветка и upstream разошлись, IDE ничего не меняет и пишет, что ветку нужно сначала выгрузить (Checkout), а потом сделать merge или rebase.
- Pull into Current (для удалённой ветки, за которой следит текущая) открывает окно Update Project.
- Push… (для любой локальной ветки) — окно Push для этой ветки: её исходящие коммиты, и Push отправляет её без Checkout. Пункт серый, если у ветки есть upstream и отправлять нечего.
- Rename… (для локальных веток), Delete
- Add to Favorites / Remove from Favorites

Правый клик по тегу: Checkout (HEAD отделяется от ветки) и Delete (удаляет только локальный тег).

Правый клик по группе Remote открывает пункт Fetch: он скачивает все remote. Правый клик по папке remote (`origin`) скачивает только этот remote.

Все git-операции идут в фоне, интерфейс не ждёт их.

### Лог

Над таблицей коммитов стоит строка фильтров. Она занимает только ширину таблицы и сужается вместе с ней:

- **Text or hash** ищет по сообщению коммита или по началу хеша. Лог обновляется, когда вы перестаёте печатать. `.*` включает регулярное выражение. `Cc` включает поиск с учётом регистра.
- **Branch** показывает выбранную ветку. Клик открывает список веток с поиском. Можно отметить несколько веток. `HEAD` — текущая ветка. Крестик сбрасывает фильтр, и лог показывает все ветки.
- **User** открывает список авторов: `me` (вы, по `user.name` и `user.email` из git) и авторы из загруженного лога. Можно отметить несколько.
- **Paths** открывает поиск по файлам и папкам проекта. Лог показывает только коммиты, которые меняют отмеченные пути.
- Сразу за Paths: **No Merges** (скрыть merge-коммиты), кнопка обновления лога, **Fetch All Remotes** (облако со стрелкой) и **Update Project…** (стрелка вниз на черту).
- Если таблица узкая, фильтры справа обрезаются.

Таблица коммитов:

- Колонки: автор, граф, сообщение с метками веток и тегов, дата («Today 17:05», «Yesterday 22:15», дальше «01.10.2026, 13:18»).
- Ваши коммиты показывают автора жирным. Merge-коммиты серые.
- Полый кружок на графе отмечает коммит, на который указывает HEAD. Цвет линии — ветка.
- Очень длинная линия (больше 30 строк) рвётся: под коммитом-потомком видна короткая линия со стрелкой вниз, над родителем — со стрелкой вверх.
- Клик выделяет коммит. Cmd+клик добавляет коммит к выделению или убирает его. Shift+клик выделяет диапазон. Стрелки двигают выделение, Shift+стрелки расширяют его.
- Следующие коммиты подгружаются при прокрутке вниз.
- Правый клик по коммиту: Copy Revision Number, Checkout Revision, New Branch…, New Tag…, Reset Current Branch to Here… (soft / mixed / hard), Revert Commit, Cherry-Pick.

Справа от таблицы стоит панель изменений. Она начинается на уровне строки фильтров и занимает всю высоту лога. Её ширину можно менять, перетаскивая границу.

- Дерево файлов выделенных коммитов, как в окне Project. При нескольких выделенных коммитах дерево показывает их общие изменения.
- Корень дерева — общая папка всех файлов и число файлов. Цепочка папок с одной вложенной папкой показана одной строкой (`src/scene  7 files`).
- Цвет имени: синий — изменён, зелёный — добавлен, серый — удалён. У переименованного файла рядом видно старое имя (или старый путь при переносе).
- Кнопки Expand All и Collapse All разворачивают и сворачивают папки.
- Длинные пути прокручиваются вбок: свайп двумя пальцами или Shift+колесо. Строка ловит клики и правый клик по всей видимой ширине.
- Двойной клик или Enter по файлу открывает дифф. F4 открывает файл в редакторе.
- Правый клик по файлу (можно по нескольким выделенным): Show Diff, Compare with Local (версия из коммита против файла на диске), Edit Source, Cherry-Pick Selected Changes (применяет только эти файлы к рабочей копии и индексу, без коммита), Create Patch… (сохраняет `.patch` по указанному пути), Copy Patch (кладёт патч в буфер обмена).
- В панели только дерево файлов. Хеш коммита копирует Copy Revision Number в меню коммита.

### Ветки

Ctrl+Shift+\` открывает список веток с поиском. Enter в поиске делает Checkout первой найденной ветки.

Сверху в списке есть действия: New Branch…, Update Project…, Push…, Fetch, Stash Changes…, Unstash Changes….

Дальше идут три группы веток: Recent, Local, Remote. Наведите мышь на ветку, и справа откроется её меню:

- Checkout
- New Branch from…
- Merge into Current
- Rebase Current onto…
- Rebase Current onto… (Update Refs) — rebase через `git rebase --update-refs`, как в меню ветки окна Git.
- Rename…
- Delete

У текущей ветки вместо Checkout, Merge, Rebase и Delete есть Push. У ветки с upstream есть Update, как в дереве веток окна Git. Delete сначала спрашивает.

Стрелки рядом с веткой показывают, на сколько коммитов она впереди или позади upstream. Checkout удалённой ветки `origin/x` создаёт локальную ветку `x`, которая следит за `origin/x`.

### Сеть

- **Update Project** делает pull. Своей клавиши у него нет. Он есть кнопкой в строке фильтров лога, в списке веток (Ctrl+Shift+\`) и пунктом Update в меню текущей ветки. Cmd+T открывает новый терминал. Можно выбрать merge или rebase. Локальные изменения IDE временно прячет и потом возвращает (`--autostash`).
- **Update** в меню любой другой локальной ветки с upstream обновляет её без Checkout (см. «Окно Git: дерево веток»).
- **Push** (Cmd+Shift+K) показывает коммиты текущей ветки, которые уйдут на сервер. Заголовок окна называет ветку и remote: «Push main to origin». Галочка Force push делает `--force-with-lease`.
- Push… в меню ветки в окне Git открывает то же окно для выбранной ветки. Текущая ветка при этом не меняется.
- Если у ветки нет upstream, Push создаёт ветку с тем же именем на `origin` (или на первом remote). Галочка Set upstream включена по умолчанию. Если upstream есть, Push идёт в него, даже если там другое имя ветки.
- **Fetch** скачивает все remote (`git fetch --all --prune`). Он есть кнопкой в строке фильтров лога, в списке веток и в меню группы Remote в дереве веток. Пока Fetch идёт, он виден в строке состояния, и крестик его останавливает. Удачный Fetch уведомления не показывает: дерево веток и лог просто обновляются. Ошибка показывается уведомлением.
- Ключи SSH и credential helper берутся из вашего git.
- Если git просит пароль в терминале, команда завершится ошибкой и не будет висеть.

### Stash

Stash Changes… и Unstash Changes… находятся в списке веток.

- Stash Changes прячет изменения. Можно спрятать и неотслеживаемые файлы.
- Unstash показывает список записей и файлы выбранной записи.
- Apply возвращает изменения. Pop возвращает изменения и удаляет запись. Drop удаляет запись и сначала спрашивает.

### Конфликты

После merge, rebase или pull с конфликтами откроется окно Conflicts. В нём список всех конфликтных файлов. Строка показывает имя файла, а за ним серым его папку. Длинная строка обрезается с `…`. При наведении она сразу раскрывается целиком, как в Search Everywhere.

Клик выбирает файл. Cmd+клик добавляет файл к выбору или убирает его. Shift+клик выбирает подряд. Кнопки справа:

- **Accept Yours** берёт вашу версию у всех выбранных файлов.
- **Accept Theirs** берёт чужую версию у всех выбранных файлов.
- **Merge…** открывает три панели для выбранного файла: ваша версия, результат, чужая версия. Двойной клик по строке делает то же.

При rebase кнопки называются **Accept Upstream (ours)** и **Accept Your commit (theirs)**. При rebase git называет «ours» ветку, на которую идёт перенос, а «theirs» — ваш переносимый коммит. Rebase останавливается на каждом коммите отдельно, поэтому в списке только конфликты текущего коммита.

Решённые файлы пропадают из списка. Когда файлов не осталось, окно пишет «All conflicts are resolved.» и предлагает продолжить merge или rebase.

В панели Merge изменения только с одной стороны уже перенесены в результат. Конфликт подсвечен красным. Кнопки `>>` и `<<` берут сторону. Результат можно править руками. Длинные строки прокручиваются вбок колесом или полосой внизу.

Save and Mark Resolved сохраняет результат и помечает файл как решённый.

Пока идёт merge, rebase, cherry-pick или revert, под заголовком окна видна плашка. На ней есть Resolve…, Continue и Abort.

### Ограничения git

- Для файлов в LFS дифф показывает со стороны HEAD текст указателя, а не содержимое.
- Команда git, которая только читает (status, blame, diff, show, log), останавливается через 30 секунд с ошибкой. Полный `git status` всего репозитория останавливается через 10 минут. Локальная запись (add, reset, stash) останавливается через 10 минут. Push, pull, fetch, commit, checkout, merge и rebase лимита не имеют: их останавливает `×` в статус-баре. Если git не стартует совсем, причина часто в macOS: `syspolicyd` проверяет новые программы. Помогает перезагрузка.
- Сабмодули не поддерживаются.
- Нет умного checkout. Если локальные изменения мешают checkout, придёт ошибка git.

## Терминал

- Alt+F12 открывает и прячет окно Terminal.
- «+» или Cmd+T открывает новый терминал. Окно Terminal при этом открывается, а фокус переходит в новый shell. Каждый терминал живёт в своей вкладке. Вкладки стоят в заголовке окна Terminal.
- Cmd+3 открывает новый терминал в папке текущего файла, как «Open In Terminal». Из редактора это папка открытого файла. Из дерева Project это выделенная папка или папка выделенного файла. Из хлебных крошек с клавиатурой (Alt+Home) это папка выделенной крошки. Окно Terminal открывается, фокус переходит в новый shell. В редактор «3» не попадает. При нескольких выделенных строках дерева Cmd+3 ничего не делает, как и пункт меню. В терминале Cmd+3 нового терминала не открывает.
- Вкладку терминала можно перетащить влево или вправо, как в IDEA и Chrome. Перетаскиваемая вкладка идёт за мышью и обведена синей рамкой. Остальные вкладки сдвигаются и освобождают место. Отпускание кнопки ставит вкладку на новое место и делает её активной. Shell при этом продолжает работать. Escape или отпускание далеко от полосы вкладок отменяет перенос. Простой клик по вкладке по-прежнему только выбирает её.
- Средняя кнопка мыши по вкладке терминала закрывает эту вкладку, как у вкладок редактора. Shell при этом завершается. Закрытие последней вкладки прячет окно.
- Двойной клик по вкладке открывает поле с её именем. То же делает пункт «Rename Tab…» в контекстном меню вкладки. Enter сохраняет имя, Escape отменяет. Клик мимо поля тоже сохраняет имя. Пустое имя возвращает обычный заголовок от shell. В том же меню есть «Close Tab».
- Вкладки терминала сохраняются для каждого проекта: сколько их, в каком порядке, их имена, активная вкладка и папка, в которой был каждый shell. При следующем открытии проекта вкладки появляются снова. Shell вкладки запускается, только когда вкладку впервые показывают. Поэтому запуск IDE не ждёт терминалов. Если папки больше нет, shell запускается в корне проекта. История вывода не сохраняется.
- Если закрыть последнюю вкладку, проект запомнит ноль вкладок. Окно Terminal тогда откроется с новым shell.
- Вкладки хранятся в файле SQLite `harwex-ide.sqlite` рядом с остальными настройками IDE (`~/Library/Application Support/harwex-ide`). Фоновый режим (`HARWEX_IDE_BACKGROUND=1`) пишет в свой файл во временной папке.
- Терминал запускает ваш login shell (`$SHELL -l`) в корне проекта.
- Пока терминал в фокусе, все клавиши идут в терминал. Исключения: Alt+F12, Shift+Esc, Cmd+T, Cmd+Shift+T, клавиши окон (Cmd+1, Cmd+0, Cmd+9, Cmd+6) и Cmd+Shift+F12. Программа в терминале их не получает.
- Escape всегда идёт в программу: в shell, vim, less, Claude Code. Фокус остаётся в терминале, как в IDEA. Вернуться в редактор можно через Shift+Esc или Alt+F12.
- Shift+Esc прячет окно Terminal и возвращает фокус в редактор. Это работает и в vim, less и htop.
- Cmd+C копирует выделение, Cmd+V вставляет, Cmd+K очищает экран.
- Shift+Enter начинает новую строку и не отправляет ввод. В Claude Code это перенос строки в промпте, как `\` и Enter. Терминал шлёт те же байты, что Option+Enter (`ESC CR`). В zsh Shift+Enter вставляет перенос строки в команду, а Enter запускает её целиком. Исключение: vi-раскладка zsh (`bindkey -v`, или `EDITOR=vim` без `bindkey -e`). В ней Shift+Enter запускает строку.
- Колесо мыши прокручивает историю вывода.
- Клик по `path:line:col` в выводе открывает файл на этой строке.
- Cmd+клик по ссылке `http://`, `https://` или `file://` открывает её в браузере по умолчанию. Если зажать Cmd и навести мышь, ссылка подчёркивается. Ссылка может переноситься на следующую строку. Точка, запятая или скобка в конце не входят в ссылку.
- Программы вроде Claude Code печатают ссылки, у которых текст отличается от адреса (OSC 8). Cmd+клик по такой ссылке открывает адрес, а не текст.
- Браузер открывает только ссылки `http`, `https`, `file` и `mailto`. Остальные ссылки IDE игнорирует.
- Cmd+клик по `file://` на существующий файл открывает файл в редакторе.
