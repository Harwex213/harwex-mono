# app (`harwex-ide`)

The IDE itself: window, layout, tool windows, tabs, Git UI, navigation and the language registry. The crate is a library plus a thin `main.rs`. `main.rs` only parses the command line and sets up background mode. Tests build the same `IdeApp` headlessly through `IdeApp::create(ctx, storage, AppOptions)`.

## Boundaries

- Git logic belongs in `ide-git`. Text editing and highlighting belong in `ide-editor`. Terminal emulation belongs in `ide-term`. LSP mechanics belong in `ide-lsp`. The app wires them together and draws the panels.
- Language-specific server setup is the exception: the language registry (`lang/`) holds the adapters for TypeScript, rust-analyzer, clangd and Roslyn (locating, root detection, init options, `ide.toml`).
- Colors, radii, spacing and font sizes come from `theme::T` (`src/theme.rs`). Widgets write no color literals. This check must find nothing: `grep -rnE "Color32::(from_|[A-Z])|hex\(0x" app/src | grep -v theme.rs`.
- `src/icons.rs` draws the icons from shapes that egui stores inline (segments, circles, rects, Béziers). Icons use no textures and no SVG, and they allocate nothing per frame.

Read `docs/app-internals.md` when you add a panel, a custom tab, a Git UI action or a language.

## Contracts inside the app

- Several projects per window (`workspace.rs`, `docs/app-internals.md`): `AppState` holds the window-wide parts; each project is a `Workspace` in `state.ws` (the one in context) or `others`. `state.ws` is the active workspace while a frame draws and the job's own workspace inside its callback (`with_ws`). Never keep a `&Workspace` across `activate`, `open_workspace` or `with_ws`. API: `open_workspace(root) -> WorkspaceId`, `activate`, `close_workspace` (asks about dirty files), `workspaces()`, `Workspace::owned_pids()`.
- `state.jobs` is tagged with the workspace in context; a clone keeps its tag, so a worker's results reach the workspace that started it, never the active one by accident. Window-level work (memory sampler, folder picker) uses `jobs.window()`.
- Every absolute egui id that a workspace draws goes through `workspace::wid(...)`, never `Id::new` (panels, popups, modals, rows), so focus, scroll and popups stay per project. Only window-level widgets (title bar, toasts, close-project modal) use `Id::new`.
- Background work: `state.jobs.spawn(label, work, done)` runs `work` on a thread and `done(&mut AppState, result)` on the UI thread. `spawn_quiet` has no spinner label. `post(f)` schedules a closure from any thread. `busy(label)` guards long-lived workers; call it on the worker thread. A panic in a job becomes an error toast.
- Cancel (`jobs::Cancel`, `progress.rs`): every labelled job shows in the status bar with its time and a `×`; a job that cannot stop early uses `busy_uncancellable` and gets no `×`. Git and LSP calls on the job's thread see its flag (thread-scoped: a thread the job spawns does not inherit it); other work reads `jobs::current_cancel()`. A cancelled job ends with one `Cancelled: <label>` toast, and `notifications` sends errors that carry the cancel text to the log only. When a result is no longer wanted, keep the `spawn_cancellable` handle and call `cancel_quietly`.
- Background tasks slot (`progress.rs`): the jobs draw in a fixed-width slot (`SLOT_W` 204, `SLOT_W_NARROW` 136 under 800 pt) at the left end of the status bar's right part, also when nothing runs, so jobs never change the breadcrumbs' width. The text is cut with `…`; its a11y node is `Running: <label>` with the whole text (and `+N`) as its value. The tasks popup lists each job as `Task <text>` with a bar: `jobs::report_progress(f)` on the job's thread sets the share, else the bar moves. Tests read `progress::list_open`. The text and the `×` share one rounded hover background (`progress::hover_pill`); the `×` has none of its own.
- Git status refresh (`git/refresh.rs`, IDEA's model): every git write goes through `git::remote::run_op` / `run_op_with` / `run_op_quiet` (no success toast), or brackets its job with `refresh::write_started` and `write_done(Refresh)`, also on failure. `Refresh::Paths` refreshes only those paths and merges the rows (stage, unstage, commit, rollback). `Refresh::Changed` (the `run_op` default) and a watcher `.git` event whose `GitStamp` differs from the one after our last write run `refresh::changed`: `status_of` over `ide_git::changed_paths` (old HEAD vs new HEAD, staged and conflicted paths) plus the shown rows, merged in; above `MAX_CHANGED` (400) paths it walks the whole tree. It never sees plain worktree edits, which the watcher's file batches refresh, so a write that edits the worktree on its own (Unstash) passes `Refresh::Full`. `Refresh::Full` and `state.refresh_git()` (startup, Refresh) walk the whole tree; a newer run cancels the running one. An incremental run must start from the stamp of the rows shown: it records its stamp only with its rows, and it falls back to a full walk while a walk runs or after one was cancelled. An `on_fs_batch` call for files the app wrote passes `git_changed: false`. Tests read `ws.git.refresh.full_runs` / `changed_runs` / `path_runs`.
- Language traffic goes through `state.ws.langs`. Each language has one queue thread, so sync commands and requests reach the server in UI order. Call `nav::flush_lsp` before a request, so the server has the current buffer text.
- Results that arrive late must not act on newer state. Use the generation counters (`nav`, `find`, `search`, the project generation) and drop stale results. Line numbers captured at click time go stale when the doc version changes. Stash entries are resolved by oid, not by index.
- A new global shortcut goes into `app::shortcuts` after the `terminal::shortcuts` check. Otherwise the shortcut fires while the user types in a terminal. The exceptions sit before that check and are taken even from a focused terminal: Shift+Esc, Cmd+T (new terminal tab), Cmd+Shift+T (`tabs::reopen_closed`), the tool window keys and mouse buttons 4/5 (below).
- Tool window keys (`app::tool_window_keys`, IDEA's): ⌘1 Project, ⌘0 Commit, ⌘9 Git, ⌘6 Problems (`ToolWindow::for_digit`; the strip tooltip shows `ToolWindow::shortcut`). A press shows the window and gives it the keys; a press while that window has them (`focused_tool_side`) hides it. Activation marks the side as pressed (the editor loses focus), then `focus_activated` focuses the biggest `focusable_noninteractive` widget on the island, also a list that loads a few passes later; a window without one (Problems with no rows) stays active by the press mark. ⇧⌘F12 is `Layout::toggle_all`; the hidden layout lives in egui temp data per project. Mouse buttons 4/5 (`PointerButton::Extra1`/`Extra2`) are `nav::mouse_buttons`, Back/Forward; `ide-term` reports only buttons 1-3 to its program.
- Cmd+F, Cmd+R, Cmd+G, Shift+Cmd+G and Ctrl+Cmd+G (Select All Occurrences) (`app::editor_find_keys`) act on the active editor only while it or its find bar has the focus, or nothing has (`EditorState::owns_focus`). From a tool window they also move to the editor and act there, unless a text field has the focus. The other multi-caret keys (Alt+click, Ctrl+G, double Alt) live in the editor widget.
- Esc in a tool window returns the focus to the active editor tab (`arm_tool_escape` in `shortcuts`, `finish_tool_escape` at the end of `update`). It acts only if no inner widget consumed the Esc that frame, so a widget that uses Esc must `consume_key` it. A focused terminal keeps its Esc.
- A popup that handles keys consumes them at the start of the frame (see `nav::take_popup_keys`, `breadcrumbs::take_keys`). Otherwise Enter and the arrows also reach the focused editor.
- IME follows `PlatformOutput::ime`: only the focused editor (`EditorView`) and focused `TextEdit`s set it. A new hand-painted text input must set it to its caret every frame while focused, or IME is off and macOS shows the input-source bubble at a stale rect. Tests read `ide.harness.output().platform_output.ime` (`editor_ime`).
- New tool-window rows and hand-painted widgets need an accessibility label. The tests find widgets by label.
- A list row whose text may be cut uses `util::expandable_row`: a hovered cut row repeats itself with the whole text on a tooltip-layer overlay in the same frame (IDEA's expandable item), never an egui tooltip. Tests read `util::expanded_row(ctx)`.
- Search Everywhere rows (`search::hit_row`) are the exception: the folder is cut first, a name that alone does not fit loses its middle (`middle_cut`, the extension stays), and the hover overlay keeps the row's left edge and grows right, at most to the screen's right edge. The a11y name is always the whole row (`<name>  <dir>`). Tests read `search::expanded_row(ctx)`; its text is the drawn glyphs, because `Galley::text()` holds the whole text also when elided.
- There is no right strip. Every tool window toggle sits on the left strip; the islands keep a full `gap` to the right window edge.
- The macOS window buttons sit vertically centered in our 40 pt title bar. `chrome::title_bar_layout` is the layout math (buttons, content x, none in full screen); `chrome/macos.rs` moves the native buttons there; `--test-chrome` checks a real background window against it.
- The title bar holds only the project widget, Settings and the display-only branch. Git and search actions live on shortcuts (Cmd+K, Cmd+Shift+K, Shift Shift, Ctrl+Shift+Backtick for branches). Do not add action buttons there.
- The project selector (`projects_popup.rs`) is window-level: `AppState::projects` holds the popup and the Recent list (storage `recent_projects`, MRU by activation, open roots hidden). The folder picker goes through `Platform::pick_folder`; tests answer it with `RecordingPlatform::set_picked_folder`. Each opening checks the Recent roots on a `jobs.window()` worker (`check_gen` drops older answers); a missing root draws grey, is labelled `Recent project <name> (missing)`, and a press on it only toasts `Folder not found: <path>`.
- Project order (task 111): `AppState::order` is the window's project order; `workspaces()`, the saved `open_projects` and the next active project on close follow it, never the id. `move_workspace(id, ±1)` changes it and keeps the active project. In the selector a hovered or selected Open Projects row shows `Move project <name> up|down` in fixed slots left of the cross (hover-only a11y nodes, disabled at the ends); Alt+Shift+Up/Down move the selected row and are consumed before the plain arrows, because `consume_key(NONE, ArrowUp)` also takes Alt+Shift+Up.
- The project tree has focus while egui's focus is on `tree::focus_id()`. Focus picks the selection color (blue focused, grey otherwise) and routes the arrow keys. A row press selects; a double click anywhere on the row toggles a folder or opens a file; a click in the chevron cell toggles at once. A double click is press 2 of the app's click chain (`state.clicks`, see below). The row is the only click widget: the chevron cell is a hover-only a11y node, and the row decides by the pointer x. A row's rect includes the spacing under it, is exactly the viewport wide, and its id is `("tree-row", path)`. Deep rows scroll sideways: the content width is the widest row drawn since the row count last changed (`ProjectTree::content_w`), never a pass over all rows; the indent, icon and name scroll, the hit rect and highlight stay on the visible part. A reveal brings the name start into view. Cmd/Shift presses, Shift+arrows and Cmd+A build a multi-selection: `tree.selected` is only its lead row, so read the selection through `ProjectTree::selection()` (`docs/app-internals.md`).
- Project tree drag and drop (`tree.rs`): a press that moves past egui's click distance starts `state.ws.tree.drag`; the drop goes through `tree_menu::drop_into`, the same `paste` as Cut/Copy + Paste (Alt copies). The target is the row's folder or a file row's parent (`tree::drop_dir`), refused inside the dragged folder; a11y node `Drop target <rel>`. The tree's `ScrollArea` has drag-to-scroll off.
- Tree speed search (`speed_search.rs`, IDEA's): the Project tree, the Commit tree (`git::changes`) and a Log tab's changed files (`git::commit_changes`) share `take_keys`, `step`, `matches`, `name_job` and `tree_field`. Typing while the tree has focus fills its `search` and selects the first match (the selected row stays while it still matches). Up/Down step between matches and wrap, Backspace edits, Escape clears, Enter acts (the tree's own Enter) and ends the search; a row press or focus loss ends it too. `take_keys` runs before the tree's own keys, which read Backspace, Escape and the arrows. Text typed with Cmd, Ctrl or Alt never enters the search. The Project tree searches visible rows only, and its field replaces the root row. The two change trees search every row as if all folders were open, match folder rows by their compressed `a/b` label, expand the folders above the match, and draw the field over the toolbar above the tree. The Commit tree holds a folder match in `ChangesUi::dir_selected` (`selected` holds files only); Enter on it toggles the folder. a11y `Speed search <text>`. While a search runs, the tree's focus lock filter takes Escape, or egui drops the focus on Escape before the tree sees it.
- Collapsing a tree folder (`ProjectTree::collapse`, also `set_expanded(dir, false)`) drops every expanded folder inside it, so the next expand shows one level.
- Terminal tab drag (`terminal::header_tabs`): each tab is `ui.interact` with the id `term.id.with("tab")`, so egui keeps the drag while the tab moves; `Terminals::drag` remembers the tab by id. Escape is consumed in `terminal::shortcuts` (before the focused-terminal Escape) and calls `ctx.stop_dragging()`, or the release would still drop. `move_tab` moves the `Terminal` (never respawns) and makes it active. Tabs persist per project in SQLite (`terminal_store.rs`, `docs/app-internals.md`); `AppOptions::terminal_db` is `None` in tests unless a test points it into its fixture.
- Breadcrumbs (`breadcrumbs::bar`) draw every segment in a horizontal `ScrollArea`; there is no `…` collapse. The app sets the offset every frame: the end while `stick_end` holds (a new file sets it, a frame that ends away from the end clears it), else egui's stored offset. A keyboard-selected crumb scrolls into view. The bar's scrollbar stays `SCROLLBAR_H` thin at the bottom edge, also hovered (`breadcrumbs::scroll_style`), so it never covers the text. `Breadcrumbs::slots` are the crumb rects at their scrolled position; popups and the file menu re-anchor to them every frame, clamped to the visible bar (`bar_rect`). A double click on a folder crumb selects and expands it in Project.
- Breadcrumbs and git-ignored entries (task 118): with `files.show_ignored` a popup listing is `list_dir(dir, true, dir_ignored)`, rows with `Entry::ignored` drawn `tree_ignored`; without it, `list_dir(dir, false, false)`. A nested level takes `dir_ignored` from its parent row; level 0 takes it from the crumb flags (`Breadcrumbs::crumb_ignored`), or the worker finds it with `tree::ignored_below`. `ignored_below` lists the parent folders down to the first ignored one, because a folder inside an ignored one matches no ignore rule itself. The crumb flags are computed on a worker once per active project file; the bar draws a flagged crumb `tree_ignored` only while the setting is on. `set_global` calls `Breadcrumbs::relist` with the tree's `relist`; its `list_gen` drops older listings.
- Breadcrumb popups have a speed search (`Level::filter`, per level): `take_keys` takes the `Event::Text` events and Backspace while a popup is open, so typing never reaches the editor. `Level::selected` stays an index into the full listing; the keys move between `visible` rows only. Escape clears the focused level's filter first. A11y: the field is `Speed search <text>`.
- Breadcrumbs of a file outside the project start at a library root (`breadcrumbs::external_root`): the rust-src crate, `<crate> <version>` from a Cargo registry, the `node_modules` package, or `External` with at most 3 segments. The label never holds a disk path, so snapshots of external files do not depend on the checkout location.
- A project crumb is a file target like a tree row: its menu is `tree_menu::file_menu` (Select in Project plus the tree's `menu`), and its keys are `tree::command_keys` plus Alt+F1, all run through `tree_menu::run`. A new file command goes into the tree's menu, and both menus get it.
- Cmd+3 (Open In Terminal, `terminal::open_here`) follows focus: the tree and a focused crumb take it through `tree::command_keys` (selected item, like the menu, nothing for several); otherwise `app::shortcuts` consumes it after the terminal check and opens the active tab's file folder, so the editor never sees it.
- The Commit tree (`git::changes`) has the groups Staged, Unstaged and Unversioned Files. A row is a (path, group) item, and a partly staged file has two. A11y labels: `<Title> group`, `Directory <dir> in <Title>`, the file path, and `<path> in Staged` for the Staged row of a partly staged file. Boxes are `Include <label>`; during a drag the target group is `Drop target <Title>`. Stage, Unstage and drops go through `run_op`.
- Commit tree folding (task 112): `ChangesUi::fold` holds the user's exceptions to the defaults, keyed by collapse key: groups start open (`collapsed_groups`), folders start collapsed (`expanded`). A status change never opens a folder; a folder new to a group starts collapsed, and `rebuild` drops `expanded` keys of folders that are gone. A selected file that moves to another group stays selected there; when its row is hidden, `reselect_hidden` moves the selection to the nearest shown folder row (`dir_selected`), or clears it. Tests that click file rows press Expand All first. The Log tab's changed files (`commit_changes`) have their own state and stay expanded by default.
- Commit tree patches (task 114, `git/patch.rs`): Copy as Patch to Clipboard and Create Patch... in the row menu take `target_items` (selection, folder or group span); the toolbar's `Patch actions` (`⋯`) takes the selection or, with none, every change. `ChangesUi::patch_files` turns rows into `LocalPatchFile`s: both rows of a partly staged file are `Both`, conflicted files are left out. The diff runs on a worker (`Repo::local_patch`); Copy goes through `state.platform` and toasts `Patch copied (N files)`; Create Patch writes the file with `std::fs::write` (a `NOT_DOCUMENTS` entry). Dirty tabs are not saved first.
- Git log (`git/log.rs`, `git/log/`, `git/commit_changes.rs`): one `LogView` per Log tab, owned by the Git window and lent to `log::log_body` each frame. A job cannot reach a lent view through `AppState`: it posts a `ViewMsg` into `state.ws.git_ui.log` under the view id, and the view applies it when drawn. Details and a11y labels in `docs/app-internals.md`. While `LogView::is_loading`, `log::loading_bar` paints a 2 pt bar (a11y `Log loading`) over the table's bottom edge; it is painted, never laid out. The branch tree's filter action goes into the view before `log_body` draws, so the press frame already shows the bar. Tests hold loads with `LogUi::hold_loads`.
- Log ref labels (`git/log/table.rs`, task 116): `fit_refs` (pure) splits the subject column: every label beside the whole message; else the first label (HEAD or the current branch, `ide_git` sorts it first) plus `+N` while the message keeps `MIN_MESSAGE_W` (120 pt, or its own width); else `+N` for all. The message is cut with `…` (`message_job`) and is not drawn below the width of `…`. The split never reads hover or selection, so rows never shift. Hovering `+N` lists every ref. A11y: `Ref label <name>`, `More refs +N`, `Ref list <name>`.
- Push dialog (`git/remote.rs`): the Force push checkbox sits left of the button. With force on, the first press only switches the same button to `Confirm force push` (danger fill); the second press pushes with lease; Esc (consumed) or unticking go back. Every label uses `push_button_width` (the widest label), so nothing moves between the states.
- Git window shell (`git/window.rs`, `git/branch_tree.rs`, `git/console.rs`): header tabs, branch tree and Console. Tab 0 (main Log) never closes; tree branch rows are labelled `Tree branch <name>` because `Branch <name>` is the title bar. Git commands reach the Console only through the sink that `install_project` sets before the `Repo` is cloned; a `Repo` built elsewhere is invisible to the Console. Details in `docs/app-internals.md`.
- Project tree file operations: `tree_menu.rs` (menu, keys, dialogs, the rename/move/delete/usages pipeline) on top of `fileops.rs` (disk work, no UI). Rename, Paste after Cut, Delete and Find Usages first run `ide_ts::import_candidates` over the file index on a worker, then ask each language through `state.ws.langs`; a dialog shows the progress, and Cancel or a newer question drops the answer by generation. Moves apply closed-file edits in parallel on workers and open documents with one `transact` each, then save.
- Trash, Finder, the clipboard (text and images) and the URL opener (terminal Cmd+click, `open_url`) go through `state.platform` (`fileops::Platform`). Deterministic mode (all tests) gets a `RecordingPlatform` that records calls (`open-url <url>`) and moves trashed items to `$TMPDIR/harwex-ide-test-trash`. Never call the system directly. With Settings › System › Files › Trash off, Delete skips the platform and deletes for good.
- `[project] excluded` in `.harwex/ide.toml` becomes `state.ws.tree.excluded`: dimmed in the tree, skipped by the file index and Find in Files. `apply_ide_config` rebuilds the index when the list changes.
- Git-ignored entries in the Project tree (`tree::list_dir`, task 110): with `files.show_ignored` (global, System › Project view, default on) a listing holds the ignored entries too, `Entry::ignored`, drawn `tree_ignored`; a child of an ignored folder is ignored without a matcher run (`ProjectTree::is_ignored` of the parent). An ignored folder is read only when expanded. The file index, Find in Files and git status still skip ignored files. The watcher keeps `node_modules`/`target`/`.yarn`/`dist` changes out of `FsBatch` and posts their folders to `AppState::on_ignored_dirs`: an expanded folder is listed again, a collapsed one `forget`s its listing. A setting change calls `ProjectTree::relist`; every listing carries `list_gen`, and `set_dir_at` drops an older one.
- Find in Files (`find/`): every text search goes through `find::targets` + `find::search_with`; the popup (debounce, streaming, cap, keys, history) is described in `docs/app-internals.md`. A Project search reads the file index (`ws.index`), so a file the tests write after the project opened is found only after an `on_fs_batch` with `structure_changed`. A search takes at most `find::search_threads()` (half the cores) at low priority; keep it so, the user's machine must stay responsive. The memchr fast path folds case by lowering ASCII bytes only: a case-insensitive query with a non-ASCII char must go to the regex (`Engine::new`), or "цели" misses "Цели". A plain query on the regex path (Words, non-ASCII) replaces with its text as typed, never expanding `$1`.
- Find window (`find_window.rs`, `preview.rs`): one bottom tab per Find Usages / Find in Files search, filled through `start_usages`/`finish_usages`/`open_text_results`; a `FilePreview` owner calls `preview::tick` every frame and `preview::flush` before dropping it (`docs/app-internals.md`).
- Editor tab drag (`Tabs::show_bar`): the tab widget is `click_and_drag` with the id `("editor-tab", tab id)`, so the drag survives the tab moving under the pointer; `Tabs::drag` remembers the tab by id. The press still activates (and closes on ×) at once, so a drag always moves the active tab. The other tabs never re-flow during a drag; `drop_slot` picks the row from the floating tab's middle. Escape goes to `Tabs::take_escape` in `app::shortcuts` before `terminal::shortcuts`, and it calls `ctx.stop_dragging()`. A drop emits `TabBarEvent::Move`; the order persists through `SavedWorkspace`, which reads `tabs.list`.
- Editor tab menu (`tabs::tab_menu`, Alt+click on × is Close Others): every multi-tab close goes through `AppState::close_tabs`, which calls `close_tab` per tab in strip order. A dirty tab's prompt parks the rest in `ws.close_batch` until `confirm_close` is answered; Cancel drops the batch.
- Custom tabs (diff, merge) implement `tabs::CustomTab`. Use `CustomTab::file_path()` when the tab shows one file, so the breadcrumbs follow it. A tab that edits a file returns it from `shared_editor()` and edits the editor tab lent as `TabEnv::editor`, never a copy of the text (the diff's working-tree side, `docs/app-internals.md`).
- Operation banner and Continue to End (`git/conflicts.rs`): the status text sits in a slot as wide as its longest variant, and a hidden Resolve... keeps its width, so the buttons never move. Continue to End (rebase only) is `ConflictsUi::auto` (`AutoContinue`). Every continue in the mode goes through `continue_step`, whose worker reads the state git left. The worker's result decides the next move: conflicts wait for the resolve (`WaitResolve`), a successful stop (edit, break) continues at once, a refusal pauses with git's text (`Paused`). After the last resolve, `check` starts the continue. It ignores a check spawned before the last step ended (`epoch`): such a check may have read the repository while git was still writing. The mode ends with the rebase, on a confirmed Abort and on an `Err`.
- Merge window (`git/conflicts/merge.rs`): three `EditorView`s. The result edits the file's own editor tab (`shared_editor`), so highlighting, language server sync and diagnostics are a normal tab's; `open_merge` opens that tab in the background when needed, and `MergeTab::init` sets the result with `reset_text`, then applies the non-conflicting changes as one undo step. Chunks keep their result range in chars and follow every edit through `changes_since` (`map_range`: an edit at a chunk's start goes in, one at its end stays out). A side counts as applied while its chunk holds a text recorded at an apply, so an undo brings the arrow back. Cancel and a close without a save put git's text back (`discard`); `close_tab` lends a custom tab its shared editor in `on_close` too. A11y: `Editor Merge <side label>`, `Editor Merge Result`, `Apply left|right change N`, `Applied left|right change N`, `Merge path <rel>`.
- Viewers (`viewer/`): `open_location` sends an image without a position to the image tab (`viewer::image`, key `image:<path>`, reloaded by the watcher), unless a text tab holds the file; `open_text_location` always opens text (SVG "Open as Text"). Images decode only on workers (`viewer::load`/`decode`, longest side capped at `MAX_TEXTURE_SIDE`); the UI thread only uploads the texture (`Pic::ready`). A binary raster diff decodes `FileDiff::old_bytes`/`new_bytes` on the diff's worker into `DiffImages`, which keeps the bytes for Copy Image.
- Copy Image (`viewer/clip.rs`): the image tab (Cmd+C, the view's menu), each image diff side (menu) and the tree menu on an image file read, decode and encode on a worker, then call `Platform::copy_image` there (macOS: `NSPasteboard` PNG + TIFF, an SVG's source as text). A raster goes at full size, a PNG as its own bytes; an SVG renders at the view's scale × `pixels_per_point` (the tree: 1:1), capped at `MAX_TEXTURE_SIDE`. A toast only on failure. Tests read `platform.copied_images()`. `viewer::clip::tests::real_pasteboard` is the real check: ignored and a no-op without `HARWEX_TEST_PASTEBOARD=1`, because clean-check runs ignored tests and the check overwrites the user's clipboard.
- Markdown preview (`viewer/markdown.rs`): a `.md` editor tab carries `EditorTab::markdown` (Editor / Split / Preview). `editor_area` draws the editor into `markdown::panes(..).editor`, then `markdown::finish` draws the preview, the splitter and the floating mode toolbar (so every `.md` snapshot shows it). The preview parses only while shown (UI thread up to 256 KB, a worker above), draws only the blocks in view and estimates the rest; Split syncs by block (`y_of_line`/`line_of_y`). Selection (task 117): one selection over the document as `TextPos` (block, char of `block_text`: table cells joined by tabs, rows by newlines); the pane widget (`Sense::click_and_drag`, under the link widgets) takes the presses and drags, `select` hits last frame's galleys (`Preview::pieces`) before drawing, and each galley paints its part first. A link is click-only, so a drag that starts on it goes to the pane. Copy posts to `state.platform` (tests read `copy <text>`); `Preview::char_pos` gives a char's screen point for tests. A11y: `Show Editor Only` / `Show Editor and Preview` / `Show Preview Only`, `Markdown preview <file>`, `Link <text>`, `Image <alt>`; image tabs `Image <file>`, `Zoom In`, `Zoom Out`, `Actual Size`, `Fit to Window`.

## Test

```sh
cargo test -p harwex-ide                              # all suites, headless
cargo test -p harwex-ide --test app git_history::     # one suite
UPDATE_SNAPSHOTS=1 cargo test -p harwex-ide --test app shell::   # re-record, then Read the PNGs, delete *.old.png
```

- `project_menu` covers the tree menu and file operations; its rename and delete tests need TypeScript 5 or rust-analyzer from `target/tools/`.
- The suites are modules of one test binary, `tests/app/main.rs`; they share one process, so a suite never sets env vars or other process-wide state (`docs/testing.md`, "Test binaries"). They drive the real `IdeApp` through `egui_kittest` with real pointer and key events. Read `docs/testing.md` before you add a test. Use the `tests/common` driver and fixtures. Assert state, not only pixels.
- A failed snapshot leaves `<name>.new.png` and `<name>.diff.png`. Read both before you re-record. A change in a shared area (status bar, top bar) re-records many snapshots. Check that the pixel difference stays inside the area you changed.
- `format` needs node and oxfmt (`HARWEX_TEST_OXFMT`).
- `diagnostics` needs node, TypeScript 5 and 7, oxlint (`HARWEX_TEST_OXLINT`) and the ESLint tree (`HARWEX_TEST_ESLINT`). `lint_budget` needs ESLint and oxlint and prints the linter table with `--nocapture`.
- `navigation` needs node and TypeScript 5, `rust_nav` needs rust-analyzer and rust-src. All come from `cargo xtask test-tools` (`target/tools/`), or from `HARWEX_TEST_TS5`, `HARWEX_RUST_ANALYZER` and `RUST_SRC_PATH`. Tools on PATH or in rustup are not used. Missing tools print `skipping ...` and pass, so read the output for skips.
- `csharp_nav` needs the .NET SDK and the Roslyn server from `target/tools/dotnet` and `target/tools/roslyn` (or `HARWEX_TEST_DOTNET`, `HARWEX_TEST_ROSLYN`). `common::init` points the app's `HARWEX_DOTNET`/`HARWEX_ROSLYN` at them and keeps the SDK's writes in `target/tools/dotnet-home`; never a `dotnet` from PATH or `~/.dotnet`.
- `cpp_nav` needs clangd from `target/tools/clangd` (or `HARWEX_TEST_CLANGD`). `common::init` points the app's `HARWEX_CLANGD` at it, so no test starts a clangd from PATH or Xcode. A test that only checks highlighting of C/C++ turns the servers off (`apply_ide_config` with `languages = ["ts"]`), or clangd's hints cover its snapshot.
- `unreal_nav` builds a fake engine with a fake `Build.sh`; it never runs a real Unreal or Epic tool. Its clangd tests skip without the pinned clangd like `cpp_nav`.
- `cancel` has its own binary (`tests/cancel.rs`): it points `HARWEX_GIT` at a fake git for the whole process (ide-git reads it once per process). A test that leaves a job hanging uses `snapshot_running` and `open_file_running`: `settle` would wait for the job.
- Deterministic mode turns the idle-save timer off (`state.settings.sync.idle_timer`), so a slow test never saves behind its back; `settings::idle_save` turns it on and moves `sync.last_input` back. Focus-loss saves and syncs fire only on pushed `Event::WindowFocused` events.
- `test_options()` gives no storage, no file watcher and a `zsh -f` terminal with the prompt `$ `. Use `MemoryStorage` for persistence tests. Never point a test at the user's storage.
- Fixtures live at fixed paths, so two processes that run the same test take turns on a lock file (`<suite>/<name>.lock`). The wait ends after 150 s with `fixture <x> locked by another run` and the holder's pid.
- Waits in `tests/common` panic with the pending jobs after 40 s; a frame that never returns ends the test process after 30 s (`common/watchdog.rs`). Raise a slow test's budget with `ide.set_wait_budget`, never with a loop around a wait (`docs/testing.md`, "Time limits").
- A real window run needs `HARWEX_IDE_BACKGROUND=1`, or a `--test-*` hook from `src/testhook.rs`. Use it only when the headless suites cannot cover the path (real repository smoke tests).

## Traps already hit

- An `egui::Area` offers its content only last frame's size. A list that starts with "Loading..." stays cut off. Ask for last frame's content height.
- A `TextEdit` that requests focus on the same frame never reports `lost_focus()`. Enter then does nothing. Re-focus only when the box did not just lose focus.
- `consume_key(NONE, F7)` ignores an extra Shift. Consume Shift+F7 first.
- A focus requested in a frame with an arrow press, while nothing had focus, is moved by egui's arrow navigation. Request the focus again on the next frame.
- A focused widget whose focus lock filter does not take the arrows loses the focus to egui's arrow navigation, even when it consumes the arrow keys itself. A tree sets `set_focus_lock_filter` with `vertical_arrows: true` every frame while it is focused (see `commit_changes::search_keys`).
- The UI fonts are bundled Inter and JetBrains Mono (`assets/fonts/`). They have ⇧ ⌘ ⌥ ⏎, arrows, › and …. A symbol outside that set may draw as a box: add it to `theme::tests::fonts_cover_shortcut_symbols` before you use it.
- `std::fs::canonicalize` on the UI thread is a blocking call. Paths in state are already canonical.
- Clippy's `items_after_test_module`: the test module sits at the end of the file.
- A widget that keeps focus without a click sense (a tree, a table) must call `ui.interact(rect, id, Sense::focusable_noninteractive())` every frame. Otherwise egui drops the focus at the end of the frame.
- A layout above the status bar must use the frame's total margin, not the Area's last-frame size, or nested popups drift.
- egui drops a widget's focus when a press lands outside it, and a `focusable_noninteractive` widget never counts as hovered. A press inside it still drops the focus until the release. Re-request the focus on the press frame, after the `interact` call (see `tree::show`).
- A small click widget on top of a bigger one (a chevron on a row) steals clicks near its edge through the interact radius, and a double click on it reaches only it. Use one click widget and split it by the pointer position.
- egui's `double_clicked()` is wrong for a real user's clicks. egui calls a click "triple" up to twice `max_double_click_delay` after the click before last (1 s with the macOS 0.5 s), and it ignores where a click lands. A double click right after a selecting click, or a second double click, never fires; a quick click on another row fires as a double. Ask `state.clicks.double(&resp)` (`clicks.rs`, the shared `ide_editor::ClickChain` that `IdeApp::update` feeds each frame). Only `clicks.rs` may call egui's `double_clicked()`/`triple_clicked()`; `clicks::tests::no_egui_double_clicks` fails on any other use in `app/src` or `crates/*/src`. A test sees this only with the real interval and no pause before the click (`Ide::click_now`, `double_click_now`); `click_at` waits it out.
- A late frame carries several button events. The first release and the second press of a double click can share a frame, and egui reports that frame's click and the next frame's click. A double click is the release of chain press 2 (`Clicks::double`), not "the chain stands at 2 when a click arrives": that check fired twice and toggled the folder back. Replay such frames with `Ide::pointer_frame` (`shell::fast_double_clicks_toggle_once`).
- egui reports no `clicked()` for a press held longer than its click time. Act on `is_pointer_button_down_on()` when a long press must still count.
- A `TopBottomPanel` stores its content height as its new height every frame. Content sized from a guess (the available height minus a fixed button height) moves the panel a few pixels per frame, and egui asks for no repaint. Make the content fill the panel exactly: add the bottom row first in a bottom-up layout, then give the rest to the box (see `git::changes::message_area`).
- In a bottom-up layout, `ui.horizontal` reserves only `interact_size.y`, so taller buttons grow down past the edge. Use `Layout::left_to_right(Align::Max)` for a bottom row.
- macOS puts the window buttons back at its default spot on resize, key-window changes, full screen exit and theme changes. `chrome::sync` re-applies them every frame, writes only when a frame differs, and asks for one more frame after a move.
- A row with `Sense::click_and_drag` under a click-only widget (the commit tree's checkbox) gets the drag, and the checkbox gets the click. In a virtualized list, find the drop row from the pointer y before the rows paint, so every target row can show the highlight.
- macOS turns ⌘X, ⌘C and ⌘V into `Event::Cut`, `Copy` and `Paste` with no key event, and sends `Paste` only when the clipboard holds text. ⇧⌘C is a `Copy` with Shift held. The tree reads both forms, and Cut/Copy put the name on the clipboard so ⌘V arrives. Tests push the events, not keys.
- The tree consumes Escape and the arrows while it has focus. While a context menu is open it must not (`ctx.is_context_menu_open()`), or Escape never closes the menu.
- A tree command that opens a dialog must not set the tree's `focus_pending`: the next frame the tree would take the focus back from the dialog's text box.
- rust-analyzer answers `willRenameFiles` with nothing for a short while after it reports `quiescent`. `RustService::retry_module` asks again while a declared module gets no edits. During the workspace load a request can also fail with "request handler panicked: Unable to get `FileSourceRootInput`"; `RustService::retry` asks again while the server loads.
- egui takes the focus from a widget under a `Modal` on every frame. A widget that must look focused under a modal requests the focus again on every frame (see `find::popup::search_field`), or its focus blinks frame by frame.
- egui opens and closes its one context menu only inside the owner's `Response::context_menu` call. When the owner is not drawn (a virtualized row scrolled out, its tool window switched by a shortcut), the menu stays open and invisible: its old rect swallows every right-click below it and `is_context_menu_open()` stays true. `util::close_orphaned_context_menu` closes it at the end of each frame. Give menu rows ids that follow the item, not the position, or the menu moves to another row after a scroll.
- A row wider than its scroll viewport (`available_width().max(N)`) has a clipped part that takes no clicks, and the a11y rect still claims it.
- A click widget drawn over the editor's text area (the problems counts widget) must live in its own `egui::Area`. In the editor's layer the text area still counts as hovered and moves the caret on the same press.
- oxlint 1.77's language server panics (`disable_fix.rs:52`) on every file that gets a `jsPlugins` diagnostic, with a JS or a JSON config, and no `fixKind` avoids it (task 057). `OxlintSource` quarantines the file whose lint was in flight when the server died: it closes the file in the client (a restart must not reopen it) and answers one `Information` row with code `crash` instead of sending the file, until the file's or an ancestor oxlint config's mtime/size changes or `shutdown`. No toast. `lint` starts the server (`capabilities`) before it sends the file, so a death there is no file's fault; 3 such deaths in a row, or 3 different files crashing in a row within 20 s with no successful lint between, stop the server until the settings change, with one toast.
- oxlint never waits for the `tsgolint` it starts, so each type-aware lint leaves one zombie, and only the parent can reap it (macOS has no subreaper). `OxlintSource::upkeep` runs on the lint queue's timer while no lint runs or waits. Above 20 zombies it kills the server's group (launchd then reaps them); the next lint starts a new server. No crash count, no toast; tests read `LintCounts::restarts`.
- `LintSource::running` waits for a server that is busy with a lint. A test that holds a lint uses `lint.pids()`.
- oxlint waits for `tsgolint` with no limit and serves nothing meanwhile. On a type-aware lint timeout `OxlintSource` kills the server's process group (tsgolint too), lints that root without type-aware rules until the settings change, and toasts once (`LintSource::take_notices`). `HARWEX_LINT_TIMEOUT_MS` shortens the 30 s in tests.
- typescript-eslint guesses a missing `tsconfigRootDir` from every config file that read `tseslint.configs` in the process. With two package configs loaded in one ESLint process, files of a config without `tsconfigRootDir` fail with "multiple candidate TSConfigRootDirs". `eslint_server.js` narrows the guess to the linted config before each lint; keep that.
- typescript-eslint builds one-shot programs (no updates after edits) when it infers a CLI run (`CI=true`, argv names the eslint bin). The ESLint server sets `TSESTREE_SINGLE_RUN=false`.
- `Ide::open_file` settles, so it waits out a first lint. A test that watches a cold start (the "ESLint: loading" label) opens the file with `state_mut().open_location` instead.
- `Context::read_response` drops the focus of a widget that a press of this frame missed. Call it only on frames without a press (see `focused_tool_side`).
- A `ScrollArea` is at least 64 pt tall by default (`min_scrolled_height`), even in a smaller space. A short list then paints over the widgets below it. Set `min_scrolled_height(0.0)` (see the Commit tree).
- `TopBottomPanel::show_inside` replaces the clip with the panel rect. Inside a `ScrollArea` the panel then paints outside the viewport. Give the content the outer clip back and no panel fill (see `git::changes::changes_body`).
- egui's context lock is not re-entrant. A ctx call (`ui.ctx().options`, `ui.fonts`, `ctx.layer_id_at`, ...) inside a `ui.input`, `ctx.input`, `fonts` or `memory` closure deadlocks the frame, and the test hangs with no output. Read the input first, close the closure, then call the ctx.
- A `ScrollArea` takes its parent's layout. Inside `ui.horizontal_top` its rows sit side by side; give the list `allocate_ui_with_layout(.., Layout::top_down(..))`.
- A new `egui::Area` spends its first frame in an invisible sizing pass that still takes clicks, sized `default_size` (else 600x400 from its position). Give a popup that opens next to a click target its known size (`default_size`), or the second press of a double click lands on the popup (`breadcrumbs::show_popup`).
- egui's floating scrollbar grows from `floating_width` to `bar_width` (10 pt) while the pointer is over it. In a short area (the 24 pt status bar) it then covers the content. Set both widths to the same small value.
- `scroll_area::State::load` needs the area's own id: `ui.make_persistent_id(Id::new(salt))`. egui hashes the salt into an `Id` first, so `make_persistent_id(salt)` finds nothing.
- A horizontal-only `ScrollArea` ignores a plain vertical wheel unless the style sets `always_scroll_the_only_direction` (see `breadcrumbs::bar`).
- On macOS a held Cmd sets both `mac_cmd` and `command`, so `i.modifiers == Modifiers::COMMAND` is false. Test exact modifiers with `command_only()` (see `tool_window_keys`).
- egui's keyboard zoom takes ⌘0, ⌘+ and ⌘- in `end_pass`, after `update`. A shortcut consumed during the frame wins (⌘0 is Commit).
- `ScrollArea::show_rows` reads `item_spacing.y` from the outer `Ui`, before its closure runs. Rows that must touch set the spacing to 0 before `show_rows`, not inside it.
- A press on a popup `Area` over the editor drops the editor's focus in that same frame, before the popup's row sees the press. A popup that closes on focus loss keeps itself while the pointer is pressed inside its last rect and picks a row on the press (`lang::npm::pointer_on`).
- `Ide::snapshot` fails when one more frame moves any widget ("the layout still moves without a repaint request"). Fix the layout. Extra settle frames only hide the drift.
