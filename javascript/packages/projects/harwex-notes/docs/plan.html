Harwex Notes Build Plan

A local web workbench over one folder on disk: a JetBrains-style file tree on the left, a tabbed editor on the right that switches its surface to match the file it opened — Excalidraw scenes, Markdown, plain text, and rendered HTML.

rspackreact 19@preact/signals-reacttRPC 11zod 4node 24 native TSexcalidraw 0.18codemirror 6

01 What gets built

One workspace package holding both halves of the app. The backend exposes a single folder on disk (the notes root) over a typed tRPC API. The frontend browses that folder and edits its files in place. No database, no auth, no cloud — the filesystem is the model.

In scope

  • Lazy file tree: expand/collapse, keyboard navigation, file-kind icons.
  • Tab bar: multiple open files, dirty marker, close, middle-click close.
  • .excalidraw → live Excalidraw canvas, autosaved.
  • .md → CodeMirror + rendered preview toggle.
  • .txt and unknown text → CodeMirror plain.
  • .html → sandboxed iframe render, with a source toggle.
  • Explicit save (Cmd/Ctrl+S) with stale-write detection.

Out of scope for the prototype

  • Create / rename / delete / move in the tree (read + write existing files only).
  • Filesystem watching and external-change push.
  • Search, git integration, multi-root workspaces.
  • Excalidraw image (binary) files and library support.
  • Relative asset resolution inside the HTML preview.

05 The contract

One file both halves import. Every path crossing the wire is workspace-relative and POSIX-separated; the server is the only place that ever sees an absolute path.

// shared/contract.ts
import { z } from "zod";

const relPathSchema = z
  .string()
  .max(1024)
  .refine((value) => !value.startsWith("/"), "Path must be workspace-relative.")
  .refine((value) => !value.includes("\0"), "Path must not contain NUL.")
  .refine((value) => !value.split("/").includes(".."), "Path must not escape the root.");

const fileKindSchema = z.enum(["excalidraw", "markdown", "text", "html"]);

const entrySchema = z.object({
  name: z.string(),
  path: relPathSchema,
  type: z.enum(["dir", "file"]),
  fileKind: fileKindSchema.nullable(),
  size: z.number().int().nonnegative(),
  mtimeMs: z.number(),
});

const listInputSchema = z.object({ path: relPathSchema });
const readInputSchema = z.object({ path: relPathSchema });
const writeInputSchema = z.object({
  path: relPathSchema,
  text: z.string().max(16 * 1024 * 1024),
  baseMtimeMs: z.number(),
});

export type Entry = z.infer<typeof entrySchema>;
export type FileKind = z.infer<typeof fileKindSchema>;
export {
  entrySchema,
  fileKindSchema,
  listInputSchema,
  readInputSchema,
  relPathSchema,
  writeInputSchema,
};
ProcedureInputReturnsBehaviour
fs.list{ path }{ entries: Entry[] }One directory level only — the tree expands lazily. Directories first, then files, both case-insensitive by name.
file.read{ path }{ path, fileKind, text, mtimeMs }UTF-8 text. Refuses files over 8 MB and anything whose first 8 KB contains a NUL byte.
file.write{ path, text, baseMtimeMs }{ mtimeMs }Rejects with CONFLICT when the file’s current mtime differs from baseMtimeMs. Writes to a temp file in the same directory, then renames.

06 Server

Path containment is the whole security model

The server hands out file contents by relative path, so the only thing between it and the rest of the disk is one function. It gets its own unit test before anything else is built.

// server/workspace.ts
async function resolveInRoot(root: string, relPath: string): Promise<string> {
  const absolute = path.resolve(root, relPath);
  const realRoot = await fs.realpath(root);
  const realTarget = await realpathOfNearestExisting(absolute);
  if (realTarget !== realRoot && !realTarget.startsWith(realRoot + path.sep)) {
    throw new TRPCError({ code: "FORBIDDEN", message: "Path escapes the workspace root." });
  }
  return absolute;
}
  • Zod rejects .. segments, absolute paths, and NUL before this runs. resolveInRoot is the second line: it catches symlinks pointing out of the root, which no amount of string checking can.
  • realpathOfNearestExisting walks up to the closest existing ancestor, so a write to a not-yet-created file is still checked.
  • Bound to 127.0.0.1 only, on a fixed port (NOTES_API_PORT, default 5788) because the rspack proxy needs a stable target. CORS stays off; the dev server proxies same-origin.

Execution

Node 24 runs .ts directly, so node server/index.ts is the whole start command and nothing is compiled. That constrains the server code to erasable TypeScript — no enums, no parameter properties, no namespaces — which tsconfig.server.json enforces with erasableSyntaxOnly. Relative imports carry the .ts extension, matching agentic-learn-harness.

07 Frontend

State: three signal stores, no context, no reducers

StoreHoldsOwns
tree-storechildrenByPath, expanded, loading, selectedPathCalls fs.list on first expand and caches the result; nothing re-lists until the user collapses and reopens.
tabs-storeopenPaths, activePathOpen, activate, close, and the “is this tab dirty” lookup. Reopening an open file just activates its tab.
doc-storedocsByPath: { status, fileKind, savedText, draftText, baseMtimeMs, error }Load, edit, save, conflict state. One entry per open tab, dropped on close.

Dirty is derived, not stored: draftText !== savedText in a computed signal per tab. The tab bar reads that computed and nothing else.

EditorHost keys each editor by path, so switching tabs unmounts the previous editor instead of feeding it a new document. That is deliberate: both Excalidraw and CodeMirror hold internal state that is far more annoying to reconcile than to rebuild.

Tree behaviour, JetBrains-shaped

  • Single click selects, Enter or double click opens a file; on a directory both toggle expansion.
  • ArrowDown / ArrowUp move through visible rows, ArrowRight expands, ArrowLeft collapses or jumps to the parent.
  • Indent guides at 14 px per level, chevrons only on directories, kind icons as inline SVG.
  • Roving tabindex on rows with role="tree" / role="treeitem", so the whole panel is one tab stop.

08 The four editors

excalidraw.excalidraw<Excalidraw> with initialData parsed from the fileAutosave, 800 ms debounce, skipped when getSceneVersion is unchanged

html.html .htm<iframe srcdoc>, sandboxed; a toggle swaps in CodeMirror with html()Explicit Cmd/Ctrl+S, preview re-renders on save

Excalidraw is the one autosaving editor because it has no save affordance of its own — the user draws, and drawing is the edit. Everything else has a visible buffer and a cursor, so it saves on command like any editor.

Writing a scene goes through Excalidraw’s own serializeAsJSON(elements, appState, files, "local") rather than a hand-rolled JSON shape, which keeps the file openable on excalidraw.com.

09 Traps found while planning

blocker Excalidraw CSS has no default export condition

Its package.json maps ./index.css to production and development only. A plain import "@excalidraw/excalidraw/index.css" fails to resolve under rspack’s default conditions. Fix: resolve.conditionNames: ["...", "production"] in the rspack config.

blocker Excalidraw fonts come from a CDN

Left alone, the bundle fetches its woff2 files from unpkg at runtime. Set window.EXCALIDRAW_ASSET_PATH = "/" in index.html and copy @excalidraw/excalidraw/dist/prod/fonts into the output with CopyRspackPlugin.

care allow-scripts plus allow-same-origin is not a sandbox

Granting both lets the framed document reach back into the parent. The HTML preview uses sandbox="allow-scripts" alone, which leaves the frame on an opaque origin. Consequence: relative src/href inside previewed HTML will not resolve — accepted, and listed as out of scope.

care CodeMirror must not be re-rendered by React

Create the EditorView once in an effect keyed on the path, and dispatch changes into it. Rebuilding the view from React state on every keystroke loses selection and undo history.

care Signals need useSignals()

@preact/signals-react tracks reads only inside components that call useSignals() from @preact/signals-react/runtime. Miss it and the component simply stops updating — silently. Repo precedent: every signal-reading component in ostrov-prototype-v2 calls it first.

care Excalidraw onChange fires on pointer move

Debounce, and compare getSceneVersion() before writing. Otherwise a single drag produces hundreds of writes to the file.

setup Two ports, one fixed

The web dev server takes port: 0 like everything else in the repo, so a forgotten run can never answer with a stale bundle. The API cannot: the proxy target must be a known number, so it pins 5788 and fails loudly if that port is taken.

setup No StrictMode

Double-invoked effects would mount two Excalidraw instances and two EditorViews per tab. Matching ostrov-prototype-v2, the root renders <App /> directly.

Manual walk, run once per milestone from M3 on:

  1. Expand notes-root to a nested folder, open welcome.md, type, Cmd+S, confirm the file changed on disk.
  2. Open scratch.excalidraw, draw, switch to another tab and back — the drawing survived.
  3. Open demo.html, see it rendered, toggle to source, edit, save, see the render update.
  4. Edit a file outside the app while its tab is dirty, then save — the conflict banner appears instead of a silent overwrite.
  5. Open four tabs, close the middle one — focus lands on a neighbour, not on nothing.

12 After the prototype

  • Tree mutations — create, rename, delete, drag-move, with the same containment check on both ends of a move.
  • Watching — fs.watch behind a tRPC subscription over SSE, so external edits refresh the tree and warn open tabs.
  • Real HTML preview — serve the notes root read-only over HTTP and point the iframe at a URL, so relative assets resolve.
  • Excalidraw files — embedded images, which means binary payloads and a second read/write path.
  • Search — content search across the root, which is where a real index starts to earn its place.
