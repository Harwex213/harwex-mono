- **absolute_redirect**: при `on` в заголовке `Location` стоит полный URL со схемой, хостом и портом. При `off` там только путь.
- **aio**: включает асинхронное чтение файлов (`on` или `threads`), чтобы диск не блокировал воркер.
- **aio_write**: при `aio threads` разрешает асинхронно писать во временные файлы, например при проксировании.
- **alias**: заменяет совпавшую часть URI указанным путём. `root`, наоборот, дописывает весь URI к пути.
- **auth_delay**: добавляет задержку перед ответом 401 при неудачной авторизации. Это защищает от атак по времени ответа.
- **chunked_transfer_encoding**: включает или выключает chunked-кодирование ответа в HTTP/1.1.
- **client_body_buffer_size**: размер буфера в памяти для тела запроса. Если тело больше, nginx пишет его во временный файл.
- **client_body_early_read**: я точно не помню. Судя по названию, nginx начинает читать тело запроса заранее, до того как модуль его запросит. Лучше проверить в доке.
- **client_body_in_file_only**: тело запроса всегда пишется в файл. При `on` файл остаётся после запроса, при `clean` удаляется. Полезно для отладки и `$request_body_file`.
- **client_body_in_single_buffer**: тело запроса хранится в одном буфере. Это нужно, чтобы `$request_body` работала надёжно.
- **client_body_temp_path**: каталог для временных файлов с телами запросов, с уровнями подкаталогов.
- **client_body_timeout**: таймаут между двумя чтениями тела запроса, а не на всё тело. При превышении клиент получает 408.
- **client_header_buffer_size**: буфер для заголовков запроса, по умолчанию 1k. Если заголовки не влезли, используются `large_client_header_buffers`.
- **client_header_timeout**: таймаут на чтение всех заголовков запроса. При превышении клиент получает 408.
- **client_max_body_size**: максимальный размер тела запроса, по умолчанию 1m. Больше — ответ 413, `0` снимает лимит.
- **connection_pool_size**: пул памяти на одно соединение. Менять почти никогда не нужно.
- **default_type**: MIME-тип для файлов, которых нет в `types`. Обычно это `application/octet-stream`.
- **directio**: файлы больше указанного размера читаются через O_DIRECT, мимо page cache. Подходит для огромных файлов.
- **directio_alignment**: выравнивание для `directio`, по умолчанию 512. Для XFS нужно 4k.
- **disable_symlinks**: правила для симлинков при открытии файлов: `off`, `on` или `if_not_owner`, плюс опция `from=`.
- **early_hints**: задаёт условия, при которых nginx передаёт клиенту ответ 103 Early Hints. Так браузер раньше начинает грузить ресурсы.
- **error_log_tag**: здесь я не уверен. Судя по названию, директива задаёт метку для записей в error_log, чтобы различать их в общем логе.
- **error_page**: своя страница или URI для кодов ошибок. Можно подменить код ответа (`=200`) или сделать редирект.
- **etag**: включает заголовок ETag для статических файлов.
- **http**: корневой блок всей HTTP-конфигурации.
- **if_modified_since**: способ сравнения `If-Modified-Since`: `off`, `exact` (по умолчанию) или `before`.
- **ignore_invalid_headers**: отбрасывает заголовки с недопустимыми именами.
- **internal**: location доступен только для внутренних переходов (error_page, try_files, X-Accel-Redirect). Снаружи туда отдаётся 404.
- **keepalive_disable**: отключает keep-alive для проблемных браузеров (`msie6`, `safari`).
- **keepalive_min_timeout**: директива новая, деталей я точно не помню. Судя по всему, это минимальное время жизни keep-alive соединения: раньше этого срока nginx его не закроет, даже если не хватает соединений.
- **keepalive_requests**: сколько запросов можно отправить по одному keep-alive соединению (по умолчанию 1000).
- **keepalive_time**: максимальное общее время жизни keep-alive соединения (по умолчанию 1h).
- **keepalive_timeout**: сколько держать простаивающее keep-alive соединение (по умолчанию 75s). Второй параметр задаёт заголовок `Keep-Alive: timeout=`.
- **large_client_header_buffers**: количество и размер больших буферов для длинных заголовков. Длинная строка запроса даёт 414, длинный заголовок даёт 400.
- **limit_except**: внутри location ограничивает доступ для всех методов, кроме перечисленных. `GET` включает и `HEAD`.
- **limit_rate**: ограничивает скорость отдачи ответа на один запрос. Лимит можно менять через `$limit_rate`.
- **limit_rate_after**: `limit_rate` начинает действовать только после указанного объёма отданных данных.
- **lingering_close**: перед закрытием соединения nginx дочитывает данные от клиента. Так клиент получает ответ, а не RST.
- **lingering_time**: максимальное время такого дочитывания (по умолчанию 30s).
- **lingering_timeout**: сколько ждать следующую порцию данных при дочитывании (по умолчанию 5s).
- **listen**: адрес, порт и опции сокета: `ssl`, `default_server`, `reuseport`, `backlog` и другие.
- **location**: блок настроек для URI по префиксу или регулярному выражению.
- **log_not_found**: писать ли в error_log о ненайденных файлах.
- **log_subrequest**: писать ли подзапросы в access_log.
- **max_headers**: максимальное количество заголовков в одном запросе.
- **max_ranges**: сколько диапазонов разрешено в заголовке `Range`. `0` отключает byte-range.
- **merge_slashes**: склеивает несколько `//` в URI в один слэш.
- **msie_padding**: добавляет к страницам ошибок заполнитель для старого IE. Иначе IE показывает свою страницу вместо ответа сервера.
- **msie_refresh**: для старого IE отдаёт страницу с meta refresh вместо обычного редиректа.
- **open_file_cache**: кэш дескрипторов файлов, их размеров, дат изменения и ошибок поиска.
- **open_file_cache_errors**: кэшировать ли ошибки вроде «файл не найден».
- **open_file_cache_min_uses**: сколько обращений к файлу нужно за время `inactive`, чтобы запись осталась в кэше.
- **open_file_cache_valid**: как часто перепроверять записи кэша (по умолчанию 60s).
- **output_buffers**: количество и размер буферов для чтения ответа с диска, когда sendfile выключен.
- **port_in_redirect**: указывать ли порт в абсолютных редиректах.
- **postpone_output**: nginx копит в буфере минимум столько байт и только потом отправляет клиенту (по умолчанию 1460).
- **read_ahead**: подсказывает ядру читать файл заранее. Работает в основном на FreeBSD.
- **recursive_error_pages**: разрешает срабатывать `error_page` во время обработки другого `error_page`.
- **request_pool_size**: пул памяти на один запрос. Менять почти никогда не нужно.
- **reset_timedout_connection**: при таймауте соединение закрывается через RST, и память сокета освобождается сразу.
- **resolver**: DNS-серверы для резолва имён во время работы, например для `proxy_pass` с переменными.
- **resolver_timeout**: таймаут DNS-запроса.
- **root**: корневой каталог для файлов. Итоговый путь — это `root` плюс URI.
- **satisfy**: при `all` запрос должен пройти все проверки (allow/deny и auth). При `any` хватает одной.
- **send_lowat**: задаёт SO_SNDLOWAT для сокета. Имеет смысл только на FreeBSD.
- **send_timeout**: таймаут между двумя операциями записи клиенту. Это не таймаут на весь ответ.
- **sendfile**: отдаёт файлы через системный вызов sendfile(), без копирования в память процесса.
- **sendfile_max_chunk**: максимум данных за один вызов sendfile (по умолчанию 2m). Так быстрый клиент не занимает воркер целиком.
- **server**: блок виртуального сервера.
- **server_name**: имена хостов для выбора нужного `server`: точные, wildcard и regex.
- **server_name_in_redirect**: в редиректах брать основной `server_name` вместо заголовка `Host`.
- **server_names_hash_bucket_size**: размер корзины хэш-таблицы имён серверов. Увеличивать, когда nginx ругается на старте.
- **server_names_hash_max_size**: максимальный размер этой хэш-таблицы. Повод увеличить тот же.
- **server_tokens**: показывать ли версию nginx в заголовке `Server` и на страницах ошибок.
- **subrequest_output_buffer_size**: буфер для ответа подзапроса, когда этот ответ хранится в памяти.
- **tcp_nodelay**: включает TCP_NODELAY, то есть отключает алгоритм Нейгла. Мелкие пакеты уходят без задержки.
- **tcp_nopush**: вместе с sendfile включает TCP_CORK. Тогда заголовки и начало файла уходят одним полным пакетом.
- **try_files**: проверяет файлы по порядку и отдаёт первый найденный. Если ничего нет, срабатывает последний аргумент: URI или `=код`.
- **types**: таблица соответствия MIME-типов расширениям файлов.
- **types_hash_bucket_size**: размер корзины хэш-таблицы `types`.
- **types_hash_max_size**: максимальный размер хэш-таблицы `types`.
- **underscores_in_headers**: разрешает подчёркивания в именах заголовков. По умолчанию такие заголовки отбрасываются.
- **variables_hash_bucket_size**: размер корзины хэш-таблицы переменных.
- **variables_hash_max_size**: максимальный размер хэш-таблицы переменных.
