01The loop

The tool exists to shorten one cycle: you see something wrong on screen, and a file changes. Every decision below serves that cycle. The tool runs in development only, because the component names it reads exist only in a development React build.

  1. Pick. Cmd/Ctrl+Shift+A enters pick mode. Hover paints a rect with the component name. A click selects the nearest component boundary. [ and ] walk the fiber.return chain outward and back. Esc cancels.
  2. Capture. The client builds a capped payload and crops the picked node to a PNG. Two other capture modes exist: a freeform drag region, and the full viewport.
  3. Send. The panel writes your instruction, attaches the payload, and sends it over the WebSocket. The server feeds it into a streaming-input session as a text block plus an image block.
  4. Work. The agent reads files, then edits them. Writes inside the app's src/ are approved automatically. Everything else stops at a prompt in the panel.
  5. Repaint. rspack recompiles and HMR updates the page. You are looking at the result within about a second.
  6. Verify. The agent calls screenshot(), get_selection() and console_errors() to check its own work before it reports back.
  7. Undo, if needed. Any user message in the transcript offers a rewind, which reverts the file changes made since that message.

02Packages

Three workspace packages sit under the existing empty packages/infrastructure/visual-agent/. The directory names stay short, because the parent directory already namespaces them. All three ship raw TypeScript with no build step, which is what @hw/vschema already does.

DirPackageOwnsRuntime deps
protocol/ @hw/visual-agent-protocol Types only. The message union, PROTOCOL_VERSION, and the pick-payload shape. Exported as "exports": "./exports.ts". None
client/ @hw/visual-agent-client Picker, capture, error buffer, and the floating panel in a shadow root. Reads fibers off the __reactFiber$* key on DOM nodes, so it holds no React dependency and works in any app that mounts React. @hw/signals, html-to-image 1.11.13
server/ @hw/visual-agent-server WebSocket server, session registry, permission fence, and the in-process MCP server. Runs as node src/index.ts on Node 24, like @hw/colony-sim-v1-backend. ws 8.18.2, @anthropic-ai/claude-agent-sdk 0.3.237, playwright 1.61.1

Versions are exact. The repo sets defaultSemverRangePrefix: "", and Playwright is held at 1.61.1 to match the chromium-1228 build already on disk.

How it enters an app

// src/main.tsx, three lines, greppable, no build config
if (process.env.NODE_ENV !== "production") {
  void import("@hw/visual-agent-client").then((module) => {
    module.mount();
  });
}

A production build drops the whole branch, so the client cannot ship.

04Decision record

Thirty-six branches, resolved in order, with the reason each one won. The reason matters more than the decision, because the reason is what tells you whether a later change is safe.

Product shape

BranchDecisionWhy, and what lost
CouplingGeneric core, optional adapterThe core needs only the DOM and fibers, so any React app in the monorepo can use it. An app that has scenarios and a store registers an adapter and gets richer context. A version coupled to one app would die with that experiment.
SurfaceIn-browser panel, server runs the SDKThe panel is the chat. This is the only arrangement where a pick becomes a message with no copy and paste. A terminal-only variant needs no SDK at all, but you keep switching windows and you lose spawning.
Edit loopAgent edits files, HMR shows itThe loop closes with no human step, which is the whole point. Safety comes from git and from rewind, not from a gate. A propose-a-diff flow adds a click to every iteration.
Spawn modelN concurrent sessions, soft guardEach spawn is one session with its own id and its own transcript. All share one cwd. The panel warns when two live sessions have touched one file. A hard lock denies an Edit mid-turn, which confuses the agent more than the warning confuses you.
v1 scopeFull design, one milestoneEverything in this record gets built before the tool is used in anger.
DocsREADMEs, skill rewrite, root pointerThree coupled packages with a wire protocol need the coupling written down. frontend-human-in-the-loop gets the workflow appended, and its philosophy section stays.

Server and agent

BranchDecisionWhy, and what lost
TransportWebSocket, one socket per tabcanUseTool and interrupt() both need server-to-client requests, not a one-way push stream. Sessions multiplex over the one socket by id, and request pairs carry a correlation id.
SecurityLoopback bind, strict Origin allowlistAny page you visit can open a socket to localhost, and this server edits files. A browser sets Origin on the handshake and page script cannot forge it, so the allowlist is the defence. It costs nothing in use.
PermissionsAuto-approve inside declared rootspermissionMode: "default", reads on the allowlist, and a canUseTool callback that resolves the path. Fast where it is safe, gated where it is not. bypassPermissions was rejected: a stray agent would rewrite yarn.lock or .claude/ and you would find out at git status.
Agent cwdRepo rootEverything is visible, including the root conventions file and every sibling package. The costs are accepted deliberately: greps are noisy across four language trees, and worktrees/ is in scope, so the write fence is doing real work. The brief names the app package as the work area up front.
Agent briefPreset, setting sources, short briefsystemPrompt: { type: "preset", preset: "claude_code", append } with settingSources: ["user", "project", "local"], so javascript/CLAUDE.md actually loads. A hand-written prompt is cheaper and would have the agent writing single quotes and unbraced if statements into a repo that forbids both.
Agent toolsscreenshot, get_selection, console_errorsThree tools, each closing one blind spot: it cannot see the page, it cannot re-read the pick, it cannot see a thrown error. Click, type and eval were rejected, because an agent driving your live tab while you watch is hostile, and scenarios already reach any state.
TranscriptStreamed text, collapsed tool timelineincludePartialMessages: true so text arrives live. Each tool call is one line that expands. A forty-second silent turn reads as broken, and you cannot tell when to interrupt.
Spawn seedOptional pick, free text, model selectorA pick attaches when one is active but is not required, because "add a dark theme" has no pick. Model defaults to claude-opus-5 per session, since a colour tweak and a refactor do not deserve the same spend. No prompt templates: they go stale and you type faster.
UndoPer-message rewindFiles()The SDK reverts file changes made since a given message, with dryRun to preview. This is what makes a loop with no approval gate defensible. Git reverts by file, so it cannot separate a good first edit from a bad third one.
Mid-turn pickQueue it, with an explicit InterruptStreaming input queues messages in order, which is exactly the desired behaviour. Auto-interrupting would silently discard a turn, including edits already on disk.

Protocol, lifecycle and process

BranchDecisionWhy, and what lost
PackagesThree, with a types-only protocolMirrors @hw/colony-sim-v1-protocol. The browser package never pulls in a node dependency, and the server never pulls in React.
Layoutclient/, server/, protocol/The parent directory namespaces them, so a repeated prefix would be noise. packages/**/* matches at this depth, proven by colony-sim-v1-backend five levels down.

ProtocolVersion in handshake, sessions globalA mismatch is refused with a message naming the fix, never a confusing runtime failure. An HMR-reloaded page against a stale server is the normal case. Sessions are server-global so any tab attaches to any of them.

05Pick payload

This type is the heart of the tool. It has to identify a component well enough that a grep finds it on the first try, and stay small enough that it does not crowd out the conversation. Every collection is capped, and every cap reports itself, so the agent knows when it is looking at a truncated view.

type PickPayload = {
  readonly kind: "element" | "region" | "viewport";

  // Identity. componentChain walks fiber.return outward, names read from
  // fiber.type.name ?? fiber.type.displayName, with _debugOwner as a tiebreaker.
  readonly componentChain: readonly string[];
  readonly tagName: string;
  readonly className: string;
  readonly domPath: string;
  readonly siblingIndex: number;

  // Reserved. Stays undefined until a build-time transform exists, so adding
  // one later is not a breaking protocol change.
  readonly sourceLocation?: {
    readonly file: string;
    readonly line: number;
    readonly column: number;
  };

  // Content and geometry.
  readonly text: string;                      // trimmed, capped
  readonly props: Readonly<Record<string, unknown>>;  // depth <= 2, fns as "[fn]"
  readonly rect: { x: number; y: number; width: number; height: number };
  readonly computedStyles: Readonly<Record<string, string>>;  // ~20 whitelisted

  // Capture.
  readonly image: { readonly dataUrl: string; readonly scale: number };

  // Present only when the app registered an adapter.
  readonly app?: {
    readonly scenarioName?: string;
    readonly scenarios?: readonly string[];
    readonly state?: unknown;
  };

  readonly truncated: readonly string[];      // e.g. ["props.tables", "text"]
};

The whitelist covers box, font, colour and layout properties. A twenty-property subset is legible; the full computed style is nine hundred lines of noise.

Adapter contract

type VisualAgentAdapter = {
  readonly getStateSnapshot?: () => unknown;   // JSON-safe view-model
  readonly getScenarioName?: () => string;
  readonly listScenarios?: () => readonly string[];
  readonly describeApp?: () => string;         // appended to the session brief
};

function registerVisualAgentContext(adapter: VisualAgentAdapter): void;

Read-only by construction. In a signals app, getStateSnapshot() is the most compressed available answer to "why does it look like this".

06Protocol

One socket per browser tab. Every frame carries a type discriminant, and every frame after the handshake carries a sessionId. Request and response pairs carry a correlationId, because two of them travel from server to client.

client → serverhelloprotocolVersion, origin, devUrl from location.origin, adapter capability flags
server → clientwelcomeAccepted version, live session list, declared write roots, app package path
server → clientversionRefusedExpected version and the remedy to show in the panel
client → serverspawnOptional PickPayload, instruction text, model
client → serversendsessionId, optional PickPayload, instruction text
client → serverattachsessionId, to receive the replayed transcript buffer
client → serverinterruptsessionId
client → serverrewindsessionId, userMessageId, dryRun
client → serversetModelsessionId, model id
server → clienttranscriptMapped SDK messages: text deltas, tool calls, tool results, thinking, result
server → clientsessionStateidle, working or queued, plus files touched and token usage
server → clientconflictWarningTwo live sessions have touched one file
server → clientpermissionRequestcorrelationId, tool name, input, and the reason the fence did not auto-approve

server → clienterrorsRequestcorrelationId, raised by console_errors()

The selection lives on the connection, not on the session, and is snapshotted into the message at send time. Two tabs therefore never fight over one pick.

07Agent session

Images and interrupts both require streaming input mode, so single-message mode is not an option: it cannot attach an image at all. Each session is one long-lived query() whose prompt is an async generator the server pushes into.

const session = query({
  prompt: pushableMessageStream,          // AsyncIterable<SDKUserMessage>
  options: {
    cwd: repoRoot,
    model: requestedModel,
    systemPrompt: { type: "preset", preset: "claude_code", append: brief },
    settingSources: ["user", "project", "local"],
    permissionMode: "default",
    allowedTools: ["Read", "Grep", "Glob"],
    canUseTool: fenceWrites(declaredRoots),
    mcpServers: { visualAgent: inProcessServer },
    includePartialMessages: true,
    resume: knownSessionId,
  },
});

A pick becomes one user message holding a text block and an image block.

What the brief says

The brief is short and situational, and it carries three load-bearing instructions. It names the app package path as the work area, because the cwd is the repo root and a bare grep spans four language trees. It says the dev server is already running, so the agent never starts one. It requires console_errors() and screenshot() before any claim of being done, because the client never volunteers an error and nothing else will tell the agent that the page went white.

08Fence and undo

The fence

Two independent checks stand between a web page and your repository. The socket binds to 127.0.0.1 and refuses any handshake whose Origin is not the declared dev URL. Then canUseTool resolves every write path and auto-approves only what sits inside the launching app's src/. Everything else, and every Bash call, stops at a prompt in the panel.

The cwd is the repo root, so worktrees/, unity/ and the memory directory are all readable. The write fence is the only thing keeping them intact, which is why it is a resolved path check and not a prefix string match.

The undo

Every user message in the transcript offers a rewind. It calls query.rewindFiles(userMessageId, { dryRun: true }) first and shows what would change, then commits on confirmation. This reverts by turn rather than by file, so a good first edit survives while a bad third one goes away. Git stays available underneath, and does not need to be the first resort.

09Consumer-app change

harness.html hardcodes data-screenshot="true" on <html>, and the panel refuses to mount when that flag is set. Left alone, the panel would never appear on the harness, which is where every interesting UI state already lives. Three files move the flag from the template into the entry.

FileChange
harness.htmlDrop data-screenshot="true" from the <html> tag.
src/harness.tsxSet the attribute before mount when the URL carries screenshot=1.
tests/helpers.tsAdd screenshot=1 to the harness URL the tests open.
Baseline guarantee

Test runs set the flag exactly as they do today, before first paint, so all twenty-four committed baselines stay byte-identical. Dev browsing gets the panel and live animations, which matters because that same flag kills every transition, and a dead transition is useless when the transition is the thing you are polishing.

10Watch list

Four things are known to be fragile. None of them blocks the build, and each has a decided response.

RiskResponse
Grep ambiguity Two components sharing a name send the agent to the wrong file. The payload carries a DOM path, sibling index and text to break the tie. If it still misses often, the escape hatch is the build-time data-va-src transform, and sourceLocation is already reserved in the payload so adding it breaks nothing.
Canvas fidelity html-to-image mis-renders backdrop-filter, some web fonts and 3D transforms, which are exactly the properties worth iterating on. The Playwright-backed screenshot() tool is the escape hatch, and the brief says to reach for it when the crop looks wrong.
Floating panel Two guards, both easy to forget. The shadow host must be filtered out of every capture, or the tool photographs itself. The window's backdrop must not take pointer events, or it swallows picks.
Development-only reads Component names and _debugOwner exist only in a development React build. A production bundle has neither, and the guarded import means the client is not there to try. This is a property of the design, not a defect to fix.

11Build order

This is a real sequence, because each step is the first thing testable after the one before it.

  1. protocol/. The message union, the payload type, the version constant. Nothing depends on anything.
  2. server/ with an injected fake query, plus its node:test suite. Permission round trip, interrupt, queueing, reconnect and replay, all without an API call.
  3. Client picker, fiber walker and payload builder, with unit tests on the capping and truncation reporting.
  4. Capture: element crop, drag region, viewport, the 1568px cap, and the shadow-host filter.
  5. Panel: floating window, transcript rendering, permission prompts, status dot.
  6. In-process MCP server: screenshot(), get_selection(), console_errors().
  7. Spawn, model selector, rewind UI, conflict warning, and the adapter.
  8. The three-file consumer change, then one Playwright test proving pick to payload end to end.
  9. Three READMEs, the frontend-human-in-the-loop rewrite, and the root README pointer.
