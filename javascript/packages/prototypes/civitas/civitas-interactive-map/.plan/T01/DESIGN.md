## 3. `rspack.config.mjs` — exact content

Byte-identical to `../civitas-map/rspack.config.mjs` except the `devServer.static`
comment. Full content:

```js
import { rspack } from "@rspack/core";

export default {
  entry: {
    main: "./src/main.tsx",
  },
  output: {
    filename: "[name].[contenthash].js",
    cssFilename: "[name].[contenthash].css",
    clean: true,
  },
  resolve: {
    extensions: ["...", ".ts", ".tsx"],
  },
  module: {
    parser: {
      "css/auto": {
        namedExports: false,
      },
    },
    generator: {
      "css/auto": {
        exportsConvention: "camel-case-only",
      },
    },
    rules: [
      {
        test: /\.tsx?$/,
        loader: "builtin:swc-loader",
        options: {
          jsc: {
            parser: {
              syntax: "typescript",
              tsx: true,
            },
            transform: {
              react: {
                runtime: "automatic",
              },
            },
          },
        },
        type: "javascript/auto",
      },
      {
        test: /\.css$/i,
        type: "css/auto",
      },
    ],
  },
  plugins: [
    new rspack.HtmlRspackPlugin({
      template: "./index.html",
    }),
  ],
  devServer: {
    hot: true,
    // Free port picked by the OS, as everywhere else in the repo: a fixed port
    // lets a forgotten server from an earlier run answer with a stale bundle.
    port: 0,
    // The map assets are served, not bundled. T02 decides how the production
    // build gets them; until then dev can read them from `/assets/...`.
    static: {
      directory: "./assets",
      publicPath: "/assets",
    },
  },
};
```

Constraints that must not drift:

- `namedExports: false` + `exportsConvention: "camel-case-only"` is what makes
  `import styles from "./x.module.css"; styles.someClass` work. Both are required.
- `type: "javascript/auto"` on the ts rule is required; without it rspack treats
  the emitted module as ESM-strict and the JSX runtime import breaks.
- `clean: true` wipes `dist/` on every build.
- No `mode` key: rspack CLI defaults to `production` for `build` and
  `development` for `serve`.

Rules applied here, and why the placeholder looks the way it does:

  the runtime.

## 13. Edge cases and failure modes

1. **`yarn install` reports the workspace was not picked up.** Cause: a syntax
   error in `package.json`, or the file was written somewhere other than the
   package root. Check with `yarn workspaces list | grep civitas-interactive-map`.
2. **A caret sneaks into a version.** `defaultSemverRangePrefix: ""` only affects
   `yarn add`; hand-written `^` is kept verbatim and would drift the resolution
   away from the reference. Grep the finished `package.json` for `^`.
3. **`tsc` fails on `styles` being untyped.** `src/env.d.ts` is missing from
   `include` — it is not; `include: ["src"]` covers it. If it still fails, the
   file is outside `src/`.
4. **`tsc` fails with "Cannot find module '@rspack/core/module'".** `@rspack/core`
   was not installed, i.e. `yarn install` did not run or ran in the wrong root.
5. **Build succeeds but `dist/index.html` has no script tag.** `HtmlRspackPlugin`
   template path is wrong. It resolves against the rspack context, which defaults
   to the package root, so `"./index.html"` is correct.
6. **Build tries to bundle `assets/map.png`.** Only possible if something in `src`
   imports it. Nothing should. Bundle size is a signal: `dist` must be well under
   1 MB.
7. **`yarn test` errors instead of reporting 0 tests.** Only if the glob is
   unquoted and the shell expands it. Keep the escaped double quotes in the
   script exactly as written in section 2.
8. **Blank page at runtime with "Target container is not a DOM element".**
   `index.html` lost `id="root"`.
