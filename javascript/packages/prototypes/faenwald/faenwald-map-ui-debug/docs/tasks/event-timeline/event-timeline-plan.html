1. Current Gaps

The existing event-timeline.tsx has three issues:

  1. No UI kit usage — raw <button> elements with hardcoded hex colors/spacing in CSS instead of IconButton, Button, ScrollArea from @/ui/kit and tokens from tokens.css.
  2. No event creation — the "+" button is a no-op. Spec requires: if no events → open modal directly; if events exist → show insertion slots between events, then open modal on slot click.
  3. No event editing — clicking an event card is a no-op. Spec requires: open modal pre-filled with event data, allow editing, save button disabled until changes are made.

Step 5: Save/update logic

Create mode

  1. Generate eventId from gameContext.counters.globalEvent++
  2. Build TGameTurnPhaseEvent from form state
  3. Call createEvent(ctx, { event, afterIndex }) from @hw/faenwald-core
  4. Call saveGameContext(gameContext) to persist
  5. Trigger mapEngine.reload() to refresh game state
  6. Close modal

Edit mode

  1. Build updated TGameTurnPhaseEvent from form state
  2. Replace event in phase array by index
  3. Call saveGameContext(gameContext)
  4. Trigger mapEngine.reload()
  5. Close modal

Save button disabled when

  • Create mode: form has required fields that are empty
  • Edit mode: form has no changes compared to original event OR has empty required fields

Required: expose loadAssets

Currently MapEngine.loadAssets() is private. Need to add a public reload() method that re-fetches game context and recomputes game state.

Step 6: Add-event flow (insertion slots)

Behavior (from spec)

  • Click "+" button → enter add mode
  • If phase has no events: skip add mode, open modal immediately with insertAfterIndex = undefined (appends to end)
  • If phase has events: show insertion slot indicators between every pair of events (and before first / after last)
  • Click a slot → open modal with the corresponding insertAfterIndex
  • Click "+" again or press Escape → exit add mode

Insertion slots

Visual: a thin highlighted gap or dashed border area between event cards, clickable. Rendered conditionally when isAddMode === true.

State additions to EventTimeline

Step 7: Edit-event flow

Behavior (from spec)

  • Click an event card → open modal in edit mode
  • Modal pre-fills type, subtype, and all form fields from the existing event
  • Type & subtype selects are disabled
  • Save button shows "Update" and is disabled until a field changes

Dirty check

The useEventForm hook tracks the original event snapshot. On each form change, deep-compare current state vs original. If identical → button disabled.
