1. Project Context

Faenwald Map UI is a canvas-based interactive world map for a strategy game prototype. The tech stack is React 19 + TypeScript 5.9 + Vite 7, with CSS Modules for styling.

Current UI elements are minimal:

  • Info overlays (selected province, hovered province, selected army) — absolutely positioned panels
  • A collapsible debug panel with checkboxes, inputs, and scrollable lists
  • A full-screen canvas container with a loading overlay

React serves as a thin shell around the canvas engine. All heavy rendering goes through MapEngine with requestAnimationFrame. No UI library is currently installed.

What we likely need going forward: buttons, toggles, dropdowns/selects, modals/dialogs, tooltips, tabs, scrollable lists, input fields — all styled to match a dark, game-like aesthetic.

2. Option A: BaseUI (Uber)

Base Web (npm: baseui) is Uber's React component library. ~9k GitHub stars. Current version: 18.0.0.

How it works

  • Styling engine: Styletron (CSS-in-JS, runtime). Required peer dependency — cannot be swapped.
  • Customization: "Overrides" pattern — every component exposes style, props, and full component replacement overrides per sub-element.
  • Theming: Deep token system (colors, typography, spacing, borders, shadows, breakpoints, z-index). createTheme() / createDarkTheme() deep-merge your tokens.
  • Tree-shaking: Per-component imports (baseui/button, baseui/select). Styletron runtime ~8 KB gzipped.
  • Components: ~40+ (Button, Select, Modal, Tabs, Input, Checkbox, Toast, Table, Popover, Tooltip, Drawer, etc.).

Strengths & Weaknesses for Faenwald

PROS

  • Exhaustive component set — covers all standard widgets
  • Overrides system is extremely powerful for reskinning
  • Built-in accessibility (ARIA, keyboard nav, focus management)
  • TypeScript support out of the box
  • Performant: Lighthouse 100 scores, Styletron deduplicates CSS declarations

CONS

  • Styletron lock-in — niche engine, conflicts with CSS Modules approach already in use
  • Enterprise design language — defaults look nothing like a game UI; heavy reskinning needed
  • Limited community support — Uber explicitly deprioritizes external issues/PRs
  • React 19 unverified — peer dep says >=18 but no explicit React 19 testing documented
  • Overhead for few components — if we only need 8-10 widgets, the Styletron setup tax is high relative to benefit
  • Two styling systems — CSS Modules for map UI + Styletron for BaseUI components = cognitive split

3. Option B: Hand-rolled Components (Claude-assisted)

Build the ~8-10 needed components from scratch using CSS Modules (the existing approach), with Claude generating the implementations.

What this looks like in practice

  • Each component is a small React + CSS Module pair (e.g., Button.tsx + Button.module.css)
  • Design tokens defined in CSS custom properties (already partially in place with dark theme variables)
  • For complex behaviors (dropdowns, modals, focus trapping), optionally use Radix Primitives as an unstyled foundation
  • Claude generates components per spec — typically 50-150 lines each

Strengths & Weaknesses

PROS

  • Zero new dependencies (or only Radix ~3-5 KB per primitive)
  • One styling system — CSS Modules everywhere, no cognitive split
  • Total visual control — game-aesthetic from day one, no fighting defaults
  • Tiny bundle — only what you use, no framework overhead
  • Claude generates fast — a Button, Modal, Select, Tabs set takes ~15 min of prompting
  • Full React 19 compatibility — no third-party runtime concerns

CONS

  • Accessibility is manual — you must add ARIA roles, keyboard handling, focus traps yourself (mitigated by Radix)
  • No free components — every widget must be specified and built
  • Maintenance burden — bugs and edge cases are yours to fix
  • Quality varies — needs review; Claude output requires testing

Radix Primitives as a middle ground

Radix Primitives provide unstyled, accessible, composable building blocks (Dialog, Select, Popover, Tooltip, Tabs, etc.) that you style yourself with CSS Modules. This gives you:

  • Correct keyboard navigation and ARIA for free
  • No visual opinions — you own all CSS
  • Per-primitive install (@radix-ui/react-dialog, etc.) — tiny footprint
  • Actively maintained, wide community, React 19 compatible

This is not a UI kit — it's behavior primitives. You still write all the CSS, which is exactly what a game UI needs.

5. Verdict: Hand-roll with optional Radix Primitives

BaseUI is the wrong tool for this project. It is built for enterprise web apps, not game UIs. The Styletron dependency conflicts with the existing CSS Modules approach, the enterprise defaults require heavy reskinning, and the limited community support adds risk for a niche engine.

Recommended approach:

  1. Define design tokens as CSS custom properties in a shared tokens.css file (colors, spacing, typography, borders, shadows) — dark, game-themed.
  2. Build components with CSS Modules — consistent with existing codebase. Use Claude to generate each component quickly.
  3. Use Radix Primitives for complex behaviors — Dialog, Select, Popover, Tooltip, Tabs. These handle accessibility and keyboard interaction; you provide all visual styling via CSS Modules.
  4. Skip Radix for simple components — Button, Input, Checkbox, Toggle are straightforward enough to hand-roll.

This gives you total visual control, zero styling conflicts, minimal dependencies, and a consistent codebase — all critical for a game prototype where aesthetics and iteration speed matter more than component library breadth.
