# FSM активной фазы битвы

Дизайн-спека машины состояний, управляющей битвой от момента «юниты расставлены»
до терминального исхода. Источник правил — статья «[CF] Боевая система»
(`faenwald-parser/out/faenwald-cf-boevaya-sistema.md`). Все решения ниже приняты
на дизайн-интервью; там, где спека молчала или противоречила себе, принятая
трактовка помечена как **(трактовка)**.

## Принципы

- **Только оркестрация.** FSM управляет очередностью, легальностью команд и
  окнами оппортунов. Расчёт урона/морали/модификаторов — отдельный чистый
  боевой модуль, вызываемый на переходах.
- **Ручной редьюсер, без зависимостей.** `reduce(state, command) → { state, events }` —
  чистая функция; никаких statechart-библиотек (пакет — vanilla JS без deps).
- **Лог команд (event sourcing).** Состояние = свёртка списка команд.
  Undo = отрезать хвост и пересвернуть. Реплей — разбор судейских споров.
- **Полный детерминизм.** Случайность (д3 за правителя, треск льда) — вне скоупа
  битвы; редьюсер не бросает кубы.
- **Hot-seat, один клиент.** Оба игрока за одним экраном; решения по оппортунам —
  синхронные промпты в UI.
- **`getLegalCommands(state)`** — единственный источник правды о доступных
  действиях; UI не дублирует правила.
- Живёт в `battle-prototype/src/modules/`; редьюсер чистый — перенос в core потом дешёвый.

## Скоуп v1

Ядро: очередь ходов, движение/повороты, атака, оппортуны, бегство, конец битвы.
Плюс: ускорение, боезапас и кулдаун арбалета, Прорыв, спешивание/седлание.
Отложено: поход за стрелами к обозу, спец-правила конного лучника (точка
расширения), потери/медики/судьба правителя (пост-битвенный слой).

## Очередность ходов

- **Раунд** («ход боя» по спеке): очередь строится **заново в начале каждого
  раунда** из текущей базовой скорости (спешившаяся кавалерия ходит как
  копейщики). Ускорение — временный баф внутри активации, на очередь не влияет.
- **Слот** = (скорость ↓, классовый приоритет, сторона). Тайбрейк классов:
  кавалерия → дальний бой → ударная пехота → копейщики. Внутри группы сначала
  слот синего, затем красного.
- В своём слоте игрок активирует **все** отряды группы, свободно перемежая их
  атомарные команды. Слот закрывается **явной командой `EndGroupTurn`** —
  после неё отряды группы добрать очки не могут.
- Раунд заканчивается, когда пройдены все слоты обеих сторон.
- Открытое окно оппортуна — **глобальный блокирующий интеррапт**: пока не
  разрешено, никакие другие команды не принимаются. Благодаря этому окно всегда
  ровно одно.

## Команды

| Команда | Семантика |
| --- | --- |
| `Step` | шаг на 1 гекс фронта; цена по местности |
| `Turn` | поворот, 1 очко; тяжёлые — 1 бесплатный поворот за раунд; копейщики — шаг в тыл/фланг без разворота за x2 |
| `Attack` | атака цели; у стрелков — с выбором режима (навес/прямая/ближний) |
| `Accelerate` | −10 морали, удвоение остатка очков, раз за раунд |
| `Dismount` / `Mount` | спешивание/седлание за 1 очко; гекс с конями — часть состояния поля |
| `EndGroupTurn` | закрыть свой слот группы |
| `Retreat` / `Surrender` / `AgreedEnd` | добровольные выходы; доступны в любой момент вне открытого окна |
| `DeclareOpportunity` / `DeclineOpportunity` | решения владельца оппортунистов внутри окна |
| `AcceptStrike` / `Retaliate` | ответ жертвы внутри окна |
| `ResolveDisplacement` | выбор клетки смещения при Прорыве (pending-решение) |

- **Частичное перемещение**: вклад привязан к целевому гексу —
  `{ targetHex, invested }`; смена цели сбрасывает вклад. Общего банка очков нет.
- **Атака — атомарная транзакция**: моральный урон → физический → отражения —
  один переход, последовательность событий наружу. Ставит `hasAttacked`;
  дальше перемещаться нельзя (исключение — «Маневренность» кавалерии).
- Контекст отряда на раунд: `hasAttacked`, `hasAccelerated`, `freeTurnUsed`,
  счётчик разбега (подряд гексы во фронт), `invested`; на бой: боезапас (8),
  кулдаун арбалета.

## Оппортуны

Единственная реактивная механика. Отдельной «контратаки» не существует:
ближний бой отвечен через обычную очередь (до атакованного дойдёт его слот).

- **Зона** = текущая досягаемость атаки врага: фронт (2 гекса) для ближнего боя,
  конус стрельбы с учётом местности для дальнего. Оппортун дальнего боя — обычная
  атака: режим выбирает стрелок из геометрически доступных, тратится боеприпас,
  кулдаун арбалета уважается. Лёгкая кавалерия — иммунитет к дальнему оппортуну.
- **Триггеры** (действия жертвы в зоне, открывающие удар): `Step`, `Turn`,
  `Dismount`/`Mount`. **Не триггеры**: `Attack`, `Accelerate`, принудительное
  смещение (Прорыв, отступление от льда) — «отряд не производит действий».
- **Вход в зону безопасен**; окно **стоячее** **(трактовка)**: пока жертва в
  зоне, каждое её триггер-действие даёт шанс удара; отказ не сжигает право.
  «Первого действия» в спеке читаем как «самый ранний возможный момент».
  Остановился в зоне и не действуешь — удара нет.
- **Право оппортуниста**: не атаковал в этом раунде. После удара «уже походил» —
  теряет всю активацию, может только развернуться.
- **Несколько оппортунистов**: FSM собирает всех легальных; их владелец решает,
  кто бьёт и в каком порядке (можно частью). Удары последовательны; если жертва
  уничтожена/побежала — оставшиеся удары не наносятся и активации не тратят.

### Поток окна

```
триггер-действие задекларировано
  → FSM собирает легальных оппортунистов (нет → действие исполняется)
  → владелец оппортунистов: DeclareOpportunity(порядок) | DeclineOpportunity
  → на каждый объявленный удар жертва выбирает:
      AcceptStrike:  удар оппортуниста → задекларированное действие исполняется
                     («подвергнувшийся атаке может продолжить перемещение»)
      Retaliate:     вместо действия жертва атакует оппортуниста —
                     её атака ПЕРВАЯ («первым наносит урон перемещающийся»);
                     если мораль оппортуниста упала до 0 / он уничтожен —
                     его удар отменяется («не совершает контратаку»),
                     отражение копейщиков при этом работает;
                     задекларированное движение отменено (после атаки ходить
                     нельзя), кроме кавалерии с «Маневренностью».
                     Условие: оппортунист в досягаемости жертвы и она
                     не атаковала в раунде; ставит ей hasAttacked.
```

Прорыв в оппортуне запрещён (правило спеки) — в т.ч. в `Retaliate`.

## Гибель и бегство

- **HP 0** → уничтожен немедленно, штрафы морали союзникам (−10 соседям, −5 через
  клетку, x2 за отряд правителя) применяются как события боевого модуля.
- **Мораль 0** → статус `routing` немедленно (штрафы соседям — сразу), текущее
  окно доигрывается. Двигается **автоматически** (pathfinding FSM, кратчайший
  маршрут с карты) **в свой обычный слот очереди**, пока не покинет карту.
  Его автодвижение — действия отряда: оппортуны по бегущему работают
  (ответить он, очевидно, не может).

## Прорыв

- Параметры команды `Attack`: толкать/нет и (при двух ударных отрядах) кто
  занимает клетку — выбирает **атакующий**.
- Приоритет клеток смещения фиксирован спекой (тыл → фланг → фронт); при
  неоднозначности внутри класса клетку выбирает **атакующий** —
  pending-состояние `ResolveDisplacement` возникает только при >1 варианте.
- Цепное смещение — не действие смещаемых: оппортунов не открывает.

## Конец битвы

Инвариант проверяется редьюсером **после каждой команды** (в т.ч. посреди
раунда): у стороны не осталось боеспособных отрядов (все уничтожены / бегут /
покинули карту) → терминальное `finished { reason }`. Добровольные выходы —
явные команды в любой момент вне открытого окна.

## Форма состояния (эскиз)

```js
state = {
  phase: "awaiting-command" | "opportunity-window" | "pending-displacement" | "finished",
  round: n,
  queue: [{ speed, unitClass, side, unitIds }],   // пересобирается каждый раунд
  slotIndex: i,
  window: { victimId, declaredAction, eligible, strikesQueue, substate } | null,
  units: { [id]: { hp, morale, facing, hex, status, roundFlags, ammo, cooldown, invested } },
  board: { hexes, horsesHexes },
  log: [command],                                  // append-only; undo = truncate + refold
}
```

API: `createBattleState(setup)`, `reduce(state, command)`, `getLegalCommands(state)`.

## Открытые вопросы

- Маппинг синий/красный ↔ attacker/defender из `battleConfig` (кто ходит первым).
- Спец-правила конного лучника (атака во фланг/тыл, неатакуемость вне стартового
  гекса) — заложены как точка расширения валидатора, в v1 не реализуются.
