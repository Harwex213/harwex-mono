# Game Show Studio

The scene opens in a Unity-like editor (Hierarchy, Scene/Game tabs, Inspector). `?solo` shows only the Game view over the whole window, and `?t=12` freezes the scene at 12 s.

- Code builds the scene. Edits made in the editor are saved as overrides in `src/scene/scene-overrides.json` (Save button or Ctrl+S). The save endpoint exists only in `yarn dev`.
- An override is keyed by a stable id: the code path of names from the root at startup, for example `Props/Host Desk` (`userData.docId`). A rename or a move in the editor keeps the id, so the overrides stay. A rename of an object in code changes its id and drops its override. The console warns about the missing id.
- Structural edits (`src/engine/sceneDocument.ts`) are saved as state, not as a history: `objects[id].name` is a rename, `objects[id].parent` + `index` is a move (parent id, `""` is the root; place among the named children), `deleted` lists the ids of deleted code objects, `added` holds the objects added in the editor (`kind`, name, parent, transform, material). Load applies adds, deletes and moves first, then the per-object fields. A file without `version` (the old format) loads as is.
- Hierarchy: right-click or `+ Add` adds a Group, a mesh primitive (`src/engine/primitives.ts`) or a light under the object. Drag a row onto a row to make it a child, onto the top or bottom edge to place it before or after; the world transform stays. Double-click or F2 renames, Del or Backspace deletes, the eye hides. Ctrl+F searches. A pick in the Scene view scrolls its row to the middle of the tree.
- The root, the Main Camera and every `userData.animated` object cannot be deleted or moved: code writes them every frame. Code keeps running on a deleted object, so code must not look up a scene object by name after `SceneDocument` applies the overrides (the engine takes the floor before it).
- An added mesh primitive has its origin at the bottom centre already. The blocking audit checks added meshes like any part of the set; a user who adds one keeps the audit clean. An added light belongs to the annex zone under `Annex`, otherwise to the amphitheatre, and it costs frame time in every shot of its room.
- Tests that save must not touch the real file: `SCENE_OVERRIDES=/path/copy.json yarn dev` loads and saves a copy. The user edits `scene-overrides.json` live.
- Wrap a new object in `named(object, "Name")` from `src/scene/geometry.ts`, so it shows in the Hierarchy and can be selected. Pass `folder = true` for a pure grouping node. A click in the Scene view skips folders.
- Set `userData.animated = true` on an object whose transform the animation writes every frame (the camera, the wheel rotor, the sweeping blue targets). Its transform is then left out of saves.
- Materials from `createMaterials` are shared and saved by name. A cloned material needs its own `name`.
- Undo works on snapshots of the saved diff (`SceneDocument.checkpoint`). A new kind of edit must call `checkpoint()` right before it changes the scene, or undo skips it.
- Editor Lighting (`src/engine/editorLighting.ts`) changes the scene only for the duration of one render and restores it afterwards. It dims the game lights to 0, and the light zones leave all of them out of the render. A new fake-light mesh needs `userData.beam = true` so that this mode hides it.
- Light zones (`src/engine/lightZones.ts`): each frame the lights of a room that the camera does not see are left out of the render through their layers. A light under the `Annex` group (`userData.lightZone = "annex"`) belongs to the annex. Every other light belongs to the amphitheatre. The frame time grows faster than the light count: all 32 lights cost 43 ms per frame in the wheel shot, the 21 amphitheatre lights cost 12 ms. A new light in one room does not slow down the other room, but it still costs in every shot of its own room. Keep the light count of each room low. The annex has 2 real lights, both on Bonus Show; fake the rest with emissive materials.
- Blocking rule: no part may cut into another part, no two faces may z-fight, and every part must touch something that leads down to the floor. Check it with `__studio.audit()` in the browser console (`src/engine/blockingAudit.ts`): all three lists must be empty after a change to the set.
- Mark a mesh `userData.seated = true` only when it is mounted into a curved surface on purpose (a bulb in the wheel ring, a globe on a lamp neck). Mark it `userData.auditIgnore = true` only when it is not part of the set (the mirror, the city backdrop, floor decals).
- The colonnade is a polygon of straight bays (`src/scene/studio.ts`). A part that runs along the wall must use `colonnadeStrip`, so that it ends on the same radial planes as the wall slabs. A round part along a straight wall always leaves a gap or an overlap.
- Pivot rule: every selectable object has its origin at the bottom centre of its bounds (an open arc gets the nearest point of its geometry instead). `recenterPivots` (`src/engine/pivots.ts`) enforces it once at startup, so build props in any frame; `__studio.pivots()` must return an empty list.
- Camera shots: the `shot` signal in `src/state.ts` picks `wheel` (Main Wheel), `dice` (Bonus Dice), `show` (Bonus Show) or `luck` (Bonus Luck). The toolbar has a button for each shot, and `?shot=show` starts on that shot. The poses live in `src/scene/cameraRig.ts`. The Main Wheel pose is fixed in world space. Each bonus game shot is set in the frame of its game object (`STATION_SHOTS`): the origin is the pivot of the object, and local +z is its front. The rig reads the object every frame, so the shot follows the game when the user moves it. A new shot makes the camera travel for 2.6–3.4 s. The move runs in a straight line on the plan and cranes up to 7 m on the way, over every prop. `?t=` skips the travel, so a frozen frame depends only on the shot and the time.
- Annex (`src/scene/annex.ts`): the Game Show platform at the front right of the amphitheatre, x from -2.4 to 23.7, z from 9.27 to 26. It sticks out 1.7 m past the round floor (radius 22) along x and 4 m along z; the user asked for a small balcony. It has no walls and no ceiling: the user does not want a room there. The platform floor is a part of `Studio/Floor/Marble`: `annexFloorPlan` cuts the exact polygon of the round floor out of it. A gold balustrade runs along the free edges, and a dark fascia under them gives the platform a thickness. The casino side and the front meet in the tip of the balcony at (23.7, 26). Bonus Show stands on the bisector of that tip and faces back along it. No annex part may stand on the round floor or cut into an amphitheatre prop.
- Balcony palette: the balcony matches the casino photo (warm black, bronze, amber gold), not the blue studio. It has its own named materials (`marbleFloorAnnex` with gold veins, `annexGold`, `annexBronze`, `annexLacquer`, `annexFascia`), so a change to them leaves the amphitheatre alone. They reflect the warm `createCasinoEnvironment` (`src/scene/materials.ts`) as their own `envMap`, not the studio environment with its blue panels. A material with `userData.ownEnvironment` gets the editor sky under Editor Lighting.
- Bonus Show lights: `Annex/Lights` holds a key and a back light. `follow()` moves both onto the live Bonus Show every frame (also while paused), so the wheel stays lit wherever the user puts it. Their transforms are `userData.animated`.
- Casino hall (`src/scene/casino.ts`, kit `casinoKit.ts`, shading `casinoShading.ts`, `shaders/casinoGlow.*`): real geometry round the balcony, rebuilt from the photo `assets/casino-panorama-center.png`, so the perspective holds from every camera. The hall frame: u along the nave, v across it, y is world y. The nave axis starts at the rest pose of the Bonus Show camera and runs along its line of sight (azimuth 33 degrees), so the vanishing point sits behind the wheel. The hall does not follow Bonus Show: a user who moves the wheel far keeps the hall where it is. The casino floor is at y = -3.4 (7.1 m under the show camera). Columns at v = +-12.5 from u = 15 every 13 m, galleries at 6.5, outer walls at v = +-24, the bar and the great window at u = 100, three chandeliers at u = 22, 38, 54. Low piers under the balcony fascia close the hall along the balcony edges; nothing of the hall stands on or over the balcony (the galleries keep 1.5 m clear). It has no real lights: every casino material adds the light of virtual lamps (chandeliers, candelabra, lanterns, table and gallery lamps, slot glow) in its shader, with the layout written into the GLSL from the TS constants. A new lamp row goes into `createLighting`. Emitters use one glow material: per-vertex HDR colour and kind (steady, flame, crystal, screen, bar, window) and phase. Pieces merge per material in `Batch`, so the hall draws in 23 meshes and about 271k triangles. `update(time)` takes the scene time (`?t=` freezes it) and keeps the hall frame uniform in step with the `Casino` group. The `Casino` folder is `auditIgnore`; check overlaps with set meshes after a change. The engine mounts it (not the annex). No haze band: only a light depth haze past 55 m.
- Bonus games (`src/scene/gameProps.ts`, under `Game Props`): Bonus Show is the jester wheel, Bonus Dice is the acrylic tower, Bonus Luck is the slot cabinet. The user places them in the editor, so their places live in `scene-overrides.json`.
- Show dressing (`src/scene/annexDressing.ts`, folder `Annex/Show Dressing`): `Bonus Show Set` holds the props composed round Bonus Show and its shot (the dais round the wheel base, torchères, podiums, lectern, sign, carpet runner, rope stanchions, two palms). The set frame is the wheel frame: it stands at the saved place of Bonus Show (`BONUS_SHOW_HOME`). A user who moves Bonus Show moves the set group the same way in the editor. The other props (champagne table, studio camera, softboxes, two palms) stand at fixed balcony places. Its lit materials take the casino environment through `createAnnex().materials`. No prop may stand inside radius 22 (the round floor).
