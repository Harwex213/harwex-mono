# Game Show Studio

The scene opens in a Unity-like editor (Hierarchy, Scene/Game tabs, Inspector). `?solo` shows only the Game view over the whole window, and `?t=12` freezes the scene at 12 s.

- The scene file is the single source of truth: every object of the scene is a record in it (stable id, name, parent, order, transform, flags, components). Code is a library of component types. The format is in [docs/scene-format.md](docs/scene-format.md).
- The scene has versions: `src/scene/versions/001.json`, `002.json`, ... and `src/scene/versions/index.json` (the list and the latest one). The folder keeps at most 10 versions; a new version past 10 removes the oldest. The editor opens the latest version; `?v=3` opens version 3. Save writes the version open in the tab. The toolbar under the main toolbar picks a version, marks an old one and makes a new version (a copy of the latest).
- Agent rule: edit the LATEST version, and edit it with `yarn scene` (`scripts/scene.mjs`), not by hand. `yarn scene help` lists the commands: `get`, `find`, `children`, `set <id> <field> <value>`, `move`, `add`, `delete`, `material`, `setting`, `patch <file.json>`, `new-version`. `--v N` edits another version, `--dry` prints the change. Each command saves only the units it changed, merged into the file as it is on disk, under a lock, with an atomic write. A careful hand edit of a version file is safe too: the dev server sees it. Never rewrite the whole file from an old copy: that throws away the edits of others.
- Humans and agents edit the same files at the same time. The open tab watches its version: a change on disk merges into the tab at once, and the unsaved edits of the human stay on top. A field that both changed is a conflict: the tab lists it and keeps the human value until the human picks a side; Save is off until then. Save sends only the edits of the tab; the dev server merges them into the file on disk and refuses on a conflict. Undo never takes back a change from disk. Details in [docs/scene-format.md](docs/scene-format.md#versions-and-merging).
- An object keeps its id for life (`userData.docId`). A rename or a move keeps it. Never rename an id in the file: an id is not a path. A new object needs a new id that no object had before.
- Never add an object in code. Add it to the scene file, with its components. A new kind of part needs a component type (a geometry recipe type in `src/engine/geometryRecipes.ts`, a body in `src/engine/sceneLoader.ts`, a procedural body like the casino props in `src/scene/casino.ts`, a behaviour or data component in `src/scene/components.ts`), and the parameters go into the file. Code must not decide how many objects exist or where they stand. Every colour and phase of an emitter is a parameter in the file too.
- The render settings (background, environment map, tone mapping, shadow map, MSAA samples, bloom) are the `settings` section of the scene file.
- Hierarchy: right-click or `+ Add` adds a Group, a mesh primitive (`src/engine/primitives.ts`) or a light under the object. Drag a row onto a row to make it a child, onto the top or bottom edge to place it before or after; the world transform stays. Double-click or F2 renames, Del or Backspace deletes, the eye hides. Ctrl+F searches. A pick in the Scene view scrolls its row to the middle of the tree.
- The root, the Main Camera and every `animated` object cannot be deleted or moved: a component writes them every frame. A behaviour finds its targets by id; a deleted object stays in memory, so the behaviour keeps running on it.
- An added mesh primitive has its origin at the bottom centre already. The blocking audit checks added meshes like any part of the set; a user who adds one keeps the audit clean. An added light belongs to the annex zone under `Annex`, otherwise to the amphitheatre, and it costs frame time in every shot of its room.
- Tests that save must not touch the real files: `SCENE_DIR=/path/copy yarn dev` (and `SCENE_DIR=/path/copy yarn scene ...`) load and save a copy of the versions folder. The user edits the versions live. `src/scene/scene-overrides.json` is the old overrides file: the bake carried its edits into the scene; leave it alone.
- The page fetches the version files; they are not modules. A save never rebuilds the bundle or reloads the page. `yarn build` copies the versions into `dist/scene/versions/`; the built page opens the latest one read-only.
- Static batching (`src/engine/staticBatch.ts`): a folder with the `staticBatch` component draws its static meshes with one draw call per material. `Studio/Walls` and the casino folders `Architecture`, `Gaming Floor` and `Bar` have it. The parts stay ordinary objects: the editor lists, picks, moves and saves them, and the batch moves the changed part on the next frame. A built-in material draws as a BatchedMesh, which still culls each part on its own. A casino material draws as one merged mesh. An animated subtree is never batched: put a moving part under an `animated` object (a chandelier `Fixture`).
- Set the `animated` flag on an object whose transform a component writes every frame (the camera, the wheel rotor, the sweeping blue targets and beams, the Bonus Show lights). The file keeps its start transform; Save does not write the animated pose.
- Materials: `src/scene/materialLibrary.ts` creates every material by key; a meshRenderer names its materials by these keys. The `materials` section of the file holds the editable values (colour, emissive, roughness, metalness) of the shared materials by name. A new material needs a new key and its own `name`.
- Undo works on snapshots of the editable state of every object and of the material values (`SceneDocument.checkpoint`). A new kind of edit must call `checkpoint()` right before it changes the scene, or undo skips it.
- Editor Lighting (`src/engine/editorLighting.ts`) changes the scene only for the duration of one render and restores it afterwards. It dims the game lights to 0, and the light zones leave all of them out of the render. A fake-light mesh is a `beam` component, so this mode hides it.
- Light zones (`src/engine/lightZones.ts`): each frame the lights of a room that the camera does not see are left out of the render through their layers. A room is an object with a `lightZone` component: its name and the space the camera must see (a box). A light under the `Annex` group belongs to the annex. Every other light belongs to the default room, the amphitheatre (the zone on `Studio`). The frame time grows faster than the light count: all 32 lights cost 43 ms per frame in the wheel shot, the 21 amphitheatre lights cost 12 ms. A new light in one room does not slow down the other room, but it still costs in every shot of its own room. Keep the light count of each room low. The annex has 2 real lights, both on Bonus Show; fake the rest with emissive materials.
- Blocking rule: no part may cut into another part, no two faces may z-fight, and every part must touch something that leads down to the floor. Check it with `__studio.audit()` in the browser console (`src/engine/blockingAudit.ts`): all three lists must be empty after a change to the set.
- Give a mesh the `seated` flag only when it is mounted into a curved surface on purpose (a bulb in the wheel ring, a globe on a lamp neck). Give it the `auditIgnore` flag only when it is not part of the set (the mirror, the city backdrop, floor decals).
- The colonnade (`Studio/Walls`) is a polygon of straight bays: 9 bays (wall slab, and in the 5 arch bays the arch frame, keystone, moulding and sill) and 8 columns, each an object in the file. A wall slab is a `wallSlab` geometry recipe: its ends lie on the radial planes through the joints. A part that runs along the wall (the steps, the entablature) is an extrude of the colonnade polygon in the file: it ends on the same radial planes. A round part along a straight wall always leaves a gap or an overlap.
- Pivot rule: every selectable object has its origin at the bottom centre of its bounds (an open arc gets the nearest point of its geometry instead). The file stores the objects that way: the geometry recipe carries the shift. `__studio.pivots()` (`src/engine/pivots.ts`) must return an empty list.
- Camera shots: the `shot` signal in `src/state.ts` picks `wheel` (Main Wheel), `dice` (Bonus Dice), `show` (Bonus Show) or `luck` (Bonus Luck). The toolbar has a button for each shot, and `?shot=show` starts on that shot. The poses live in the `cameraRig` component of the Main Camera in the scene file; the motion is in `src/scene/cameraRig.ts`. The Main Wheel pose is fixed in world space. Each bonus game shot is set in the frame of its game object (`stations`, by id): the origin is the pivot of the object, and local +z is its front. The rig reads the object every frame, so the shot follows the game when the user moves it. A new shot makes the camera travel for 2.6–3.4 s. The move runs in a straight line on the plan and cranes up to 7 m on the way, over every prop. `?t=` skips the travel, so a frozen frame depends only on the shot and the time.
- Annex (objects under `Annex` in the scene file): the Game Show platform at the front right of the amphitheatre, x from -2.4 to 23.7, z from 9.27 to 26. It sticks out 1.7 m past the round floor (radius 22) along x and 4 m along z; the user asked for a small balcony. It has no walls and no ceiling: the user does not want a room there. The platform floor is a part of `Studio/Floor/Marble` (a merge recipe: the round floor plus the plan polygon of the platform, cut along the exact polygon of the round floor). A gold balustrade runs along the free edges, and a dark fascia under them gives the platform a thickness. The casino side and the front meet in the tip of the balcony at (23.7, 26). Bonus Show stands on the bisector of that tip and faces back along it. No annex part may stand on the round floor or cut into an amphitheatre prop.
- Balcony palette: the balcony matches the casino photo (warm black, bronze, amber gold), not the blue studio. It has its own named materials (`marbleFloorAnnex` with gold veins, `annexGold`, `annexBronze`, `annexLacquer`, `annexFascia`), so a change to them leaves the amphitheatre alone. They live in `src/scene/annexMaterials.ts` and reflect the warm `createCasinoEnvironment` (`src/scene/materials.ts`) as their own `envMap`, not the studio environment with its blue panels. A material with `userData.ownEnvironment` gets the editor sky under Editor Lighting.
- Bonus Show lights: `Annex/Lights` holds a key and a back light with their targets. Each of the four has a `followTarget` component on `Game Props/Bonus Show`: it moves them onto the live Bonus Show before every render (also while paused), so the wheel stays lit wherever the user puts it. They are `animated`.
- Casino hall (objects under `Casino` in the scene file; bodies `src/scene/casino.ts`, kit `casinoKit.ts`, shading `casinoShading.ts`, `shaders/casinoGlow.*`): real geometry round the balcony, rebuilt from the photo `assets/casino-panorama-center.png`, so the perspective holds from every camera. The hall frame is the frame of the `Casino` object: u (x) along the nave, v (z) across it, y is world y. The nave axis starts at the rest pose of the Bonus Show camera and runs along its line of sight (azimuth 33 degrees), so the vanishing point sits behind the wheel. The hall does not follow Bonus Show: a user who moves the wheel far keeps the hall where it is. The casino floor is at y = -3.4 (7.1 m under the show camera). Columns at v = +-12.5 from u = 15 every 13 m, galleries at 6.5, outer walls at v = +-24, the bar and the great window at u = 100, three chandeliers at u = 22, 38, 54. Low piers under the balcony fascia close the hall along the balcony edges; nothing of the hall stands on or over the balcony (the galleries keep 1.5 m clear). Every column, arch, drape, window, candelabrum, lamp, table, chair, slot machine, palm, guest and bar part is an object with a procedural body (`casinoColumn`, `casinoSlotMachine`, ...): one mesh with a draw group per casino material. The folders `Architecture`, `Gaming Floor` and `Bar` are static batches, so the hall draws in 23 calls and about 271k triangles. The `Left Side` of the colonnade is the `Right Side` mirrored (scale -1 on z). The hall has no real lights: every casino material adds the light of virtual lamps in its shader. The lamps are objects in the file: a `virtualLamp` component (chandeliers, the candelabra on the columns, lanterns, table lamps) or a `virtualLine` (the gallery lamps, the slot glow). A moved lamp moves its light at once; a chandelier moves with its light. Lamps with the same `row` form a row along the nave; each half of the hall sees only its own rows. The shader is straight-line code written for the lamp layout, with the lamp places in uniforms: a loop over lamps costs far more per fragment. The ambient light and the patterns of floor and vault are the `casinoLighting` component on `Casino`. Emitters use one glow material: per-vertex HDR colour and kind (steady, flame, crystal, screen, bar, window) and phase, all from the component data. The chandelier `Fixture` sways (`sway`, `animated`); move its parent `Chandelier n` instead. Check overlaps with set meshes after a change. No haze band: only a light depth haze past 55 m. The reference photos live in `reference/`. `casino-hall.png` is the photo the hall is built from (the same file as `assets/casino-panorama-center.png`). `casino-hall-user-photo.png` is the first casino photo from the user.
- Bonus games (under `Game Props` in the scene file; materials in `src/scene/gameProps.ts`): Bonus Show is the jester wheel (base, collar, post, arc with bulbs, printed disc, rim, pivots, pointers: each an object under `Game Props/Bonus Show`), Bonus Dice is the acrylic tower, Bonus Luck is the slot cabinet. The user places them in the editor.
- Show dressing (folder `Annex/Show Dressing` in the scene file, materials in `src/scene/annexMaterials.ts`): `Bonus Show Set` holds the props composed round Bonus Show and its shot (the dais round the wheel base, torchères, podiums, lectern, sign, carpet runner, rope stanchions, two palms). The set frame is the wheel frame: it stands at the saved place of Bonus Show. A user who moves Bonus Show moves the set group the same way in the editor. The other props (champagne table, studio camera, softboxes, two palms) stand at fixed balcony places. Its lit materials take the casino environment. No prop may stand inside radius 22 (the round floor).
- GLB export: `yarn export-glb` builds the page and writes the latest version to `exports/scene-v<NNN>.glb` (`--v 3` picks a version). The Export GLB button in the toolbar downloads the same file. The export (`src/engine/glbExport.ts`) leaves hidden objects out and keeps the Hierarchy names and ids (`extras.id`). glTF has no shaders, so glows become emissive materials, the mirror becomes glossy metal, and the beams become faint cones. Bloom, the environment map, shadows and light zones do not go into the file.
