TL;DR

Главное решение

Браузер не должен открывать .blend напрямую. Сервер запускает Blender headless, получает канонический model.blend и производный model.glb. Браузер грузит GLB, рендерит его через Three.js/WebGPU и позволяет интерактивно менять объектные трансформации только в памяти браузера. model.blend и model.glb после генерации не меняются.

1

.blend — результат

Полная сцена Blender для скачивания, следующего запуска агента или ручной доработки.

2

.glb — delivery

Компактный, готовый к рендерингу снимок мешей, PBR-материалов и текстур.

3

Web — песочница

WebGPU рисует сцену, а все пользовательские трансформы остаются локальными.

FBX в этой цепочке не нужен. Он остаётся опциональным экспортом для внешних DCC/движков, но веб-превью должно потреблять GLB/glTF.

Что уже есть в modelgen-harness

Текущий pipeline уже закрывает тяжёлую нижнюю половину схемы. Host-side pipeline.py валидирует job, создаёт изолированный run directory и запускает Blender с --background --disable-autoexec. Blender-side blender_worker.py выполняет agent-authored build script, проверяет геометрию, сохраняет blend, экспортирует GLB/FBX и рендерит PNG-превью.

Уже реализовано

  • изолированные run directories;
  • запуск Blender headless;
  • запрет auto-exec из входного blend;
  • валидация мешей и трансформаций;
  • model.blend как результат;
  • model.glb как веб-артефакт;
  • статические PNG-превью;
  • report.json и host status.

Нужно добавить

  • стабильные web_id для объектов;
  • web-метаданные для логических узлов;
  • HTTP-раздачу GLB и статусов;
  • Three.js viewer;
  • raycast selection и transform gizmo;
  • client-side undo/redo и reset;
  • опциональное сохранение web-сессии отдельно от BLEND.

Основной generation flow

  1. Сервер принимает требования пользователя и создаёт job.
  2. Агент генерирует или меняет Blender build script в рамках job.
  3. Harness запускает Blender headless в отдельном run directory.
  4. Worker строит сцену, проводит audit и validation.
  5. Worker назначает/проверяет идентификаторы интерактивных объектов.
  6. Worker сохраняет model.blend.
  7. Worker экспортирует model.glb и scene-manifest.json.
  8. Сервер переводит run в ready и отдаёт URL превью.
  9. Клиент грузит GLB и строит индекс web_id → Object3D.

Web-only interaction flow

  1. Пользователь кликает по видимому мешу.
  2. Клиент поднимается по его родителям до логического узла с web_id.
  3. Gizmo меняет transform локально — кадр обновляется немедленно.
  4. На окончание drag клиент фиксирует команду только в локальном undo stack.
  5. Reset Object возвращает выбранный узел к transform из загруженного GLB.
  6. Reset Scene восстанавливает исходное состояние всей сцены.
  7. Перезагрузка страницы сбрасывает изменения, если session snapshot не включён.

После публикации GLB Blender больше не участвует. Выделение, перемещение, вращение, масштабирование, undo и reset выполняются в Three.js. Поэтому управление отзывчивое и не требует transform API, очередей или worker.

Идентичность объектов внутри web-сессии

Имена Blender-объектов не являются API: пользователь или агент может их поменять, Blender добавляет суффиксы, а экспортёр создаёт промежуточные узлы. Чтобы клик по дочернему mesh выбирал правильную составную деталь, каждый интерактивный логический объект получает UUID в custom property. Стабильность между генерациями желательна, но для web-only режима не обязательна. 

import uuid

for obj in bpy.context.scene.objects:
    if obj.type == "MESH" and "web_id" not in obj:
        obj["web_id"] = str(uuid.uuid4())
        obj["web_interactive"] = True

Экспорт glTF должен включать custom properties. Они попадают в glTF extras, а после загрузки Three.js доступны как object.userData.web_id. 

function findEditableNode(hitObject) {
  let node = hitObject;

  while (node) {
    if (node.userData?.web_id && node.userData?.web_interactive !== false) {
      return node;
    }
    node = node.parent;
  }

  return null;
}

Правило: transform применяется к логическому узлу с web_id, а не обязательно к тому дочернему Mesh, в треугольник которого попал raycast.

Веб-превью

Загрузка

GLTFLoader загружает GLB и возвращает scene graph, материалы и текстуры.

Рендер

WebGPURenderer использует WebGPU и может откатиться на WebGL 2.

Управление

OrbitControls, Raycaster и TransformControls.

Минимальный состав UI

  • canvas на всю доступную область;
  • orbit/pan/zoom камеры;
  • клик для выбора объекта, клик в пустоту для сброса;
  • outline или emissive-подсветка выбранного объекта;
  • режимы Move, Rotate, Scale;
  • переключатель Local / World;
  • snap для перемещения, угла и масштаба;
  • панель имени, ID, текущего TRS и material slots;
  • Undo/Redo и Reset Object / Reset Scene;
  • индикаторы loading, ready, modified locally, failed.

Базовый selection flow

pointerdown
  → Raycaster.setFromCamera(pointer, camera)
  → intersectObject(gltf.scene, true)
  → nearest visible hit
  → climb parents until userData.web_id
  → setSelection(node)
  → TransformControls.attach(node)

На время перетаскивания gizmo OrbitControls отключается, иначе один жест одновременно двигает объект и камеру. После mouseUp камера снова включается, а операция попадает в локальный undo stack.

Трансформации внутри браузера

В браузере

Three.js хранит transform как position, quaternion, scale и вычисляемую матрицу. Эти значения меняются только у загруженных Object3D; файлы на сервере остаются нетронутыми. Перед первым изменением viewer сохраняет исходный local TRS каждого интерактивного узла для Reset и сравнения состояния. 

transformControls.addEventListener("mouseDown", () => {
  orbitControls.enabled = false;
  beginUndoTransaction(selected);
});

transformControls.addEventListener("objectChange", () => {
  markModifiedLocally(selected.userData.web_id);
  render();
});

transformControls.addEventListener("mouseUp", () => {
  orbitControls.enabled = true;
  commitUndoTransaction(selected);
});

Исходное состояние и Reset

Сразу после загрузки GLB клиент создаёт snapshot исходных transforms. Reset копирует значения назад в объект; новый экспорт и сетевой запрос не нужны. 

const initialTransforms = new Map();

gltf.scene.traverse((node) => {
  if (!node.userData?.web_id) return;
  initialTransforms.set(node.userData.web_id, {
    position: node.position.clone(),
    quaternion: node.quaternion.clone(),
    scale: node.scale.clone(),
  });
});

function resetObject(node) {
  const initial = initialTransforms.get(node.userData.web_id);
  node.position.copy(initial.position);
  node.quaternion.copy(initial.quaternion);
  node.scale.copy(initial.scale);
  node.updateMatrixWorld(true);
}

Undo/Redo

Стек полностью клиентский. Каждая операция хранит before и after local TRS выбранного узла. Reload/Reset Scene очищает стек. Никакие команды не уходят моделирующему агенту или Blender worker.

Координаты, pivot и иерархия

Blender использует Z-up, glTF — Y-up, но для web-only трансформов эта разница почти полностью закрывается экспортёром: viewer работает только с уже сконвертированным scene graph. Обратной конверсии в Blender basis нет.

Рекомендуемый подход

  • менять local TRS самого логического Object3D;
  • не распрямлять иерархию после загрузки без необходимости;
  • вращение хранить quaternion, в UI показывать Euler;
  • сохранять исходный local TRS до первой операции;
  • ставить gizmo в pivot/origin выбранного объекта.

Что обязательно проверить

  • объекты с non-zero origin;
  • вложенные parent/child transforms;
  • неравномерный scale;
  • отрицательный scale;
  • rotated parent + scaled child;
  • empty как логический root;
  • инстансы и linked mesh data.

Если загруженный узел имеет shear или матрицу, которую нельзя чисто разложить в TRS, его лучше оставить selectable, но отключить gizmo. Это редкий случай, но молчаливое разложение матрицы даст визуальные скачки уже в браузере.

Опциональный snapshot

Если позже понадобится восстановить «игровую» раскладку после reload, её можно положить в localStorage или сохранить отдельным JSON на сервере. Это не новый GLB и не изменение .blend: при загрузке viewer сначала открывает оригинальный GLB, затем накладывает session transforms по web_id. 

{
  "schemaVersion": 1,
  "sourceRunId": "20260904T120000Z-a31f9c2d",
  "transforms": {
    "9f2cd95a-...": {
      "position": [1.2, 0.0, -3.4],
      "quaternion": [0.0, 0.7071068, 0.0, 0.7071068],
      "scale": [1.0, 1.0, 1.0]
    }
  }
}

Snapshot должен ссылаться на конкретный sourceRunId. Не надо автоматически накладывать старую раскладку на заново сгенерированную модель: иерархия и геометрия могли измениться.

Контракт для моделирующего агента

Чтобы web preview был предсказуемым, агентные build scripts должны соблюдать узкий набор правил. Эти требования стоит добавить в prompt/skill агента и проверять worker-валидацией.

  1. MUST: создавать осмысленные имена объектов и материалов.
  2. SHOULD: сохранять существующий web_id при доработке объекта.
  3. SHOULD: назначать новый UUID новому логическому объекту.
  4. MUST: использовать конечные transforms без NaN/Infinity.
  5. MUST: сохранять master .blend до экспорта runtime-артефактов.
  6. SHOULD: держать один логический interactive root на составную деталь.
  7. SHOULD: использовать Principled BSDF и image textures.
  8. SHOULD: применять или явно документировать модификаторы перед экспортом.
  9. SHOULD: избегать negative scale; при необходимости применять scale.
  10. SHOULD: ставить origin туда, где пользователь ожидает вращение детали.
  11. MAY: помечать служебные объекты web_interactive = false.

Важное разделение: агент отвечает за создание содержимого сцены, worker — за инварианты, audit, IDs, сохранение и экспорт. Не стоит надеяться, что каждый сгенерированный скрипт идеально реализует инфраструктурные правила сам.

Материалы и текстуры

GLB хорошо переносит стандартный metallic/roughness PBR: base color, metallic, roughness, normal, occlusion, emission, alpha и ряд glTF extensions. Но произвольная Blender node graph не становится автоматически эквивалентным web shader.

Viewer lighting preset

Для честной проверки материала viewer должен иметь нейтральный HDR environment, key/fill/rim либо студийный preset, переключение solid/material mode и контроль exposure. Иначе хороший материал будет выглядеть плохо просто из-за пустого света.

Оптимизация после MVP

  • KTX2/Basis для сжатия GPU-текстур;
  • Meshopt или Draco для геометрии;
  • лимиты размера текстур и общего GLB;
  • LOD для тяжёлых ассетов;
  • отложенная загрузка environment map.

Безопасность и эксплуатация

.blend — недоверенный вход. Он может содержать Python и другие тяжёлые данные. Запуск с --disable-autoexec обязателен, но сам worker всё равно исполняет agent-authored Python, поэтому процесс должен быть изолирован ресурсными лимитами и правами файловой системы.

  • отдельный процесс Blender на generation job;
  • timeout, memory/CPU limits и максимальный размер входных файлов;
  • запись только в конкретный run directory;
  • никаких пользовательских абсолютных output paths внутри worker;
  • атомарная публикация артефактов только после успешной валидации;
  • viewer получает только статические артефакты и не запускает Blender;
  • старый успешный preview остаётся доступен, если новый generation run упал;
  • логи связываются по jobId и runId;
  • очистка старых run directories отдельной retention policy.

Критерии готовности MVP

  • После успешного modelgen job браузер открывает GLB без ручного экспорта.
  • Меши, UV-текстуры и поддерживаемые PBR-материалы визуально присутствуют.
  • Пользователь может выбрать логический объект кликом по любой его геометрии.
  • Выбранный объект однозначно связан с Blender-объектом через web_id.
  • Move, rotate и scale работают интерактивно без запросов к серверу.
  • Undo/Redo возвращает корректный local TRS выбранного объекта.
  • Reset Object и Reset Scene восстанавливают состояние из загруженного GLB.
  • Изменения в viewer не меняют model.blend, model.glb или report.json.
  • Тесты проходят для X/Y/Z, local/world и parented object.
  • Reload открывает исходную модель, если session snapshot не включён.

Ключевые тестовые сцены

  1. Одиночный текстурированный cube.
  2. Два объекта с разными материалами и похожими именами.
  3. Parent empty → rotated mesh child.
  4. Составная модель с несколькими дочерними mesh nodes под одним interactive root.
  5. Non-uniform scale и object origin вне геометрического центра.
  6. Сцена с procedural material, который должен быть baked или помечен warning.

Все игровые transform-операции выполняются локально над Three.js scene graph и никак не затрагивают Blender. Это даёт быстрый preview без transform API и без попытки запихнуть Blender runtime в браузер.
