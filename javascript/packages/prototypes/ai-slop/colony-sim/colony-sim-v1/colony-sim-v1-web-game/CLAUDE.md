Игровое приложение с оболочкой: роутинг, сессия, лобби, автосейв. Границы с остальными пакетами — в
CLAUDE.md группы (`../CLAUDE.md`): здесь только внутренние правила web-game.

Страницы вокруг игры (имя игрока, список игр, комната) принадлежат только этому пакету; core, hud и
рендер о них не знают, поэтому dev-game остаётся голым бутстрапом.

## Монтирование игры

- **Два корня в разметке:** `#app` — preact-дерево страниц, `#game` — канвас и HUD над ним. Игру
  монтирует эффект на сигнале роута, а не компонент: луп принадлежит engine-синглтону. Оба корня
  смотрят на один сигнал роута и разъехаться не могут.
- **Бутстрап игры возвращает handle:** уход с игрового роута обязан остановить тикер и снять канвас,
  иначе второй заход оставляет за собой первый.

## Роутинг и сессия

- **Роутинг хэшевый.** Бандл раздаётся статикой, переписывать пути некому: `#/games/x` переживает
  перезагрузку, `/games/x` — нет. Навигация только через хэш, иначе адресная строка и «назад» спорят
  с состоянием.
- **Сессия живёт в памяти,** ни имени, ни id в localStorage: id действителен ровно пока открыт поток
  событий игрока, сохранённый id — заявка с забытым сервером хэндлом. Перезагрузка = новая сессия с
  формы имени, поэтому гейт стоит в `App`, а не в каждой странице.

## Лобби

- **Клиентское лобби — зеркало серверного, а не вторая правда.** `rooms` пишет только поток событий,
  команды идут отдельным POST'ом, эффект виден после нового снапшота — две вкладки не расходятся во
  мнении, кто где ждёт.
- **Читаем SSE, пишем POST'ом** (не websocket): лобби только вещает вниз, SSE односторонний,
  переподключается сам, не требует протокола поверх.
- **Выход из игры обязан явно покинуть комнату:** присутствие на сервере держится открытым потоком, и
  без явного выхода игрок числится в комнате до закрытия вкладки.
- **Клиент ходит относительными путями, dev проксирует `/api`** — одно происхождение в dev и в
  деплое, без CORS и хоста в конфиге. Прокси без сжатия: gzip буферизует SSE и отдаёт события пачкой.

## Сид и автосейв

- **Комната — не состояние игры:** в ней участники и сид, мир по сиду строит сим на каждом клиенте,
  симуляции не синхронизированы. Общий сид = общая карта, и не более.
- **Слот автосейва один на приложение** → снапшот принадлежит игре только при совпадении сида, иначе
  вторая игра поднимет колонию первой. Две вкладки с одним сидом делят слот и затирают автосейв друг
  друга.
