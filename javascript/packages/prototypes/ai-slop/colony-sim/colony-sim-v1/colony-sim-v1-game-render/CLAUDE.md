pixi-рендер мира: реконсилиация спрайтов, бейк террейна, шейдеры, камера, ассеты. Границы с остальными
пакетами — в CLAUDE.md группы (`../CLAUDE.md`): здесь только внутренние правила рендера.

## Модель работы

**Реконсилиация, а не подписки:** каждый кадр пул спрайтов сверяется с `world` — новым создать,
исчезнувшим удалить, остальным обновить трансформ. Связей sim→render нет, рассинхрониться нечему;
цена — `reconcile()` синхронен и ничего не может дождаться (отсюда прелоад текстур в бутстрапе).

- Между тиками интерполяция `lerp(prevPos, pos, alpha)`: sim идёт 10 раз в секунду, картинка 60 fps.
  `alpha` даёт `TurnSource`, а не рендер.
- Выводимое из состояния в состоянии не хранится: facing — из движения, вариант спрайта — из
  `entityId`, разброс декора — из `tileHash(x, y, seed)`. Стабильно между перезагрузками, вне сейва,
  без миграций.
- Принадлежность — исключение: лист берётся из состояния. Лист колониста выбирается по
  `world.owners`, а не по id: команды обязаны оставаться разными после перезагрузки, а сменивший
  хозяина колонист — сменить цвет. Листы игроков — перекраски одного шаблона, поэтому раскладка кадров
  описана один раз, а пер-игроковая только таблица «игрок → файл» (`WORKER_SHEETS`, `HUT_SHEETS`,
  `TRADE_SHEETS`).
- Кадр анимации выбирается по тику, а не по таймеру рендера: `ANIM_TICKS_PER_FRAME = 2` → 5 fps
  цикла ходьбы при 10 тиках в секунду. Пауза замораживает, ускорение ускоряет, детерминизм цел;
  самоанимирующиеся спрайты не используются. Фазе шейдера целых тиков мало — ей идёт `tick + alpha`,
  тот же множитель, что лерпит спрайты. Дискретный ритм — только тому, что должно мигать
  (`PULSE_FRAMES` у выделения).
- Три категории графики: запечённое (собирается один раз), реконсилируемое (сверяется с world каждый
  кадр), шейдерное (геометрия строится один раз, живёт через uniform'ы).
- Статичное запекается: террейн — один битмап на всю карту, скалы — `CompositeTilemap`. Ставший
  интерактивным или добываемым объект переезжает в сущности.
- Порядок задают только слои (`layers.ts`: `ground → objects → entities → fx`) и y-сортировка.
  Запечённый слой в y-сортировке не участвует: для клаттера размером в тайл приемлемо, для крупных
  объектов нет.
- Постройка кладётся на тайл, а не в точку: `BUILDING_ANCHOR = 0` (у всего остального якорь по центру
  и `anchorY` под ногами — `0.85` у колониста, `0.65` у камня, `0.6` у курицы и стопки). Иначе
  призрак, подсветка тайла и готовая постройка разъезжаются на полтайла; по той же причине скобки
  выделения постройки идут по тайлу, а не за спрайтом.
- Призрак стройки спрашивает правило у core (`canBuildAt`), а не повторяет его: своя копия обещала бы
  курсором тайлы, которые команда потом отвергнет. Иконка ресурса над складом кладётся кадром 1:1 —
  уменьшать пиксель-арт нельзя, полупиксели рядом с целыми видны сразу.

## Бейк террейна (`terrain.ts`)

**Граница террейнов пиксельная, а не тайловая.** Тайл решает только, из чего сделана точка; границу
бейк считает по арт-пикселям на dual grid — билинейно по четырём центрам тайлов вокруг точки, с
порогом `COVERAGE_THRESHOLD = 0.5`. Тайловая единица покраски даёт швы по краям тайлов и
карту-лоскутное одеяло.

- Материалы упорядочены **тотально** (`Material`: `DeepWater → MidWater → Shallow → Sand →
  GrassLight → GrassDark → DryLight → DryDark`), старший заливает младшего; два оттенка одной земли —
  два материала, поэтому пятна не квадратные. Порядок даёт вложенные множества покрытия → одно
  значение шума решает их все; иначе на пиксель претендуют двое или никто.
- Контур гнёт шум в две октавы: грубая (`EDGE_COARSE_PX = 7` арт-px на единицу) даёт меандр берега,
  мелкая (`EDGE_FINE_PX = 2.5`, вес `0.25`) — рванину на пиксельном масштабе; амплитуда
  `EDGE_AMPLITUDE = 0.3` покрытия. Шум берётся в мировых арт-пикселях: пер-тайловый паттерн вернёт
  тайловый шов. Прямая граница остаётся прямой — бейк снимает квантование по сетке, а не искривляет
  линию (апрон хребта в `divided-lands`).
- Резкий цветовой шаг лечится квантованными тонами и дизерингом, а не смешиванием: альфа-градиент даёт
  внепалитровые цвета и на ×8 читается как блюр. Правильный градиент — пара-четвёрка плоских тонов
  плюс статический пер-пиксельный хеш на границе. Без дизеринга возвращаются концентрические контуры,
  с анимированным — кипящий берег.
  - Полоса «песок → вода» (`#e7d593 → #77c0b4`, самый жёсткий шаг на карте): тон — кадр мокрого песка
    из `Shore.png`. Кладётся по дистанции от границы, вторым проходом по готовому битмапу (ширина —
    свойство расстояния, известна только когда вся граница посчитана). Ширина `WET_BAND_PX = 4`
    шатается на `±WET_SWING_PX = 2.2` — иначе у полосы появляется свой жёсткий край; плюс вторая
    октава на пиксельном масштабе (`WET_RAGGED_PX = 1`), чтобы полоса дизерилась в сухой песок.
  - Пена — оверлей, её тона вне палитры: рамп по той же дистанции, ярко у линии воды, растворяется в
    море.
- Дистанция до берега — два chamfer-прохода целыми весами `5` ортогонально / `7` по диагонали
  (приближение `1 : √2`), с кэпом `SHORE_REACH_PX = 10`. Они же — большая часть стоимости бейка: два
  прохода по всему битмапу.
- Битмап карты — одна текстура, поэтому карта ограничена лимитом GPU: `96×64` тайла по `16 px` =
  `1536×1024`, кап `MAX_BAKE_PX = 4096` (превышение — брошенная ошибка, а не тихая порча). Ответ на
  рост — чанкинг, не битмап побольше.
- Скалы (`Cliff.png`, `7×9` кадров) — nine-slice по четырём соседям того же террейна, `CompositeTilemap`
  поверх запечённой земли, а не вместо неё: углы кадров прозрачные. Поэтому гора не заводит своего
  материала в бейке — ей нужна барренная земля, та же, что у `Terrain.Rock`. Nine-slice покрывает
  только выпуклый контур: массив шириной в тайл рисуется отдельным «камнем» (любой из девяти кадров —
  стена вдоль одной стороны и плато вдоль другой).
- Вогнутый стык кладётся половинами тайла (`CLIFF_HALF = 8`). Тайл, у которого все четыре соседа —
  гора, а диагональный между двумя из них открыт, по четырём соседям читается как плато: стена,
  обязанная завернуть за угол, просто не рисуется, и по диагональной кромке массив течёт травой наружу
  на каждой ступеньке. Поэтому кадр выбирается не на тайл, а на половину тайла, и вогнутый стык
  считается открытой стороной для той половины, которой касается. Половины именно горизонтальные: лист
  сам заворачивает стену на середине кадра — северная стена нарисована в его нижней половине. Когда
  обе стороны половины открыты, кладутся обе боковые стены, каждая подрезанная на `CLIFF_INSET = 4`
  — отступ, которым лист держит массив от края тайла; иначе одна закрашивает полосу, которую другая
  оставила под грунт.

## Шейдеры (`water.ts`)

- Шейдер — материал слоя, а не постобработка: рисуется поверх запечённой графики (лист владеет базовым
  цветом, шейдер добавляет движение), считает в мировых координатах — в экранных эффект едет при пане
  и зуме. Пиксельность держим сами: снап к арт-пикселю, квантование в полосы.
- Форму шейдеру задаёт маска, а не геометрия: после пиксельной границы сетка квадов «по водным тайлам»
  врёт про воду. Вода — один `Mesh` над мокрой частью карты (`WaterField.left/top/right/bottom`) плюс
  маска-текстура, сухие пиксели внутри квада отбрасываются. Маску и заливку печёт один проход, иначе
  кайма.
- **В маске дистанция, а не тир:** alpha — «здесь вода», red — расстояние до ближайшего сухого
  пикселя, нормированное по `SHORE_REACH_PX`. Сигнал шейдеру обязан быть той же точности, что картинка
  под ним: тайловый тир глубины (`MAX_DEPTH = 3` — это про затемнение, не про пену) положил бы пену
  кольцом шириной в тайл.
- pixi прибит к WebGL (`app.init({ preference: "webgl" })`): шейдеры только на GLSL `#version 300 es`,
  автодетект мог бы поднять WebGPU-контекст и молча их выкинуть.

## Камера и вывод

- Камера — единственный владелец трансформа корневого контейнера. Zoom якорится на курсоре
  (`WHEEL_ZOOM_RATE = 0.0015` на пиксель колеса, экспонентой), зажат в `[MIN_ZOOM 1, MAX_ZOOM 8]`,
  старт `DEFAULT_ZOOM = 3`; pan зажат границами мира, клавиатурный — `KEY_PAN_SPEED = 700` экранных
  px/s. Offset считается во float и уходит в pixi округлённым — иначе pixel-art дрожит при панораме.
- Драг и клик различаются порогом `CLICK_SLOP_PX = 4`, тянут левая и средняя кнопки: иначе каждый
  сдвиг мыши на пиксель отменял бы выбор.
- Хоткеи камеры шлют команды тем же `Dispatcher`, что и HUD (`COMMAND_KEYS`), а не трогают состояние.
- `nearest` на всех текстурах.
- Постобработка — один `ColorMatrixFilter` на корневом контейнере, не на stage: грейд палитры
  (`GRADE_BRIGHTNESS = 0.82`, `GRADE_SATURATION = -0.12`) правится константой, исходная графика и
  DOM-HUD поверх канваса не затронуты.

## Ассеты (`textures.ts`)

- Логика — в тайлах: пиксельный размер тайла (`FRAME = 16`) — деталь рендера.
- Раскладка листов описывается один раз и наружу отдаётся по смысловым осям, не по сырым координатам
  кадра.
- Текстуры прелоадятся в `createGameStage` до первого вида: реконсилиация синхронна и ждать загрузку
  не может.
- Заливки земли нужны байтами, а не текстурами: бейк собирает карту попиксельно на CPU, а
  GPU-текстуру обратно не прочитать. `decodeFrames` тянет лист через `createImageBitmap(..., {
  premultiplyAlpha: "none" })` в `OffscreenCanvas` и отдаёт RGBA — для пиксель-арта премультипликация
  портит крайние пиксели. Спрайт-листы (включая `Cliff.png`) идут обычным путём через `Assets`.
