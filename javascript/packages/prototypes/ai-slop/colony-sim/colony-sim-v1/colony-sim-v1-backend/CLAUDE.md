Лобби-сервер: комнаты, присутствие, сид. Границы с остальными пакетами — в CLAUDE.md группы
(`../CLAUDE.md`): здесь только внутренние правила backend.

- **Игровой логики нет.** Сервер знает комнаты и их участников, ни одной сущности мира. Из игрового
  владеет сидом — единственным значением, обязательно одинаковым у всех игроков комнаты.
- **Соединение и есть присутствие.** Игрок жив, пока открыт его поток событий: закрытая вкладка
  убирает его из комнаты, пустая комната исчезает, ушедший хост передаёт права. Heartbeat-протокол для
  честных счётчиков не нужен.
- **Регистрация ≠ присутствие:** `POST /session` заводит игрока, онлайн его делает открытый поток —
  иначе сессия, попросившая id и не вернувшаяся, висела бы в списке онлайна вечно.
- **Где игрок — выводится из комнат, а не хранится на игроке:** членство уже лежит в одном месте,
  копия протухнет.
- **Вниз только SSE, вверх только POST.** Лобби вещает целиком, а не диффом: на таком размере снапшот
  дешевле учёта, и клиент, пропустивший сообщение, не может остаться в неверном состоянии.
- **Исходники гоняются через стриппинг типов Node** → относительные импорты пишутся с расширением
  `.ts`, а из `protocol` берутся только типы (`import type`): Node не грузит TypeScript из
  `node_modules`, куда ведёт воркспейс-симлинк.
- **Порт 8787 фиксирован** — на него ходит прокси dev-сервера web-game.
