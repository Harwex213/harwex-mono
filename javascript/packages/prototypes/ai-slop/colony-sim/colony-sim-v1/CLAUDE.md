Web colony-sim в духе RimWorld/DF. Рендер — pixi, HUD — Preact, персист — IndexedDB.

Здесь только состав пакетов и границы между ними. Правила внутри пакета — в его CLAUDE.md:

| пакет | содержимое |
| --- | --- |
| `colony-sim-v1-core` | мир, ECS, тик, детерминизм, mapgen, signals, команды, часы (`TurnSource`), сейв |
| `colony-sim-v1-game-render` | pixi-рендер, бейк террейна, шейдеры, камера, ассеты |
| `colony-sim-v1-hud` | preact-HUD над канвасом |
| `colony-sim-v1-web-game` | оболочка: роутинг, сессия, лобби, lockstep-клиент |
| `colony-sim-v1-dev-game` | dev-бутстрап без бэкенда и персиста |
| `colony-sim-v1-backend` | лобби-сервер (комнаты, присутствие, сид) + часы хода |
| `colony-sim-v1-protocol` | общие типы клиента и сервера |

## Рабочий цикл

- Читать этот файл перед правками. Обновлять только при смене **принципа**: новая граница слоёв, смена
  направления данных, найденная ловушка. Фичи здесь не документируются; правило внутри одного пакета —
  в CLAUDE.md этого пакета.
- Сборка типы не проверяет (swc их стрипает) → `yarn typecheck` в каждом затронутом пакете.
  `web-game` — самый широкий прогон: проверяет и исходники зависимостей.
- Dev: `yarn workspace @hw/colony-sim-v1-{dev-game|web-game} dev`. Порт случайный (`port: 0`),
  печатается при старте — фикс-порт отвечает бандлом забытого сервера прошлого прогона.
- `web-game` требует бэкенда (`…-v1-backend dev`, порт 8787 фиксирован, клиент ходит через прокси
  dev-сервера); без него застревает на форме имени. `dev-game` автономен.
- **Мультиплеер проверяется двумя видимыми окнами, а не двумя табами.** Невидимый таб получает от
  Chrome ~один кадр в секунду, его сим отстаёт от потока ходов на минуты и потом догоняет пачками —
  выглядит как «мир замер», но это троттлинг, а не десинк. Догон в `LockstepTurnSource` на это
  рассчитан; сверка миров — строка `worlds agree at turn N` в логе бэкенда, десинк — `desync in room`.

## Границы пакетов

**Мир — функция сида и последовательности ходов, больше ничего.** Это и есть lockstep: по проводу не
ходит ни одна сущность, у всех клиентов одинаковые миры, потому что одинаковы входы. Любая зависимость
тика от чего-то ещё (часов машины, порядка кадров, неточной математики) — не баг рендера, а разъезд
миров, и увидят его через минуту.

### Два шва вокруг core

- **core не знает, кто его рисует** — связь через `GameView`: мир внутрь, пиксели наружу, обратно
  ничего. Кадры тоже снаружи: `engine.frame(deltaMs)` зовёт владелец рендера. В core нет pixi и
  canvas, поэтому второй рендер (или прогон систем без рендера) правок core не требует.
- **core не знает и кто им играет** — `TurnSource` решает, когда случается тик и какие команды в нём.
  Локально это аккумулятор над кадром (`LocalTurnSource`), в сети — поток ходов сервера
  (`LockstepTurnSource`), и engine не различает их. Отсюда: сети в core нет, а мультиплеер — не режим
  внутри симуляции.
- Sim не знает про рендер, камеру и DOM. Экранные координаты входят только через явное преобразование
  камеры; понадобился системе пиксель — граница нарушена.

### Кто что читает

- Signals лежат в core, не в hud. Пишет их engine, читают оба потребителя: DOM-HUD и рендер
  (`selection`, `buildOrder`). В hud они втянули бы preact в зависимости core.
- hud получает `Dispatcher`, а не `GameEngine`. Тип разрешает ему только отправку команд; состояние
  меняется одним путём — командой, у кнопок, хоткеев камеры и любого будущего входа общий диспетчер.
- Лупом владеет engine-синглтон, не React. HUD монтируется поверх canvas и получает диспетчер через
  context; управлять лупом из компонента нельзя — StrictMode и переподключения жизненного цикла его
  ломают.
- Панель, нужная одному приложению, живёт в этом приложении. dev-game собирает HUD из кусков
  (`EngineProvider` + `App` + свой `DebugPanel`), а не через `mountHud`; поэтому hud экспортирует
  куски, а не только точку входа. Флаг «dev» внутри hud означал бы отладочную панель в прод-бандле.

### Приложения

- Приложения различаются политикой загрузки, а не движком. dev-game — фиксированный сид, локальные
  часы, без IndexedDB; web-game — оболочка вокруг того же бутстрапа с часами из сети. В core это
  необязательные `db` и `turns`.
- Сетевая игра не персистится. Снапшот — мир одного клиента, а поднять его значит поднять у всех
  остальных тот же ход из тех же байт и в тот же момент; это фича «поздний вход», которой нет.
  Автосейв, который некому загрузить, хуже отсутствующего — поэтому в web-game `db: null`, а в core
  `db` остался опцией.

### Сеть

- В backend нет игровой логики: ни одной сущности мира, ни одной прочитанной команды. Из игрового он
  владеет сидом и границами ходов — обоими потому, что это единственные значения, обязательно
  одинаковые у всех в комнате, и сказать это может только он.
- `protocol` — только типы. Две копии DTO разъезжаются, и разъезд выглядит как молча `undefined` поле
  на одной стороне. Рантайм в пакете невозможен: backend стриппит типы средствами Node, а Node не
  грузит TS из `node_modules`, куда ведёт воркспейс-симлинк; `import type` стирается раньше.
- **Команда едет по проводу непрозрачной** (`WireCommand = unknown`). Дать ей форму в `protocol` —
  привезти в лобби-сервер союз команд симуляции, а с ним зависимость от core, которую backend
  физически не загрузит. Сервер ретранслирует, разбирает клиент (`web-game/net/wire.ts`) — и обязан
  разбирать: на другом конце не доверенный вызов, а другая сборка игры. Отброшенная команда безопасна
  ровно потому, что её отбросят все: у всех одни байты и один валидатор.

## Сборка группы

- Пакеты потребляются как TS-исходники, без сборки. Отсюда: swc-правило не исключает `node_modules`
  (там симлинки на соседей); опции компилятора (jsx, ambient-типы ассетов, пути) общие на группу в
  `tsconfig.base.json`, т.к. tsc проверяет исходники зависимостей своими опциями.
- Ассеты лежат вне пакетов (один набор на v1 и v2), alias `@assets` задаёт `rspack.shared.mjs` вместе
  с общими правилами загрузчиков.

## Одно направление данных

```
   сид + ходы ──►  in-memory world  ──►  systems  ──►  renderer
                          │                   │
                          │                   └──►  signals ──►  HUD
                          │                                       │
                          ▼                                       ▼
                   hashWorld ──► сервер (сверка)          команды ──► сервер ──► ход ──┐
                                                                                       │
                                              применяются на границе тика у всех ◄─────┘
```

Живая правда — в памяти; остальное её проекция (рендер, signals) или снапшот (IDB, только синглплеер).
Рендер и HUD world не мутируют: читают и шлют команды. Команда своего же клиента тоже возвращается
через сервер — круг, а не короткий путь: клик, применённый локально сразу, был бы применён на другом
тике, чем у всех остальных.
