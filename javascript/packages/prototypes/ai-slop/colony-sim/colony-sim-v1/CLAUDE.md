Web colony-sim в духе RimWorld/DF. Рендер — pixi, HUD — Preact, персист — IndexedDB.

Здесь только состав пакетов и границы между ними. Правила внутри пакета — в его CLAUDE.md:

| пакет | содержимое |
| --- | --- |
| `colony-sim-v1-core` | мир, ECS, тик, детерминизм, mapgen, signals, команды, сейв |
| `colony-sim-v1-game-render` | pixi-рендер, бейк террейна, шейдеры, камера, ассеты |
| `colony-sim-v1-hud` | preact-HUD над канвасом |
| `colony-sim-v1-web-game` | оболочка: роутинг, сессия, лобби, автосейв |
| `colony-sim-v1-dev-game` | dev-бутстрап без бэкенда и персиста |
| `colony-sim-v1-backend` | лобби-сервер (комнаты, присутствие, сид) |
| `colony-sim-v1-protocol` | общие типы клиента и сервера |

## Рабочий цикл

- Читать этот файл перед правками. Обновлять только при смене **принципа**: новая граница слоёв,
  смена направления данных, найденная ловушка. Фичи здесь не документируются; правило внутри одного
  пакета — в CLAUDE.md этого пакета.
- Сборка типы не проверяет (swc их стрипает) → `yarn typecheck` в каждом затронутом пакете.
  `web-game` — самый широкий прогон: проверяет и исходники зависимостей.
- Dev: `yarn workspace @hw/colony-sim-v1-{dev-game|web-game} dev`. Порт случайный (`port: 0`),
  печатается при старте — фикс-порт отвечает бандлом забытого сервера прошлого прогона.
- `web-game` требует бэкенда (`…-v1-backend dev`, порт 8787 фиксирован, клиент ходит через прокси
  dev-сервера); без него застревает на форме имени. `dev-game` автономен.

## Граф зависимостей

```
                    core  ◄──  game-render      core  ◄──  hud
                          core + game-render + hud  ◄──  dev-game, web-game
                              protocol  ◄──  web-game, backend
```

## Границы пакетов

- **core не знает, кто его рисует.** Связь через `GameView`: мир внутрь, пиксели наружу, обратно
  ничего. Часы тоже снаружи — `engine.frame(deltaMs)` зовёт владелец рендера. В core нет pixi и
  canvas, поэтому второй рендер (или прогон систем без рендера) правок core не требует.
- **Sim не знает про рендер, камеру и DOM.** Экранные координаты входят только через явное
  преобразование камеры; понадобился системе пиксель — граница нарушена.
- **Signals лежат в core, не в hud.** Пишет их engine, читают оба потребителя: DOM-HUD и рендер
  (`selection`). В hud они втянули бы preact в зависимости core.
- **hud получает `Dispatcher`, а не `GameEngine`.** Тип разрешает ему только отправку команд;
  состояние меняется одним путём — командой, у кнопок, хоткеев и любого будущего входа общий
  диспетчер.
- **Лупом владеет engine-синглтон, не React.** HUD монтируется поверх canvas и получает диспетчер
  через context; управлять лупом из компонента нельзя — StrictMode и переподключения жизненного
  цикла его ломают.
- **Приложения различаются политикой загрузки, а не движком.** dev-game — фиксированный сид, без
  IndexedDB; web-game — автосейв и оболочка вокруг того же бутстрапа. В core это один необязательный
  `db`.
- **Панель, нужная одному приложению, живёт в этом приложении.** dev-game собирает HUD из кусков
  (`EngineProvider` + `App` + свой `DebugPanel`), а не через `mountHud`; поэтому hud экспортирует
  куски, а не только точку входа. Флаг «dev» внутри hud означал бы отладочную панель в прод-бандле.
- **В backend нет игровой логики:** только комнаты и их участники, ни одной сущности мира. Из
  игрового он владеет сидом — единственным значением, обязательно одинаковым у всех в комнате.
- **`protocol` — только типы.** Две копии DTO разъезжаются, и разъезд выглядит как молча `undefined`
  поле на одной стороне. Рантайм в пакете невозможен: backend стриппит типы средствами Node, а Node
  не грузит TS из `node_modules`, куда ведёт воркспейс-симлинк; `import type` стирается раньше.

## Сборка группы

- **Пакеты потребляются как TS-исходники, без сборки.** Отсюда: swc-правило не исключает
  `node_modules` (там симлинки на соседей); опции компилятора (jsx, ambient-типы ассетов, пути) общие
  на группу в `tsconfig.base.json`, т.к. tsc проверяет исходники зависимостей своими опциями.
- **Ассеты лежат вне пакетов** (один набор на v1 и v2), alias `@assets` задаёт `rspack.shared.mjs`
  вместе с общими правилами загрузчиков.

## Одно направление данных

```
IndexedDB (defs + autosave)  ──boot──►  in-memory world  ──►  systems  ──►  renderer
                                              ▲                    │
                             autosave ────────┘                    └──►  signals ──► HUD ──► commands ──┐
                                                                                                        │
                                                              команды применяются на границе тика ◄─────┘
```

Живая правда — в памяти; остальное её проекция (рендер, signals) или снапшот (IDB). Рендер и HUD
world не мутируют: читают и шлют команды.
